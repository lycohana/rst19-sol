# rst19 实现模块设计

## 1. 设计目标

把当前仓库已经核验的数据约定和星表研究方案落成一个可离线复现、可单元测试、可逐步替换的 Python 基线。第一版优先保证输入边界、坐标约定、参数记录和失败行为清晰。

## 2. 非目标

第一版不把主办方截图中的数字当作真值，不硬编码相机 FOV/像元尺度，不访问在线 Gaia 服务，不把最近邻匹配数量直接当作星点总数，也不输出未经标定的 `Mv`。

## 2.1 UI 设计读取：qiaomu-design 适配

本项目把 [qiaomu-design](https://github.com/joeseesun/qiaomu-design) 作为现有 Tkinter 工作台的打磨约束，而不是引入 Web UI。设计读取是“本地科学工作台 + 观测站实验台 / field notebook”：视觉冒险度 `4/10`、动效强度 `3/10`、信息密度 `7/10`。纸张色、深靛蓝、琥珀和青绿色服务于证据分层；禁止紫色渐变、玻璃拟态、Inter、居中营销式首屏和无语义装饰数字。

界面功能契约为：选择 FITS、运行单图或 15 帧分析、持续看到进度、区分候选/质量/moving、读取星等/速度/方向/预测并导出表图。右侧说明必须受容器宽度约束，长文本不能挤掉主图；进度、错误、缓存命中和无 WCS 边界必须有可见状态。后续修改按 Audit / Polish / Harden 复核，不为视觉变化牺牲科学字段的可解释性。

## 3. 架构

```text

                    │
                    ├─> detection.py ──> DetectionResult
                    │                         │
                    ├─> attitude.py ──> 逐帧光轴姿态先验
                    │
                    └─> catalog.py + wcs.py ─> matching.py ──> MatchResult
                                                       │
                    └─> pipeline.py / cli.py
                                                                  │
                                                                   ├─> gui.py ──> cache.py
                                                                   │          └─> 用户 CSV + 先验 WCS ──> 星表核验窗口
                                                                   └─> JSON / gzip cache
```

## 4. 关键决策

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| FITS 读取 | 第一版使用小型原生读取器 | 当前数据结构简单；避免未安装 Astropy 时无法跑通输入校验，并保留原始 16 bit 存储值 |
| 检测基线 | 128 px 局部背景/RMS + Gaussian PSF 匹配滤波 + NMS | 对当前数据保留候选并抑制单像素峰；真实 PSF 仍需由注入/亮星拟合验证 |
| 候选/质量语义 | `sources` 保留所有返回候选，`quality_sources` 供科学下游使用 | 可审计地解释被拒绝候选，不把一个数量包装为真值 |
| SNR | `snr`、`filter_snr`、`flux_snr` 独立输出 | 最暗源按通量误差筛选，未知 gain 时不虚构 Poisson 参数 |
| 序列 | `sequence.py` 用静态源估计平移、互相最近匹配和唯一关联 | 适合作为 15 帧基线；旋转/尺度/畸变需要后续仿射或 WCS |
| 辅助姿态 | `attitude.py` 用格式说明的四元数和机体系 `-Y` 轴恢复逐帧光轴 RA/Dec | 已在 15 帧真实数据上与辅助 RA/Dec 做亚纳角秒级一致性核验；只作光轴/姿态先验，不冒充完整 WCS |
| 默认检测策略 | 4σ 阈值 + `max_sources=None` | 优先保召回；默认完成候选源全量计算，数量限制必须由调用方显式传入 |
| 星表格式 | 用户提供的 UTF-8 CSV + 明确必需列 | 仓库不内置未授权数据；更容易冻结版本、复现实验和提交答辩材料 |
| 坐标模型 | 显式 0-based 切平面 TAN 近似 | 避免隐藏像素原点和 x/y 约定；真实匹配后再判断是否需要 SIP |
| 匹配策略 | 半径门控候选图内的全局最大基数/最小总残差一对一分配；保留贪心对照 | 避免局部残差抢占导致可匹配源数下降，同时保留旧口径做敏感性审计；不把它伪装成盲解算 |
| 输出 | 结构化 JSON | 保存阈值、检测属性、匹配残差和失败上下文，便于画图和复核 |
| 最暗源判定 | 正通量 + SNR 达标 + 排除边缘/掩膜/饱和后取最大 `m_inst` | 在没有零点和波段转换时，输出可复核的仪器星等，不伪装成物理星等 |
| 线状结构 | 点源检测中以连通域 PCA 标记 `LINE_ARTIFACT`；序列层独立提取高残差线状候选并跨帧拟合 | 亮线不进入可信点源和点轨迹，但不因点源质量拒绝而从运动目标分析中消失 |
| 单像素尖峰 | 候选峰中心 3×3 核心至少 3 个像素超过 `max(2σ_local, 0.1×peak_excess)` | 1σ footprint 对高单像素脉冲过于宽松；保留候选并以 `INSUFFICIENT_PSF_SUPPORT` 拒绝质量层 |
| GUI 状态 | 切帧只载入预览，点击分析后按文件状态和参数读写 gzip 缓存；运动分析和星表核验单独接入 | 避免启动时提前计算；帧令牌丢弃晚到的旧结果，按钮允许清理缓存；质量/候选/运动/星表四种叠加层不混淆语义 |

## 5. 已知限制

- 当前 FITS 读取器只为主 HDU 二维图像和项目已知 `BITPIX` 类型设计，尚未覆盖多 HDU 组合、压缩图像和完整 FITS WCS 关键字。
- 当前背景估计是 128 px 网格化局部背景/RMS，不是完整的 Photutils `Background2D` 或复杂散射光模型；在强渐变场景下需要升级。
- 匹配器需要用户提供可验证的 WCS 初值；它不能单独完成四星/五星盲解算。
- 星表匹配默认在每个稀疏候选连通分量内建立稠密代价矩阵，因此通常适合局部小分量；若 WCS 误差过大或目录过密导致超大连通分量，需要改用分块/稀疏最小费用流实现。当前接口也没有把次优分配间隔自动提升为物理身份概率，近似等价结果仍应人工复核。
- 星等只读取星表参考字段，不进行绝对零点、颜色项、空间项或误差模型拟合。
- 自行传播采用线性近似；高自行源、长时间跨度和视差需要更完整的历元处理。
- 当前运动目标基线包含全局平移后的点轨迹统计、原图线状候选关联和时间中值差分；星表核验后的局部仿射 WCS 校准已经作为独立证据接入，但序列级仿射配准、完整 WCS/PSF matching、运动目标注入和比赛真值评测仍需继续验证。序列结果已纳入 gzip 缓存，但缓存保留全部审计轨迹时仍可能较大。
- 当前 Tkinter 界面是本地单帧/15 帧工作台；叠加绘制质量源、线状轨迹、图像平面预测和可选星表匹配，右侧表格为通量 SNR 前 40 行的交互摘要，15 帧证据窗口提供逐帧、轨迹、遥测表、相对首帧遥测轨迹、图证、理想/真实 FITS 背景注入实验、真实首帧阈值/PSF 扫描、空间分区留出注入和按需单图长线逐帧审计；真实背景实验、空间注入与长线审计按阶段回报后台进度，星表核验仍要求用户提供已标定的 WCS 初值。
- 辅助遥测位置字段按格式说明记为 `m`；速度字段原文漏写 `/s` 的可能性由位置—时间差分强烈支持，但在主办方确认前 UI 和报告均保留 `m/s?` 及逐帧自洽误差，不据此宣称完成轨道解算。

## 6. 变更历史

### 2026-09-02 - 增加辅助姿态光轴审计

新增 `attitude.py`、`attitude_cli.py` 和 `rst19-aux-audit` 入口。实现依据格式说明将辅助四元数按向量在前、标量在后的 Hamilton 约定转换为主动旋转，以机体系 `-Y` 轴恢复每帧光轴 RA/Dec，并输出逐帧 CSV/JSON 审计。15 张真实 FITS 的四元数模长、辅助 RA/Dec、FITS 头 `p_az/p_el` 均通过一致性检查；计算光轴与辅助 RA/Dec 最大残差约 `1.1e-10` 角秒。

这条路径只把原先的“无 WCS”边界细化为“有中心/姿态先验、仍无完整 WCS”：尚缺像元尺度、图像轴方向和畸变模型，后续必须通过获授权星表、留出匹配和局部仿射拟合完成标定，不能直接把辅助 RA/Dec 赋给检测源。

### 2026-08-31 - 稳定星场默认显示与路径映射

**变更内容**：15 帧结果完成后默认显示“稳定星场”；稳定/运动图层根据当前 FITS 路径解析序列帧索引，并保证缩小总览仍有可见的稳定点标记。

**变更理由**：序列结果已经计算出 `static/persistent` 轨迹，但旧完成事件默认切到运动层，用户容易误以为稳定星场没有结果；相对缓存路径也不能只依赖列表位置。

**影响范围**：`gui.py` 的图层完成状态、稳定层绘制和悬停查询；不改变检测和轨迹分类口径。

### 2026-08-27 - 建立星表匹配基线

**变更内容**：新增 FITS 读取、辅助数据解码、星点检测、离线星表加载、切平面 WCS、逐源匹配、单帧 pipeline、CLI 和测试。

**变更理由**：将主办方提出的星表路线从研究文档推进为可运行的最小闭环。

**影响范围**：新增 `src/rst19` Python 包、`tests` 测试和项目安装配置；不改变本地 FITS 归档和已有资料文档。

**决策依据**：先把输入、参数和输出边界固定，再用真实数据测量 FOV、WCS 残差和检测稳定性，避免在未经验证的相机参数上直接做自动盲解算。

### 2026-08-27 - 增加 Python 桌面工作台与最暗源标注

**变更内容**：新增 `rst19-gui` Tkinter 桌面入口，提供 FITS 帧列表、图像预览、候选点叠加、参数控制、统计卡片、源表摘要和最暗可信源的仪器星等标注；检测默认不限制候选源数量。

**变更理由**：让算法基线可以被参赛队伍直接操作和抽检，同时明确展示候选源与最终科学结果的边界。

**影响范围**：新增 `gui.py`、`photometry.py` 和 Pillow 依赖；移除 Web 服务与静态资源。不上传图像、不引入在线星表服务。

**决策依据**：使用 Python 标准库 Tkinter 配合 Pillow 绘制本地预览，避免浏览器服务和额外前端构建；预览和分析均在本机数据目录内完成。最暗源按质量条件筛选后再用 `m_inst` 标注；真实物理星等留待零点和波段标定。

### 2026-08-27 - 增加交互视图与可清理缓存

**变更内容**：预览支持滚轮缩放、左键拖拽和候选源悬浮信息；切换帧时清除旧状态并用帧令牌保护异步结果；移除启动自动分析，检测结果改为按文件状态和参数键控的 gzip 缓存，并在界面提供清空入口。

**决策依据**：真实 FITS 较大且全量候选源计算成本高，预览和检测解耦可以先确认当前帧，再按需运行；缓存不进入 Git，清空操作只处理 `.rst19-cache/`，不触碰原始图像。

### 2026-08-28 - 增加科研检测和序列关联

**变更内容**：`detection.py` 增加局部背景/RMS、PSF 匹配滤波、孔径通量误差、三种 SNR、形状质量和饱和/掩膜标志；新增 `sequence.py` 与 `rst19-sequence`，提供 15 帧平移配准、唯一轨迹关联和 `static/moving/transient` 分类。

**决策依据**：首帧正峰/负峰对照和阈值扫描表明，单一原始像素峰值不能作为恒星真值；候选、质量源和跨帧轨迹需要同时保留并可审计。所有参数进入 JSON，详细实验记录见 `doc/02-星图识别/检测器实验记录.md`。

### 2026-08-28 - 接入运动候选图层和线状伪迹审计

GUI 新增 15 帧分析按钮和三个互斥叠加层；运动层不再绘制整幅质量星场，独立显示洋红色 `moving` 线状轨迹、橙色待复核线状候选和严格 `moving` 点轨迹，悬停可查看线/点轨迹统计，且右上角图层选择在切帧后保持不变。悬浮信息栏使用固定宽度并自动换行，避免检测详情长文本撑大 viewer、挤压右侧结果面板。检测器增加 `LINE_ARTIFACT` 连通域/PCA 审计，并将该开关写入缓存键；序列层另以原图残差、面积和 PCA 形状建立线状候选池。序列配准使用互相最近的一对一源匹配，点轨迹使用拟合速度跨跨度判定位移并禁止跨漏帧重连；切帧时旧任务不会恢复按钮状态或覆盖当前缓存语义。

### 2026-08-29 - 增加辅助遥测位置—速度自洽核验

**变更内容**：对 15 个真实 FITS 按 `DATE-OBS` 做位置差分，端点使用一侧差分、中间帧使用中心差分，并把位置差分速度、速度残差和相对误差写入创新报告、逐帧 CSV 和 Tkinter 的“辅助遥测”页；保留原有 `*_raw` 字段，速度单位在界面和文档中标为 `m/s?`。

**变更理由**：格式说明明确位置为 `m`，但速度字段表格原文写成 `m`。不能凭字段名直接修正文档，也不能继续把全部向量笼统写成 raw；需要用原始 15 帧的时间序列检验两种解释是否自洽。

**影响范围**：`innovation.py` 的报告/CSV 字段、辅助遥测 UI、创新分析与本地数据核验文档；不修改 FITS 原图，不把载体状态速度与图像长线 `px/s` 混为一谈。

**决策依据**：J2000/WGS84 中间帧位置差分与辅助速度的相对误差均约为万分之几，强烈支持速度实际单位为 `m/s`、DOCX 漏写 `/s`；在主办方正式确认前，代码保留假设状态和逐帧残差证据。

### 2026-08-29 - 增加单图长线逐帧审计

**变更内容**：新增 `rst19-trails` 命令，逐张独立运行单帧残差/PCA 长线筛选，输出候选数量、最长线长度、宽度、方向、残差 SNR、触边状态和包围盒的 CSV 与曲线；主界面单帧分析完成后在右侧摘要显示同一组证据。

**变更理由**：序列轨迹结果不能证明每一帧都存在可见长线。需要把“单图形状证据”和“跨帧运动证据”拆开，直接检查是否出现了整幅图误标或中间帧缺失。

**影响范围**：`experiments.py`、`trail_cli.py`、`pyproject.toml`、Tkinter 单帧摘要以及运动目标/创新分析文档；不改变长线判定门槛，也不把单帧候选升级为运动真值。

**决策依据**：真实 15 帧审计在当前固定参数下得到第 1 帧 1 条强长线、第 2–8 帧 0 条、第 9–15 帧各 1 条；这为连续 7 帧轨迹提供独立帧级支持，同时保留第 1 帧为不同候选组。

### 2026-08-29 - 增加集中式创新摘要页

15 帧证据窗口新增“创新摘要”页，将时序、配准、线状候选图像平面速度/方向/拟合、短期外推坐标和辅助遥测单位边界集中为可滚动证据表；新增“遥测轨迹”页，以相对首帧的 J2000/WGS84 XY 投影显示观测序列和末帧常速度预测；“图证”页并列显示线状候选裁剪和拟合图像平面轨迹。页面只整理现有 `SequenceResult`，不重新检测；图像 `px/s`、载体 `m/s?` 和待标定的角秒/WCS 结论保持分离。

### 2026-08-29 - 增加源级星点研究表

新增 `rst19-sources` 与 GUI“研究工具”菜单中的“导出星点研究表”，从已完成的检测结果导出全量源表、可重叠质量标志汇总、互斥类别摘要、按类别的形态/SNR/空间分位数与拒绝原因表、三个 SNR 口径的排名曲线和通量 SNR 分布；导出层不重新检测，也不把质量数量包装成物理恒星真值。高 SNR 拒绝计数只是诊断切片，不是物理伪影真值。

源级研究表增加 `source_feature_method_summary.csv`：对每个首要类别统计 Gaussian、DoG 窄/宽尺度的提议器交集、`gaussian_only`、`dog_only` 和无 Gaussian 质量数；另有 `source_feature_morphology.csv`，统计 peak/flux/filter SNR、FWHM、椭圆率、sharpness、PSF 支持、footprint、质心偏移、X/Y 空间分位数和重叠拒绝原因比例；再增加可重叠的 `source_feature_subclass_summary.csv`，按完整 flag token 拆分重复码、极端负值、饱和、边界、部分掩膜、线状、未分辨近邻和尖峰；`source_feature_spatial.csv` 再按 4×4 粗网格统计类别的候选/质量数和高 SNR 拒绝数。该输出用于分辨“显著但非点源”“重复但质量不足”“有效孔径损失”“局部空间结构”和“不同提议器的敏感性差异”，不改变 `quality_passed` 或星等口径；方法交集也不被解释为真星概率。

有原始 FITS 时同步输出 `source_feature_psf_similarity.csv`，对每个类别的确定性裁剪计算经验 PSF 相关系数、相对残差和中心能量占比；同时输出 `source_feature_psf_spatial.csv`，将全局经验核与按 4×4 detector 网格构造的留出局部核比较。局部模板只从局部池取样，但用整幅候选表做邻峰隔离；不足三个干净模板时保留回退计数，不直接进入默认质量层，也不等于星表/WCS 身份。当前首帧线状候选集中在单个粗网格，而拥挤候选遍布视场；空间集中性和局部模板可得率只作为机制线索，仍需逐源 PSF 和星表留出验证。

### 2026-09-03 - 增加真实背景 2/3 源拥挤组审计

新增 `run_crowded_blend_audit` 和 `rst19-injection --crowded-blend-audit`。它在真实首帧上沿随机方向注入等间距的 2 源/3 源组，固定组总离散积分信号，并分别输出单源召回、组级一对一完整解析率、合并率和组邻域额外候选率。`group_resolution` 要求组内每个真值由不同候选命中；`merged` 表示一个候选同时接近至少两个真值；`extra` 只表示保护区内候选数超过注入真值数，三者都不是 precision。

经验 PSF 的 `4 组/条件` 敏感性控制显示，`3 px` 仍不能组级解析，`5.4 px` 候选层仍可分开，但 `6 px` 的候选组解析可下降到 `0.75`（2 源）或 `0.25`（3 源）。因此间距阈值不能脱离 PSF 形状、方向、每源信号和局部背景；该结果仅作为控制，不能排名两种 PSF。

该模块的输出分为逐候选、类别汇总和指定目标三层：`source_peak_consistency.csv`、`source_peak_consistency_class_summary.csv`、`source_peak_consistency_targets.csv` 和 `source_peak_consistency.json`。`raw_local_maximum` 只回答局部像素拓扑问题，不升级 `quality_passed`，不输出物理恒星概率、precision、FDR 或源数，也不接入默认检测、质量层、GUI 或缓存。当前目标 pair 的 `82931/82934` 在三个窗口均非 raw 局部峰，`r=3` 共同指向同一亮像素；该结果作为值域/共享结构/PSF 混叠的复核信号，不能单独判定噪点或真实星。

`source_proposal_peak_audit.py` 在此结果之上按 `detection_id` 连接 `source_catalog.csv` 的 `proposal_methods`，把来源归一为 `all_three`、`gaussian_only`、`dog_only` 和 `partial`，输出 `source_proposal_peak_rows.csv`、`source_proposal_peak_summary.csv`、`source_proposal_peak_targets.csv` 与 JSON。该层只做类别—来源子组的 detector-level 对照，不能把来源交集当成独立投票或恒星概率，也不修改默认检测、质量层、GUI 和缓存；目标 pair 的来源尾部结果进入真实性研究 10.103 和实验记录 8.116。

新增 `source_proposal_temporal_audit.py` 与 `rst19-source-proposal-temporal-audit`，把来源组合与同一 15 帧实验的注册邻域持久性连接。输入包括当前 v3 `source_catalog.csv`、v6 非紧凑逐源诊断表和 v6 紧凑来源子组持久表；实验参数从子组表统一取得，并对可选的逐源元数据做严格核对。非紧凑类别输出逐源来源—时序行，紧凑质量类别只输出按来源子组加权的计数和均值，不伪造逐源中位数/同机制值。`candidate≥12/15`、`candidate_same_subgroup≥12/15`、`quality≥12/15` 分列；当前 `crowded_blend/dog_only` 为 `509/902、196/902、6/902`，目标 `82934` 的 Gaussian-only 子组为 `2` 个且目标自身 `4/15、3/15、0/15`，目标 `82931` 为 `4/15、4/15、0/15`。这些字段只支持 detector-level 复核排序，不是星表身份、噪点概率、precision、FDR 或物理源数；该层不修改 detector、质量层、GUI 或缓存，产物为 `tmp/source-proposal-temporal-audit-code-pattern-current-v1/`，回归为 `tests/test_source_proposal_temporal_audit.py`，对应真实性研究 10.104 与实验记录 8.117。

### 2026-09-09 - pair 强度分配状态审计

`pair_flux_covariance.py` 的 v3 在原有跨帧共变之外，记录每个共同帧的 `primary/(primary+secondary)`，并以 pair 总响应中位数把帧分成低/高两组。新增 `primary_fraction_range`、`primary_fraction_mad_scaled`、两组分配中位数和 `primary_fraction_shift_high_minus_low` 字段，并对完整控制 pair 汇总绝对分配变化的中位数、P95 和探索性上尾。它们使用同一强制测光 SNR，仅用于发现“共同变亮”与“响应在两个框之间重新分配”的差别；不称为通量比例、双星概率或显著性检验。

当前 `82931/82934` 的固定 `flux_snr` 分配中位数/范围/稳健离散度为 `0.5486 / 0.2476 / 0.0243`；按总响应分层，低组 `7` 帧分配中位数 `0.6065`，高组 `8` 帧为 `0.5354`，差值（高−低）为 `-0.0711`。局部重定位量对应为 `0.5399 / 0.2430 / 0.0176`，低/高组为 `0.6106/0.5330`，差值 `-0.0776`。`29,640/29,639` 个控制 pair 的绝对差值中位数/P95 为 `0.0334/0.3968`、`0.0266/0.3898`，目标探索性上尾为 `31.7%/27.7%`，所以分配变化本身不是目标特异异常；它只能与重复码、负异常和共享孔径合并作为局部机制线索。模块只读既有 CSV，不改默认 detector、质量层、GUI 或缓存。

### 2026-09-07 - 近邻 pair 原始像素拓扑审计

当前 pair 在 `3/5/8/10σ` 下均为同一正值连通块，而 `3/5/7 px` 局部峰审计中两颗候选均不是局部极大值；首帧最高像素为 `(2438,4022)=13028`。该证据支持共享响应/混叠优先解释，但既不等于噪点证明，也不排除未解析真实近邻星；模块只生成 CSV/JSON/SVG，不接入默认检测、质量层、GUI 或缓存。回归测试为 `tests/test_pair_pixel_topology.py`，真实产物为 `tmp/pair-pixel-topology-pair-82931-82934-current-v1/`。

### 2026-09-09 - 线状候选的坐标几何交叉审计

### 2026-09-09 - 逐帧原始响应与产物血缘审计

`feature_temporal_consistency_audit.py` 只读取 canonical v3 源目录和逐帧原始孔径摘要 CSV，在固定 detector 坐标/测量口径下计算逐源稳健相对波动 `R_MAD`、覆盖、正值/`flux SNR≥5` 比例、符号翻转、零值、负异常和重复码比例，再按首要 `feature_class` 汇总。`R_MAD` 使用 `1.4826×MAD/max(|median|,1)`；它是响应描述量，不是 p 值、FDR、precision 或恒星概率。输入字段 `repeated_code_count` 与 pair 专用的 `repeated_3990_3993_count` 是显式同义别名，其余字段不做猜测。

类别默认来自 `source_catalog.csv`。若逐帧表也带 `feature_class`，默认要求每个 detection ID 的类别一致；`feature_class_source="frame"` 是显式采用 artifact-local 类别的研究模式，CLI 还支持重复 `--detection-id` 只审计指定源。这样处理是必要的：旧 GUI 源表与当前 v3/pair 专用表对同名 `82931/82934` 的类别不同，detection ID 不是跨产物全局物理身份。修正后的全类产物为 `tmp/feature-temporal-consistency-audit-code-pattern-current-v2/`，pair 产物为 `tmp/feature-temporal-consistency-pair-82931-82934-current-v2/`。该模块不接入默认 detection、质量层、GUI、缓存或 FITS 读取；产物为 `feature_temporal_consistency_audit.json`、`feature_temporal_consistency_sources.csv` 和 `feature_temporal_consistency_summary.csv`，测试为 `tests/test_feature_temporal_consistency_audit.py`。
