# rst19 实现模块设计

## 1. 设计目标

把当前仓库已经核验的数据约定和星表研究方案落成一个可离线复现、可单元测试、可逐步替换的 Python 基线。第一版优先保证输入边界、坐标约定、参数记录和失败行为清晰。

## 2. 非目标

第一版不把主办方截图中的数字当作真值，不硬编码相机 FOV/像元尺度，不访问在线 Gaia 服务，不把最近邻匹配数量直接当作星点总数，也不输出未经标定的 `Mv`。

## 3. 架构

```text
FITS bytes
  └─ fits.py ──> FitsFrame + AuxiliaryData
                    │
                    ├─> detection.py ──> DetectionResult
                    │                         │
                    └─> catalog.py + wcs.py ─> matching.py ──> MatchResult
                                                       │
                    └─> pipeline.py / cli.py
                                                                  │
                                                                   ├─> gui.py ──> cache.py
                                                                   └─> JSON / gzip cache
```

## 4. 关键决策

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| FITS 读取 | 第一版使用小型原生读取器 | 当前数据结构简单；避免未安装 Astropy 时无法跑通输入校验，并保留原始 16 bit 存储值 |
| 检测基线 | 128 px 局部背景/RMS + Gaussian PSF 匹配滤波 + NMS | 对当前数据保留候选并抑制单像素峰；真实 PSF 仍需由注入/亮星拟合验证 |
| 候选/质量语义 | `sources` 保留所有返回候选，`quality_sources` 供科学下游使用 | 可审计地解释被拒绝候选，不把一个数量包装为真值 |
| SNR | `snr`、`filter_snr`、`flux_snr` 独立输出 | 最暗源按通量误差筛选，未知 gain 时不虚构 Poisson 参数 |
| 序列 | `sequence.py` 用静态源估计平移、互相最近匹配和唯一关联 | 适合作为 15 帧基线；旋转/尺度/畸变需要后续仿射或 WCS |
| 默认检测策略 | 4σ 阈值 + `max_sources=None` | 优先保召回；默认完成候选源全量计算，数量限制必须由调用方显式传入 |
| 星表格式 | UTF-8 CSV + 明确必需列 | 比在线查询更容易冻结版本、复现实验和提交答辩材料 |
| 坐标模型 | 显式 0-based 切平面 TAN 近似 | 避免隐藏像素原点和 x/y 约定；真实匹配后再判断是否需要 SIP |
| 匹配策略 | 半径约束 + 全局候选排序 + 一对一分配 | 避免一个星表源被多个检测源重复占用；不把它伪装成盲解算 |
| 输出 | 结构化 JSON | 保存阈值、检测属性、匹配残差和失败上下文，便于画图和复核 |
| 最暗源判定 | 正通量 + SNR 达标 + 排除边缘/掩膜/饱和后取最大 `m_inst` | 在没有零点和波段转换时，输出可复核的仪器星等，不伪装成物理星等 |
| 线状结构 | 连通域 PCA 检出跨越多个 PSF 宽度的长线，标记 `LINE_ARTIFACT` | 保留审计证据但阻止亮线伪峰进入可信点源和轨迹 |
| GUI 状态 | 切帧只载入预览，点击分析后按文件状态和参数读写 gzip 缓存；运动分析单独接入 | 避免启动时提前计算；帧令牌丢弃晚到的旧结果，按钮允许清理缓存；三种叠加层不混淆语义 |

## 5. 已知限制

- 当前 FITS 读取器只为主 HDU 二维图像和项目已知 `BITPIX` 类型设计，尚未覆盖多 HDU 组合、压缩图像和完整 FITS WCS 关键字。
- 当前背景估计是 128 px 网格化局部背景/RMS，不是完整的 Photutils `Background2D` 或复杂散射光模型；在强渐变场景下需要升级。
- 匹配器需要用户提供可验证的 WCS 初值；它不能单独完成四星/五星盲解算。
- 星等只读取星表参考字段，不进行绝对零点、颜色项、空间项或误差模型拟合。
- 自行传播采用线性近似；高自行源、长时间跨度和视差需要更完整的历元处理。
- 当前运动目标基线只支持全局平移和像素轨迹统计，仍需要仿射/WCS、差分图、注入目标和比赛真值评测。
- 当前 Tkinter 界面是本地单帧工作台；叠加绘制质量源，右侧表格为通量 SNR 前 40 行的交互摘要；星表匹配尚未接入桌面操作流。

## 6. 变更历史

### 2026-08-27 - 建立星表匹配基线

**变更内容**：新增 FITS 读取、辅助数据解码、星点检测、离线星表加载、切平面 WCS、逐源匹配、单帧 pipeline、CLI 和测试。

**变更理由**：将主办方提出的星表路线从研究文档推进为可运行的最小闭环。

**影响范围**：新增 `src/rst19` Python 包、`tests` 测试和项目安装配置；不改变本地 FITS 归档和已有资料文档。

**决策依据**：先把输入、参数和输出边界固定，再用真实数据测量 FOV、WCS 残差和检测稳定性，避免在未经验证的相机参数上直接做自动盲解算。

### 2026-08-27 - 增加 Python 桌面工作台与最暗源标注

**变更内容**：新增 `rst19-gui` Tkinter 桌面入口，提供 FITS 帧列表、图像预览、候选点叠加、参数控制、统计卡片、源表摘要和最暗可信源的仪器星等标注；检测默认不限制候选源数量。

**变更理由**：让算法基线可以被参赛队伍直接操作和抽检，同时明确展示候选源与最终科学结果的边界。

**影响范围**：新增 `gui.py`、`photometry.py` 和 Pillow 依赖；移除 Web 服务与静态资源。不上传图像、不引入在线星表服务。

**决策依据**：使用 Python 标准库 Tkinter 配合 Pillow 绘制本地预览，避免浏览器服务和额外前端构建；预览和分析均在本机数据目录内完成。最暗源按质量条件筛选后再用 `m_inst` 标注；真实物理星等留待零点和波段标定。

### 2026-08-27 - 增加交互视图与可清理缓存

**变更内容**：预览支持滚轮缩放、左键拖拽和候选源悬浮信息；切换帧时清除旧状态并用帧令牌保护异步结果；移除启动自动分析，检测结果改为按文件状态和参数键控的 gzip 缓存，并在界面提供清空入口。

**决策依据**：真实 FITS 较大且全量候选源计算成本高，预览和检测解耦可以先确认当前帧，再按需运行；缓存不进入 Git，清空操作只处理 `.rst19-cache/`，不触碰原始图像。

### 2026-08-28 - 增加科研检测和序列关联

**变更内容**：`detection.py` 增加局部背景/RMS、PSF 匹配滤波、孔径通量误差、三种 SNR、形状质量和饱和/掩膜标志；新增 `sequence.py` 与 `rst19-sequence`，提供 15 帧平移配准、唯一轨迹关联和 `static/moving/transient` 分类。

**决策依据**：首帧正峰/负峰对照和阈值扫描表明，单一原始像素峰值不能作为恒星真值；候选、质量源和跨帧轨迹需要同时保留并可审计。所有参数进入 JSON，详细实验记录见 `doc/02-星图识别/检测器实验记录.md`。

### 2026-08-28 - 接入运动候选图层和线状伪迹审计

GUI 新增 15 帧分析按钮和三个互斥叠加层；运动层只取严格 `moving` 轨迹的当前帧原始坐标，悬停可查看轨迹统计。检测器增加 `LINE_ARTIFACT` 连通域/PCA 审计，并将该开关写入缓存键。序列配准使用互相最近的一对一源匹配；切帧时旧任务不会恢复按钮状态或覆盖当前缓存语义。
