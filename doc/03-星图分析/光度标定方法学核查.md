## 1. Gaia DR3 的 G 到底是什么系统

### 1.1 通带

【文献结论】G/Bp/Rp 通带**不是矩形、不是任何标准宽带**，而是"外部标定"的产物：它描述"平均仪器"的
滤光片 x 光学路径 x 探测器量子效率随波长的联合响应，并附带处理过程引入的特征。
官方原文（DR3 passbands 页）：

> "the calibration of most instrumental effects needs to rely uniquely on internal data. This generates a
> photometric system corresponding to an **average instrument** ... the internal average instrument generated
> at each cycle is different. This implies that **any comparison of passbands derived for different releases
> is meaningless**."

【文献结论】G 的**参考响应**取 DR1 名义响应：R_G(λ) = T0(λ) x rho_att(λ) x Q(λ)
（Riello+2021 式(13)；T0 = 镜面反射率，rho_att = 表面粗糙度/分子污染衰减，Q = 探测器 QE）。
G 的波长覆盖从 330 nm 起（Riello+2021 明确写了把 CALSPEC 光谱 "extended to 330 nm" 以覆盖 Gaia 全波段），
红端到 1050 nm 量级；λ0、λp、FWHM 三个通带特征量与零点一起在 Riello+2021 Table 3 给出。

### 1.2 零点：Vega 系，不是 AB

【文献结论】官方 `gaia_source` 字段描述逐字：

> `phot_g_mean_mag` : G-band mean magnitude ... "computed from the G-band mean flux (`phot_g_mean_flux`)
> **applying the magnitude zero-point in the Vega scale** (see Section 5.4.1)."

即目录里的 G 是 **VEGAMAG**。Riello+2021 同时给出了 VEGAMAG 与 AB 两套零点的算法（式(18)(19)）与数值
（Table 3），但**目录值用的是 Vega 系**。

【文献结论】绝对流量定标链：BP/RP 光谱的外部标定基于 SPSS 标定星集，
"the Gaia EDR3 flux scale is **tied to the Vega flux scale to an accuracy of 1%**"。

### 1.3 能不能当"标准 V"

【文献结论】不能。G 是 330-1050 nm 的宽白光标定带，V 是 ~500-700 nm 的窄带；两者之间只有**经验色变换**。
Riello+2021 Table 4 给出 G 与 Johnson-Cousins / SDSS 色指数的多项式关系，并给出**本征残差 sigma**，例如：

| 关系 | 残差 sigma (mag) |
|---|---|
| G - B_T | 0.0706 |
| G - g (SDSS) | 0.0872 |
| G - r (SDSS) | 0.123 |
| G - i (SDSS) | 0.0711 |

（以上 sigma 是我从 ar5iv 全文的**平坦化表格**里逐格读出的"表末列"；多项式系数个数随色对变化
（B_T 那一组 5 个系数，SDSS 那几组 4 个）。**若要把这些数字写进对外报告，请先用 A&A PDF 的 Table 4
复核行/列对齐**——HTML 平坦化后极易错位；我只做了一次读取，未做二次核对。）

【推断】既然官方在**已知标准带之间**转换的残差就有 0.07-0.12 mag，那么"未知响应的 450-750 nm 相机 -> G"
的经验变换不可能优于这个量级；0.07 mag 应当被当作**颜色项残差地板**，而不是本项目能达到的精度目标。

【必须实验决定】本相机（450-750 nm 名义、QE 未知）与 G 的响应重叠程度 —— 它决定：
① 颜色项 C 的量级与符号；② 拟合残差能否降到 0.1 mag 以下；③ 零点是否必须分色报告。

## 2. 参考星该用什么权重

### 2.1 用哪个量

【文献结论】官方**不提供星等误差**：

> `phot_g_mean_mag` ... "**No error is provided for this quantity** as the error distribution is only
> symmetric in flux space. This converts to an asymmetric error distribution in magnitude space which cannot
> be represented by a single error value."

【文献结论】官方提供的是 `phot_g_mean_flux_error`（加权平均通量的误差）与
`phot_g_mean_flux_over_error`（= flux / flux_error，即 SNR）。

【推断】因此权重必须建立在通量空间：

    sigma_G[mag] = (2.5/ln10) * sigma_F/F = 1.0857 / (phot_g_mean_flux_over_error)

这也是唯一与官方"误差只在通量空间对称"的说法自洽的用法。

### 2.2 不确定度随 G 的量级

【文献结论】Riello+2021 摘要给出中位不确定度（由内定标重复测量的标准差测得）：
**G = 10-14 时 0.2 mmag；G ~ 17 时 0.8 mmag；G ~ 19 时 2.6 mmag**；且 "no trends larger than 1 mmag/mag"。

【文献结论】同一篇的 Fig. 14 把实测不确定度与 Jordi+2010 的理论预言对比，并给出
**标定误差地板：G 2.0 mmag、Bp 3.1 mmag、Rp 1.8 mmag**（原文："combined with a calibration error of
2.0, 3.1, and 1.8 mmag for G, G_BP, and G_RP, respectively"）。

【文献结论】官方**没有**发布单一解析式 sigma_G(G)；可用的官方量是"逐源 flux_error"+"发布的中位值/地板"。
方案里问"官方有无发布表/经验式"，答案是：没有单一公式，但有上述中位值表与地板值，
以及逐源 flux_error（这才是该用的东西）。

### 2.3 权重怎么写

【推断】正确的权重应含系统地板：

    w_i = 1 / (sigma_rand,G^2 + (2.0 mmag)^2) ,  sigma_rand,G = 1.0857 / flux_over_error

在 G = 10-13，sigma_rand,G = 0.2-0.3 mmag，被 2.0 mmag 地板完全支配 => **亮端参考星权重几乎相等**，
"更亮的星权重大 4 倍"这类做法在这段星等上没有依据。

【推断】对本项目更要紧的一点：本帧的 sigma_inst 是 0.2 mag 量级（且当前 UNTRUSTED），比 sigma_G 大两个数量级，
所以拟合权重实际由 **sigma_inst 主导**，参考星权重只在"离群判定"和"分组加权"里起作用。
不要为了"Gaia 误差很小"而给参考星写 1/sigma_G^2 的权重——那会让少数亮星独占权重。

【必须实验决定】sigma_inst 的真实值（当前生产模型的误差条不可复现，见方案 §1、补充 §7.2）。

## 3. 参考星质量筛选：每个量约束什么、不能当什么用

### 3.1 逐项（官方字段描述原文 + 用法）

| 量 | 官方口径（摘要） | 它能约束什么 | **不能**当什么用 |
|---|---|---|---|
| `ruwe` | = chi2_AL/(n_good_obs - m) / f(G, BP-RP)；f 是 "renormalising function"，由离线统计（Lindegren 2018 技术说明）确定 | 天体测量解是否良好（未分辨双星、坏解、强抖动） | 光度质量指标。G 的单带测光不依赖 ruwe；ruwe 好不等于测光好 |
| `astrometric_excess_noise` / `_sig` | 官方："If D <= 2 then eps_i is probably not significant" | D>2 时"残差显著大于噪声"，提示未建模误差或双星 | 误差条的替代；也不代表测光被污染 |
| `phot_bp_rp_excess_factor` | C = (I_BP + I_RP)/I_G；官方："A deviation from the norm means that there is a consistency issue between the fluxes" | Bp/Rp 与 G 之间的一致性（Bp/Rp 端的问题） | G 单带的测光质量判据。G 好而 Bp/Rp 坏时 C 会超限，但 G 仍可用 |
| `non_single_star` | short 掩码：bit1 天体测量双星 / bit2 分光双星 / bit3 食双星；只表示"NSS 表里有额外信息" | 已知被识别为非单星 | 双星完整性。绝大多数双星没进 NSS 表 |
| `duplicated_source` | 官方："This may indicate observational, cross-matching or processing problems, or stellar multiplicity, and **probable astrometric or photometric problems in all cases**"；E/DR3 判据 0.18 arcsec（DR2 是 0.4 arcsec） | 处理/交叉证认异常 | 一般性"干净"标记；它专指同一源多 ID 的处理异常 |
| `ipd_frac_multi_peak` | 成功 IPD 窗口中"多于一个峰"的百分比 | 未分辨/已分辨双星、强拥挤（官方明确：对某些双星它反而小） | 测光误差估计；官方原文："The interpretation of this parameter is non-trivial" |
| `ipd_gof_harmonic_amplitude` | ln(GoF) = c0 + c2*cos(2*psi) + s2*sin(2*psi) 的振幅 sqrt(c2^2+s2^2) | 扫描角相关的拟合变差（双星/延展源） | 同上；对暗源统计性差 |
| `phot_variable_flag` | "VARIABLE" / "CONSTANT" / "NOT_AVAILABLE" | 仅标记**被处理并导出**的变星 | **见 3.3，几乎不能用作"非变星"证据** |

### 3.2 阈值：ruwe 的 1.4

【文献结论】1.4 不是官方"物理边界"，而是社区的通行筛选阈值；Lindegren+2021（EDR3 天体测量解论文）
**自己**在选样时就用它：其 LMC 样本写明 "five-parameter solutions, G < 19, and **ruwe < 1.4**"，
另一处视差偏差检验样本写 "13 < G < 17.5 and **RUWE < 1.4**"。

【文献结论】官方对 ruwe 的定性说法（在 `astrometric_gof_al` 描述里）：
"values exceeding, say, +3 thus indicate a bad fit to the data"（这是对 gof_al，不是 ruwe 直接）。

【推断】可执行写法：`ruwe < 1.4` 作为**主筛**，并**分层报告**"切掉多少、切掉的源在 G - m_inst 上的分布"；
不要把它写成"ruwe>1.4 即坏星"的物理解释。

### 3.3 变星：一个必须改掉的用法

【文献结论】`phot_variable_flag` 官方原文：

> "Note that for this data release only a subset of (variable) sources was processed and/or exported, so for
> many (known) variable sources this flag is set to 'NOT AVAILABLE'. **No 'CONSTANT' sources were exported either.**"

【文献结论】我用 TAP 实测确认：`SELECT TOP 1 phot_variable_flag, ruwe FROM gaiadr3.gaia_source` 返回
`NOT_AVAILABLE, 1.1284022`。

【推断】因此：
- 不能用 `phot_variable_flag != 'VARIABLE'` 当"非变星"筛（几乎全库都通过，等于没筛）；
- 也不能用 `vari_summary` 左连的"无记录"当"非变星"（方案已正确写了这一点，此处给出官方原文作依据）；
- 唯一可用的是**反面标记**：`phot_variable_flag='VARIABLE'` => 剔除；
  以及本项目自己的多帧一致性（补充 §4 的 E10），但 E10 已证明它在 SNR>500 的亮端有 28.8% 不一致，
  不能当作"变星识别器"。

### 3.4 建议的筛选组合（推断，可执行）

```
duplicated_source = false
ruwe < 1.4                                # 分层报告切掉多少
astrometric_excess_noise_sig < 2
phot_variable_flag != 'VARIABLE'          # 只作负面标记
phot_g_mean_flux_over_error > 50          # 等价 sigma_G < 22 mmag（仍被 2 mmag 地板支配 => 可放宽到 30）
phot_bp_rp_excess_factor 在 C* 的 +-N sigma 带内（见 3.5）
图像侧：未饱和 / 非边缘 / 3xFWHM 内无邻星 / 多帧静止性通过
```

【推断】在 n~88 的样本上，每加一条筛都会让统计失去意义；**先解决匹配率，再谈筛选分层**（见 §9）。

### 3.5 Bp/Rp 超流量的官方经验关系（可直接实现）

【文献结论】Riello+2021 定义修正超流量 C* = C - f(BP-RP)，其中 f 为分段多项式
（原文 Table 2，我把三段的系数逐格读出）：

| 适用色范围 | a0 | a1 | a2 | a3 |
|---|---|---|---|---|
| x = BP-RP < 0.5 | 1.154360 | 0.033772 | 0.032277 | 无（二次） |
| 0.5 <= x < 4.0 | 1.162004 | 0.011464 | 0.049255 | -0.005879（三次） |
| x >= 4.0 | 1.057572 | 0.140537 | 无 | 无（线性） |

有效范围：-1.0 <= BP-RP <= 7.0。用法：C* = (I_BP+I_RP)/I_G - f(BP-RP)，C* 偏离 0 即 Bp/Rp 与 G 不一致。

【必须实验决定】+-N sigma 中 sigma 的具体取值（论文按颜色/亮度给出散度描述，我未逐字核对其数值）；
本项目的样本色范围预计全部落在 0.5 <= x < 4.0 段，可先用该段。

## 4. 历元、自行、光行差

### 4.1 历元

【文献结论】`ref_epoch` 官方定义："Reference epoch to which the astrometric source parameters are
referred, expressed as a Julian Year in **TCB**"。

【文献结论】本次 TAP 实测（`SELECT TOP 3 ref_epoch, source_id FROM gaiadr3.gaia_source`）三行全部为
**2016.0** => DR3 的 ref_epoch = J2016.0 得到实测确认，不是传言。

### 4.2 传播公式与何时需要径向速度

【文献结论】astropy 官方文档原文：

> "If the SkyCoord object has no specified radial velocity (RV), the RV is assumed to be 0. The new position
> of the source is determined assuming the source moves in a straight line with constant velocity in an
> inertial frame."

即：拿 5 参数（alpha, delta, varpi, mu_alpha*, mu_delta）传播时，透视加速度被丢弃；要恢复它必须给 RV（6D 空间运动）。

【推断】标准的一阶传播（Dt = t - ref_epoch）：

    Dt = 2026.24 - 2016.0 = 10.24 yr
    alpha(t) = alpha0 + mu_alpha* / cos(delta) * Dt     # mu_alpha* = mu_alpha*cos(delta) 已含 cos(delta)，勿重复乘
    delta(t) = delta0 + mu_delta * Dt

更稳的写法：把 (ra, dec, pmra, pmdec) 交给 astropy `apply_space_motion`，让它在球面上做旋转，
避免"直接给 ra 加 pmra/cos(dec)*Dt"在极区/大 Dt 的失真。

数值尺度（用本帧 8.1606 arcsec/px）：
- mu = 100 mas/yr => 1.024 arcsec => **0.125 px**
- mu = 1000 mas/yr => 1.25 arcsec => **1.25 px**（会掉出 1.2 px 门限）
所以传播**必须做**，但它不是当前精度瓶颈。

【推断】何时必须要 RV：条件是两个小量同时成立——(mu*Dt) 已接近/超过匹配门限，且 varpi 大（近距）。
对本项目（Dt = 10.24 yr、门限 1.2 px = 9.8 arcsec = 9.8e3 mas）：
即使 mu = 1 arcsec/yr（极端高自行），线性传播与完整 6D 的差是**毫角秒级**
（判据：位置差 ~ 0.5*(dmu/dt)*Dt^2，而 dmu/dt ~ 2*mu*V_r/d，量级远小于 1 mas）。
=> **本项目不需要 RV，但必须在报告里写明"RV 未用，等价于假设 V_r = 0"**。

【推断】视差同理：varpi = 100 mas => 0.1 arcsec => 0.012 px，一帧内可忽略；若将来要求 0.01 px 级位置，
需按观测时刻的日心位置逐帧加视差。

### 4.3 光行差：对匹配与对测光分别是什么后果

【文献结论】年光行差幅度 ~20.5 arcsec（v_earth/c ~ 9.94e-5 rad）；Gaia 的目录位置是**天体测量方向**
（不含光行差），望远镜观测到的像位置含当刻光行差。

【推断】
- **对匹配**：如果 WCS 是从同一帧的星-像对应拟合出来的，那么该帧的光行差已被吸收进"像 -> 天球"映射，
  不需要额外改正（对 4 参数线性 WCS 尤其干净）。
- 但如果用**外部 WCS**（另一历元/另一来源）或**遥测视轴先验**做绝对比较，20.5 arcsec = **2.5 px** 必须显式处理。
- 差动光行差：在 9.78 deg 视场内，位移随方向的变幅 <= 20.5 arcsec * 0.1707 rad ~ **3.5 arcsec ~ 0.43 px**，
  且是平滑梯度——大部分被线性项吸收，剩余部分远小于当前 WCS 的 4.21 px rms。
- **对测光**：光行差是纯几何映射，**不改变流量**，不需要改正。唯一间接影响是像元相位变化，
  而补充 §2 的 E3 已实测相位效应 0.145%（真实星）/0.84%（注入）< 判据。

【必须实验决定】FITS 首行遥测的视轴先验（RA 129.5335482522945, Dec -1.8453719932545742）
是**J2000 天体测量方向**还是**含光行差的视方向**（或其他历元）。这直接决定
"先验 vs WCS 解"的残差里 20.5 arcsec 该不该出现——没有这一条，任何"WCS 与先验不符"的结论都无法解释。

## 5. 饱和参考星：为什么必须剔除，以及没有 SATURATE 卡时怎么识别

### 5.1 为什么必须剔除

【文献结论】孔径/PSF 测光把"通量"定义为像元值的线性求和；一旦峰值进入非线性区或满阱，
测得通量与真实通量的关系变成一条**未知的、随位置/时间变化的压缩函数**，
而误差条（基于环带噪声）完全反映不了这个系统项。
DAOPHOT（Stetson 1987）与 AAVSO 的 CCD 测光指南都把"饱和/线性上限"列为测光前的必查项。

【推断】对本项目的具体后果：饱和是**亮端单侧、非随机**的偏差，且随亮度单调 =>
它会伪装成"颜色项"或"空间项"进入拟合（因为亮的星更红/更蓝、位置分布也不同），
用留出散度也未必能发现。因此必须在拟合前用**图像证据**剔除，不能靠拟合残差事后剔除。

### 5.2 关于"用亮星定零点"的告诫

【文献结论】AAVSO 指南层面的通行告诫是：**零点应由远离饱和、远离检出限的星确定，亮端只用于检验线性**；
用最亮的星定零点会把零点锚定在最可能非线性的那段。（本条的 AAVSO 页面在本次核查中
**无法访问（403）**，故只能标为"惯例"，不引用具体章节号，见 §10。）

【推断】本项目可直接用的自洽论据，不依赖外部文献：
亮的参考星若被压缩，则 (G - m_inst) 与 G 会出现**斜率 < 1 的正相关**（越亮 ZP 越小）；
方案里观察到的方向正是这个，因此**必须先排除饱和，再解释为颜色项**。

### 5.3 没有 SATURATE 卡时的经验判据（推断，逐条可实现）

1. **峰值平台**：核内（r <= 1 px）>= 2 像元同时 >= 经验上限（补充用过 20000 DN），或出现"成列同值填充"。
2. **负值码**：DN = -1（= 65535 满量程的无符号回绕）出现在核内；补充 §7.1 已发现最亮 3 颗窗口内
   同时有 -1、-24648 与常数填充列 => 溢出旁证。
3. **PSF 拟合残差**：亮核内残差呈"平顶"结构（拟合剖面低于实测两翼），或拟合 FWHM 随亮度系统变大。
4. **增长曲线反向**：AC(r) 在亮端**下降**（越亮修正越小），与"溢出把外翼当核"一致；
   补充 §3.3 已看到 AC(4) 从 1.089（暗）单调降到 1.043（亮），方向与幅度（0.047 mag）都与此一致。
5. **多帧一致性**：同一个源在不同帧的相对通量若在亮端出现 28.8% 的超标散布（补充 §4.3），
   优先怀疑非线性/饱和，而不是变光。

【必须实验决定】真实满阱、线性度上限、ADC 在 0 ADU 与 65535 处的行为。
在拿到之前，**所有亮端星等必须视为未标定**，且必须把"经验上限"写进配置与报告
（例如 `saturation_policy = empirical_20000_DN`）。

### 5.4 一个必须写进方案的数字

【推断】用本帧经验 PSF（FWHM 2.19 px => sigma = 0.930 px => 2*pi*sigma^2 = 5.43 px^2）反推峰值：
峰值 ~ 天光 21 + F/5.43。若一颗星 F = 1.0e3 ADU，峰值 ~ **212 DN**；
即使按方案里较乐观的零点（ZP=19.66）反推 G=10.5 的星，F ~ 6.9e3 ADU，峰值 ~ **1.3e3 DN**。
两者都**远低于**任何合理的满阱（16 bit 上限 65535；经验上限 20000）。
=> 这一算式的用途见 §9.1：它说明"亮星被饱和压低"在本帧数据上**不可能**解释 2 mag 的通量亏损。

## 6. 经验零点与颜色项：拟合、加权、剔除、交叉验证

### 6.1 模型

【推断】最小可用模型：

    G_i = m_inst,i + ZP + C*(BP-RP)_i + e_i ,   w_i = 1/(sigma_inst,i^2 + sigma_G,i^2)

- 加权最小二乘（WLS）；`sigma_G,i = 1.0857/flux_over_error`，并加 2.0 mmag 系统地板（§2）。
- **稳健化**：由于本项目误配率未知且可能很高（§9.1），普通 3 sigma 迭代不够，应先用 RANSAC /
  最小中位残差找初值，再用 3*MAD 迭代精化；否则初值会被误配群拖走。
- 剔除不是"为了好看"：每条剔除都要记录"切掉多少、被切掉的 (G, BP-RP, 位置) 分布"。

### 6.2 交叉验证的标准做法

【文献结论】k 折交叉验证在"数据有空间/时间结构"时会给乐观估计，必须用**分块交叉验证**
（blocked CV）：把数据按空间块分组，整块留出。Roberts et al. 2017 系统整理了这一策略
（"Cross-validation strategies for data with temporal, spatial, hierarchical or phylogenetic structure"）。

【推断】本项目的最小 CV 设计：
- 空间分块：4x4 网格（补充 §3.3 已用它检查 AC 的空间依赖）=> **留一象限 / 留一网格列**；
- 每折 >= 10 颗、总 >= 30 颗、>= 3 个块（方案 §7 G4 已写）；
- 报告量：留出残差的 **RMS 与中位绝对残差**（不是 R^2）、残差-颜色斜率、残差-位置斜率，
  以及 sigma_out（留出残差的标准差，作为"这个零点可信到多少 mag"的唯一对外数字）。

### 6.3 为什么不能用 R^2 报拟合优度

【文献结论】（统计方法学，ESL 第 7 章 "Model Assessment and Selection"）：
R^2（或等价的经验风险）是**样本内**量，随模型自由度单调不降；它回答"模型在已用数据上解释了多少方差"，
不回答"对新源的预测误差是多少"。模型选择必须用**留出/CV 误差**或带惩罚的准则（AIC/BIC）。

【推断】在本项目里的具体危害：n ~ 88 时，加一个二次颜色项几乎必然抬高 R^2，
但留出散度可能同时变差；用 R^2 报优会**奖励过拟合**，而我们要的恰恰是"新源能信到多少 mag"。

### 6.4 高阶项过拟合的判据

【推断】可执行的三条（全部满足才接受高阶项）：
1. **CV 显著下降**：Delta CV > 2 x CV 的标准误（bootstrap 估计），否则按"无改进"处理；
2. **信息准则**：AIC/BIC 下降；
3. **物理可解释 + 显著性**：C/sigma_C > 3，且拟合出的 C 与"响应曲线重叠程度"的定性预期一致
   （例如 450-750 nm 窄带对宽 G，C 应显著非零）。

【推断】再加一条**同质性检查**：把样本按亮度三分位、按空间四象限分别拟合，若 ZP 的分组差异
超过 sigma_out（例如 0.05 mag），则必须升级为"分组零点"或"亮度相关项"，而不是加高阶颜色项。
（补充 §3.3 的 AC(4) 亮度依赖 0.047 mag 正好在这个判据边缘，说明这条不是纸上谈兵。）

## 7. 宽波段（450-750 nm 名义、响应未知）相机做 Gaia G 经验标定

### 7.1 文献与官方资料支持到什么程度

【文献结论】官方**支持**的部分：
1. G 的零点、通带曲线、lambda0/lambdap/FWHM 全部公开，可以算"任意已知 SED 在该通带下的合成星等"；
2. DR3 提供 `xp_synthetic_photometry_gspc` 表：由 Bp/Rp 光谱合成**标准带**的流量/星等，
   含 Johnson-Kron-Cousins UBVRI、SDSS ugriz、Pan-STARRS1、HST ACS/WFC F606W/F814W 等，
   每带都有 `*_flux`、`*_flux_error`、`*_mag` 与 `*_flag`（flag = "G mag and BP-RP color of the
   source lie in the validated range"）；
3. Bp/Rp 光谱本身的绝对定标已系到 Vega 尺度（1%）。

【文献结论】官方**不支持**的部分：没有任何官方资料能把"未知响应的探测器"的星等变换到标准带。
合成测光要求**你提供响应曲线** S(lambda)；没有 S(lambda) 就没有合成测光，只剩经验拟合。

### 7.2 gspc 能解决什么、不能解决什么

【推断】
- **能解决**：给每颗参考星一个"与 Gaia 内部自洽"的合成 V/r/g，从而把经验颜色项拆成两块：
  `C_emp = (G 与合成V 的色差项) + (合成V 与本相机的色差项)`。第二块仍未知，但第一块被固定住了，
  于是可以回答"如果我只做 G 定标，颜色项会有多大"。同时 `*_flag` 给出该星是否在验证区间内，
  是比"颜色区间重叠"更硬的可用性判据。
- **不能解决**：① 本相机自己的带通；② 绝对流量到 ADU 的转换（gain、QE、镀膜、滤光片）；
  ③ 任何"颜色项可以被物理预测"的主张——若没有响应曲线，C 只能被**拟合**，不能被**预测**。
- **额外警告**：gspc 的合成星等建立在 Bp/Rp 光谱上，因此它继承了 Bp/Rp 的系统（例如 C* 超流量问题）。
  用 C* 超限的星做颜色项训练，等于把 Bp/Rp 的误差灌进颜色项。

### 7.3 该怎么命名与限定适用区间

【推断】命名必须把"经验、未知响应、适用区间"三件事写进名字，例如：

    G_emp[450-750nm nominal, response=UNKNOWN, ZP+C(BP-RP), model_id=sha256..., 
          valid: G in [10.5, 13.5], BP-RP in [0.6, 2.0], sigma_out=0.xx mag]

禁止写 `G`、`V`、`R`、`Rc`。若将来拿到实测响应曲线，再升级为 `V_syn`（合成）或 `V`
（若与 Landolt 系一致）。

【文献结论】命名先例：SVO Filter Profile Service 是登记"自定义带"响应的正规设施，
查带/登记带都以它为准（没有响应曲线就无法登记）。

【推断】AAVSO 对"非标准带但按标准带零点报告"用**改写带号**表示（社区常用的 CV/CR/TG/SG 一类代码），
这是本项目"G_emp 精神"的现成先例；但具体代码表需以 AAVSO 文档为准（本次无法访问，见 §10）。

【必须实验决定】C 的符号与幅度；G_emp 的适用区间（只能用"颜色重叠 + 残差趋势"实测确定）。

## 8. 极限星等 / 完备深度 / 最暗已标定源

### 8.1 三个概念不能混

【推断】
- **完备深度 m_comp(50%) / m_comp(90%)**：注入-回收曲线上的回收率点，**只描述流程**；
- **极限星等（limiting magnitude）**：一个上限约定值，用法不统一，**不应在无完备度曲线时使用**；
- **最暗已标定源（faintest calibrated）**：在该通量上**零点仍可用**（留出残差与 0 相容）的最暗参考星，
  与检出能力无关。

### 8.2 报告规范

【文献结论】50%/90% 完备度用注入-回收（artificial-star tests）是 HST 测光的标准做法，
Dolphin 2000（HSTphot）给出了这一套流程与"用回收率曲线定义完备限"的用法。
（DOI 经 Crossref 校验：PASP 112, 1383-1396，标题 "WFPC2 Stellar Photometry with HSTphot"。）

【文献结论】二项比例的置信区间不应直接用 Wald 区间（小 n 时失效），
Brown, Cai & DasGupta 2001 系统比较了各类区间并推荐 Wilson/似然区间；
在 n=30 这样的分箱里，Wald 区间会给出明显偏窄的结果。

【推断】本项目的可执行规范（把方案 §7 G5 落地）：

    m_comp(50%): 每 0.25 mag >= 200 次注入、>= 5 次独立实现、Wilson 95% CI、按背景/拥挤度分箱报告
    m_comp(90%): 同法，且注明"90% 点对 PSF 模型比对 50% 点更敏感"
    报告模板: m_comp(50%) = X.XX mag [band=G_emp(...), model_id=..., n_inj=..., CI=+-...]

【推断】"最暗已标定源"的报告必须写成三件事：通量（ADU）、对应 G_emp、以及该处的 sigma_out；
并明确"这是零点可外推的最暗参考星，不是检出限"。

### 8.3 Eddington / Malmquist

【文献结论】在检出限附近，若只用"测得通量 >= 阈值"的样本做平均，会系统性高估真实通量
（Eddington bias）；Hogg & Turner 1998 给出的极大似然估计是无偏替代
（标题即 "A maximum-likelihood method for improving faint source flux and color estimates"）。

【推断】对本项目的直接含义：
1. 方案的 E7-lite 已用"回收判据"（SNR >= 5 且 |F_meas/F_inj - 1| <= 0.5），这不是极大似然，
   因此 **m_inst(50%) 含 Eddington 偏置**，只能作为"流程完备度"读，不能读成"能测到这个星等"；
2. 注入回收的回收率曲线**不应**用"注入样本的平均测量误差"来修正，而应报告"50% 点的通量"本身；
3. 将来若要做通量无偏估计，需按 Hogg & Turner 的似然做法重写，不在本轮范围。

## 9. 对现有方案必须修改的地方

按"不改正就无法继续"排序。前三条属**阻断级**。

### 9.1（阻断）88 对标定样本必须先证伪，再使用

【推断】用方案给的三组数反推，问题立刻暴露：

| G 分箱 | G - m_inst (=ZP) | 取 G 中值 | m_inst | 反推通量 F = 1.5 * 10^(-0.4*m_inst) |
|---|---|---|---|---|
| 10-11 | 17.60 | 10.5 | -7.10 | **1.04e3 ADU** |
| 11-12 | 18.43 | 11.5 | -6.93 | 0.89e3 ADU |
| 12-13 | 19.66 | 12.5 | -7.16 | **1.10e3 ADU** |

也就是说：**G 跨 2 mag，而三个分箱的仪器通量只跨 0.23 mag**（1.04 / 0.89 / 1.10 x 10^3 ADU），
且不是单调的。这个样本的仪器星等几乎与 G 无关。物理上只有两种解释：
(a) 全部是随机误配；(b) 全部被压到同一个平台。而 (b) 被 §5.4 的峰值估算否掉
（F ~ 1e3 ADU => 峰值 ~ 212 DN，比 20000 DN 的经验上限低约两个数量级；即使按 ZP=19.66 反推
G=10.5 的星，峰值也只有 ~1.3e3 DN）。
另外两个旁证同向：
- **斜率**：(G - m_inst) 对 G 的斜率 = (19.66-17.60)/(12.5-10.5) = **1.03**；
  误配的期望斜率正是 1（m_inst 与 G 无关，于是 ZP 完全跟随 G）。
- **位置残差**：中位 0.83 px；若匹配是随机落入 1.2 px 圆，半径中位数的期望是 1.2/sqrt(2) = **0.85 px**。
  实测与"纯随机"几乎重合，而与"真匹配 + 亚像元 WCS"（应 <= 0.3 px）不符。

**动作**：在做任何 ZP 拟合之前，必须跑并公开三件事：
1. 位移星表对照（方案 E9）：+50/+200 px 位移后的匹配数，误配率 = 位移匹配数 / 真实匹配数；
2. 88 对的**峰值 DN 与负值码**分布（饱和假设的直接检验，一条命令）；
3. 匹配门限扫描（0.5 / 1.0 / 1.5 / 2.0 px）下的匹配数曲线——真匹配应随门限饱和，误配则随门限二次增长。

### 9.2（阻断）88 对与"期望偶然相符数"同量级

【推断】偶然相符的期望数 ~ N_g * N_d * pi*r^2 / A：

    r = 1.2 px = 9.79 arcsec,  pi*r^2 = 301 arcsec^2
    A = 9.78 deg x 9.78 deg = 95.6 deg^2 = 1.24e9 arcsec^2
    N_g = 19582（1 deg 瓦片 40 次查询所得，meta 标 complete=false => 只少不多）
    N_d = 27552（quality）~ 66469（candidate）

    => 期望偶然对数 ~ 131（N_d=27552）~ 316（N_d=66469）

**与实测 88 对同量级或更大**。因此"88 对"这个数字本身不能作为"匹配成功"的证据。
（这是数量级估计：若 Gaia 星表实际覆盖面积小于 95.6 deg²，N_g 密度上升，期望值还会更大。）

**动作**：方案 §7 G3 的门（"匹配率 > 95%；位移对照误配率 < 2%"）保留，但必须**先做 G3 再做 E8**；
并把"匹配率"的定义从"有多少对"改成"有多少对通过了位移对照"。

### 9.3（阻断）WCS 还没到能支撑光度关联的水平

【推断】`rst19-wcs-validation` 的 rms 4.21 px = **34 arcsec**，且 `backend/src` 里 SIP 出现 0 次。
9.78 deg 视场的光学畸变在 4096 px 上留几 px 残差是正常的，因此"无 SIP + 4.21 px rms"这一组合
说明当前解只是"大致对准"，不是"可做 1 px 关联"的解。交互拟合的 0.93 px 也只有 7.6 arcsec。

**动作**：把 WCS 验收改成"留出星残差 p90 < 0.3 px + 位移对照误配率 < 2% + 至少一个非线性项（SIP 或径向多项式）"；
未达标前，任何"星表位置与图像位置"的关联结论都只能标 UNVALIDATED。

### 9.4 误差条：两种口径并列，不要合成一个数

【推断】方案 §6.3 的分解式方向正确，但要补两条**具体口径**：
- 口径 A（生产当前口径）：环带 4xMAD 裁剪后的 sigma_pix => r=4 孔径 7.617 ADU；
- 口径 B（天光中位数误差 x 孔径面积）：sqrt(7.617^2 + (49*0.98)^2) ~ **48.6 ADU**（补充 §4.3 已给）。
两者差 6.4 倍，且**都对**——它们回答不同问题（"像元噪声"vs"孔径和的噪声预算"）。
在 gain 未知（源泊松项缺失）之前，报告必须两个都写，并写明"总 S/N 只会更低"。

### 9.5 权重与筛选的具体改法

- sigma_G 用 `1.0857/phot_g_mean_flux_over_error`，并加 **2.0 mmag** 系统地板（§2.3）。
- 权重实际由 sigma_inst 主导，写法 `w = 1/(sigma_inst^2 + sigma_G^2)`；禁止用 1/sigma_G^2。
- `phot_variable_flag` 只能作**负面标记**（`='VARIABLE'` 剔除），不能当"非变星"筛（§3.3）。
- 加 `duplicated_source = false`（官方明说 "probable astrometric or photometric problems in all cases"）。
- C* 用 Riello+2021 Table 2 的分段系数先算出来，再按 +-N sigma 带筛（§3.5 给了系数）。

### 9.6 历元/光行差的三句话要写进报告

- `Dt = 10.24 yr`，用 `ref_epoch=2016.0`（已实测）+ pm 传播；**RV 未用，等价于 V_r=0**，影响远小于 1 mas。
- 光行差 ~20.5 arcsec：**若 WCS 由本帧自拟合则不需要改正**；若与遥测视轴先验或外部 WCS 比较，
  则 20.5 arcsec = 2.5 px 必须先处理。
- 必须确认遥测视轴先验是**天体测量方向**还是**视方向**（§4.3）。

### 9.7 命名与深度报告

- 一律 `G_emp[...]`，带 model_id、band_kind=Unknown、valid ranges、sigma_out（§7.3 模板）。
- E7-lite 的 m_inst(50%) 只有在挂上 G_emp 之后才能转成星等，且必须写"50% 注入回收，不是完备深度上限"，
  并注明含 Eddington 偏置（§8.3）。
