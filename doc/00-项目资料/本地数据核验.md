## 3. 首行辅助数据核验

比赛方说明指出，图像数据第一行的前 208 字节保留为辅助数据，即第一行前 104 个 16 bit 像素位置不应直接当作普通图像像素。按说明中的 16 位字节交换后，以小端格式解包 26 个 `double`，当前首个文件得到：

- `p_az = 270.0`
- `p_el = 0.0`
- `ra ≈ 129.533548`
- `dec ≈ -1.845372`
- `q1..q4 ≈ (0.658783, 0.224458, -0.671886, 0.253363)`
- `roll/pitch/yaw ≈ (59.4144, -14.9257, 9.4498) deg`

其中 `p_az`、`p_el` 与 FITS 头一致，且姿态四元数数值量级合理。随后对 15 个文件逐一执行了同一审计，结果见下一节。

### 3.1 15 帧辅助姿态—光轴一致性

格式说明给出相机物理指向为卫星本体坐标系的 `-Y` 轴，四元数为矢量在前、标量在后的 `(q1,q2,q3,q4)`。按标准 Hamilton 矩阵把本体 `-Y` 轴变换到 J2000 方向后，再换算为 RA/Dec，与每帧辅助字段比较，得到：

| 审计项 | 15 帧结果 |
| --- | ---: |
| 辅助数据完整帧 | `15/15` |
| 四元数范数范围 | `0.9999999999999998--1.0000000000000002` |
| 四元数推导光轴最大角残差 | `1.1×10^-10 arcsec` |
| `p_az/p_el` 与头部指向一致 | `15/15` |
| 辅助 RA 范围 | `8.60 arcsec` |
| 辅助 Dec 范围 | `7.79 arcsec` |

这证明了本批文件的 `ra/dec` 可以作为逐帧光轴中心先验，四元数与 `-Y` 轴的约定也得到数据内部复核。它仍不是完整 WCS：格式说明没有给出图像列/行对应的相机横纵轴、像元角尺度、焦面旋转、畸变或曝光期间姿态积分。因而当前只能把它用于缩小星表搜索区域和检查帧间指向，不能从目录行数直接推断图像恒星数。

可复现产物为 `tmp/auxiliary-attitude-audit/auxiliary_boresight_audit.csv` 和 `auxiliary_boresight_audit.json`；代码入口为 `rst19-aux-audit`。

## 4. 图像值抽检

对首个文件按 FITS 16 bit 大端存储读取，并暂时排除首行前 104 个辅助数据位置后，得到：

- 数据数组形状：`(4096, 4096)`，对应 FITS 的 `(NAXIS2, NAXIS1)`。
- 数据类型：`>i2`，即大端 16 bit 有符号整数。
- 像素最小值：`-32726`。
- 像素最大值：`32750`。
- 非零像素约 16.70M 个；存在少量负值和大量低值背景像素。
- 99.9 分位约为 `1232.8`，99.99 分位约为 `7776.6`。

这些数字只用于确认数据范围和后续参数初始化，不能直接解释为物理亮度或星等。负值、接近 16 bit 极值的值、首行辅助区域和可能的饱和点都需要在算法中显式标记。

对 15 帧原始数组又做了逐像素范围审计。每帧精确 `-1` 的数量为 `130--156`，合计 `2,185`；其中有 `74` 个探测器坐标在 15 帧中始终为 `-1`。这组固定位置证据明显不同于独立背景噪声，但格式说明没有声明 `-1` 是 `BLANK`、坏像素、饱和标记还是合法物理码，因此当前只把它记为“固定无效码候选”，不直接改写原始像素。每帧低于有符号 16 位负侧 `90%` 的极端负码为 `33--47` 个，合计 `600`；每帧高于正侧同等范围的极端正码为 `39--59` 个，合计 `738`。这些极值也不能在没有 ADC/满阱资料时直接命名为物理饱和。

## 5. 已知冲突与处理决定

原始 DOCX 正文写有“4096×4098×16bit”，但实际 15 个文件的 `NAXIS2` 均为 4096，且文件大小严格符合 4096×4096×16 bit 加 2880 字节头。当前处理决定：

1. 以每个 FITS 文件的合法头字段为准。
2. 解析前检查 `NAXIS1`、`NAXIS2`、`BITPIX` 与文件长度。
3. 把说明文档中的 4098 记录为待向比赛方确认的文字差异，不在代码中写死 4098。

此外，`BITPIX=16`、`BZERO=0`、`BSCALE=1` 按 FITS 标准支持当前程序的有符号 `>i2` 读取；但比赛材料只明确写“16bit”，没有明确探测器 ADC 的有符号/无符号语义，也没有 `BLANK` 卡片。把同一帧仅作诊断性地重解释为 `uint16` 后，局部亮部会从“含正负异常码的两个响应”变成一个连续的高/饱和核心，但全图质量源从历史有符号读取的约 `29,271` 级别骤降到 `176`；当前默认 `CODE_PATTERN` 口径为 `29,263`。这说明 `uint16` 是需要主办方确认的替代假设，不能直接作为默认读取方式。

## 8. 位置—速度单位的独立自洽检查

重新读取归档的《天基图像数据格式说明.docx》后，能确认以下两点：

1. `DATE-OBS` 是 UTC 时间，并且说明表述为曝光中心时刻；
2. `j2000_x/y/z`、`wgs84_x/y/z` 的位置单位写为 `m`。

速度字段 `j2000_xv/yv/zv`、`wgs84_xv/yv/zv` 在说明表格中原文写成 `m`，没有写出 `/s`。这与字段名和物理含义不完全相符，因此代码没有静默修改原始格式说明，而是增加了一个独立的数值核验：用 `DATE-OBS` 的真实时间差，对位置做首尾一侧差分、中间帧中心差分，再与速度三分量比较。

15 个文件的独立计算结果如下：

| 参考系 | 位置差分速度模长中位数 | 说明表速度模长中位数 | 中间帧相对误差中位数 | 中间帧相对误差最大值 |
| --- | ---: | ---: | ---: | ---: |
| J2000 | 7,610.652 | 7,610.5 | 0.00243% | 0.00749% |
| WGS84 | 7,690.705 | 7,690.6 | 0.00263% | 0.00752% |

位置单位为 `m`、时间单位为 `s` 时，位置差分速度的单位必然是 `m/s`。上表显示两者在中间帧上高度一致，因此目前最稳妥的判断是：速度字段的实际单位高度可能是 `m/s`，而 DOCX 速度行疑似漏写 `/s`。这是一条由原始文件内部一致性支持的假设，不替代主办方对格式表的正式确认；在答辩材料中应写成“`m/s`（由位置—时间差分自洽支持，格式说明待确认）”。

端点使用一侧差分，误差会受离散化和姿态变化影响而略大，不能只用首帧或末帧否定整体一致性。这个检查验证的是辅助遥测字段的解码、时间序列连续性和单位线索，不是图像平面长线的 `px/s`，更不是完整轨道解算。代码会在 `innovation_report.json`、`frame_evidence.csv` 和 GUI 的“辅助遥测”页同时保留原始向量、位置差分速度和相对误差，方便复核。

## 9. 2026-09-01 漏检抽测补充

## 10. 2026-09-01 时序补提案门槛抽测

为区分“多帧先验漏检”与“降低普通候选门槛导致的纹理泄漏”，当前代码允许把 `candidate_consensus_min_snr` 与 `temporal_reference_min_snr` 分开设置。真实 15 帧、`both` 模式、普通候选保持 `15σ` 而时序参考降到 `12σ` 时，稳定静态为 `5,276`、持续候选为 `20,249`、合计 `25,525`；相对参考门槛同为 `15σ` 的 `22,174` 合计，新增 `3,344` 条注册坐标，其中 `2,947` 条出现 `15/15` 帧。新增坐标的逐帧原图近似核心/形态抽样中 `2,919/3,344` 通过代理检查，但它们仍未经过完整逐星星表确认，不能直接计为真实恒星。

作为敏感性控制，把普通候选门槛也降到 `10σ` 时，持续候选增至 `24,213`，但 `support=0` 的时序淘汰增至 `3,972`。因此当前正式口径保留 15σ，12σ 作为可复核的召回研究层，10σ 只用于审计；所有新增候选仍必须回到原始 FITS 做 PSF 支持、形状、掩膜、持续性和人工/星表核验。

## 11. 2026-09-01 局部峰定位复测

继续抽测发现，时序参考坐标在注册后可能落在像素之间。旧实现将其直接四舍五入到单个整数点，导致真实 PSF 中心落在相邻像素时被形状细筛误拒。当前在预测点 `±1 px` 的 `3×3` 窄窗口内寻找最高匹配响应，再执行原始图像的 `support_3x3`、局部背景、PSF 相关和持续性审计；这不是降低 SNR，也不是扩大到远邻随机峰。

同一真实 15 帧、Gaussian 单帧提案、参考 SNR `15σ`、PSF 相关 `0.80` 的快速口径复测为：

| 时序定位 | 严格静态 | 持续候选 | 稳定/持续合计 | PSF 相关拒绝 |
| --- | ---: | ---: | ---: | ---: |
| 固定预测整数点 | 5,276 | 14,919 | 20,195 | 1,336 |
| 局部 `±1 px` 峰重定位 | 5,276 | 15,524 | 20,800 | 669 |

局部重定位增加的约 `793` 个注册坐标中，`777` 个出现 `15/15` 帧；这支持“部分漏检由定位误差造成”的工程判断，但不能把新增坐标自动视为真实恒星。当前序列缓存版本为 `29`，旧整数定位结果会自动失效；正式结论仍需可靠 WCS/星表、实测 PSF、阴性对照和分层注入回收共同确认。

## 12. 2026-09-06 15 帧符号反相的值域复核

为检查原始负侧异常是否会在阴性对照中伪装成亮星，对 15 个 FITS 逐帧构造 `I_mirror=2B-I`，其中 `B` 为各帧 sigma-clipped 背景；检测参数保持 `hybrid / 4σ / min_distance=4 px / FWHM=2 px / flux SNR≥5 / PSF support≥3`。结果不能替代 signedness 或坏像素标定，但能把反相响应与原始值域证据对应起来：

| pooled 项 | 数量 |
| --- | ---: |
| 正向候选/质量 | `1,282,630 / 441,619` |
| 反相候选/质量 | `36,170 / 35` |
| 与原始极端负码扩张区相交的反相候选/质量 | `570 / 19` |
| 排除极端负码转移后的反相质量 | `16` |

35 个反相质量源中，`32` 个原始孔径含负像素，`32` 个含 `≤−1000 ADU` 的异常负值，`19` 个含 `≤−29,490.3 ADU` 的极端负值，`22` 个含精确 `-1`。排除极端负码转移后剩余 16 个中仍有 `13` 个原始异常负值；另外 `3` 个没有负值证据，且是弱/宽响应。由此应把它们分成值域转移、负值/固定哨兵异常、普通弱/宽候选三类，不能以“反相即噪声”或“反相通过即真星”作判断。
