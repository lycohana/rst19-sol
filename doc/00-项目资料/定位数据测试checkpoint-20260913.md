## 当前判定

在没有额外关联说明前，PIC 与 POS 不能直接建立逐帧真值配对。已观察到三项独立不一致：

1. 包名中的 ID 不一致：PIC 为 `39155` / `1472628590117082`，POS 为 `44299` / `1472628590117087`。
2. FITS 头部时间与 POS 时间不重叠，首尾相差约 7 分 32 秒。
3. FITS 首行辅助定位字段全零，不能用它补回这段时间差。

因此，本 checkpoint 后续的“程序精准度”必须拆成两种测试：

- 若主办方确认两包确实属于同一目标但存在时间偏移：先求出时间偏移和坐标到像素的映射，再做逐帧误差评估。

## 本 checkpoint 的算法修正（2026-09-13）

### 已确认的旧问题

第一次全量序列运行并不能直接证明“检测准确率”。在程序内部仍可以确认两个会造成运动误报的工程问题：

- 仅用平移配准时，F04→F05 等相邻帧的宽一致位移约为 `18 px`，后续还出现约 `37–38 px` 的帧间累计变化；旧的局部 `8 px` 搜索容易选到密集星场中的错误近邻。
- 修正宽搜索后，平移配准得到 `1903` 条严格静态轨迹和 `650` 条点源 `moving`。这 `650` 条的原始拟合位移为约 `2.02–13.43 px`，且都共享类似的亚像素/小角度视场漂移；它们不像 650 个彼此独立的物理目标。

### 已完成的修正

- 注册阶段将“配准搜索半径”和“轨迹关联半径”分开：在有限宽窗口内寻找互相最近源，再用二维位移一致簇估计帧间平移。
- 在平移配准后的跨帧源对上增加稳健全局仿射残差拟合。只有满足非共线源数、RANSAC 内点比例和小尺度/小剪切约束时才启用；否则回退到平移模型。
- 点轨迹的位移和直线拟合 RMS 在仿射残差校正后的坐标上计算，但 `TrackPoint.aligned_x/y` 和 `cumulative_shifts` 仍保留平移坐标，便于复查原始配准证据。
- 运动下限不再只看用户输入的 `2 px`：在有足够轨迹时，程序用校正后稳定多数的 robust median + `5×1.4826×MAD` 得到数据驱动的有效下限，并把它写入 `effective_motion_min_displacement_px`。这只是“当前配准误差下无法解释的位移门槛”，不是物理速度真值。
- 主轨迹、快速点源补检和候选轨迹补检现在共用这个有效下限；不会出现主分类已经过滤掉伪运动、辅助层又用旧的 `2 px` 把它重新加入输出的情况。
- 序列缓存版本从 `39` 升为 `40`，旧缓存会自动失效，避免 GUI 继续显示旧的 `650` 条 moving 结果。
