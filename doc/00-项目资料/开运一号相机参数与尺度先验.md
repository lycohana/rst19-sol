# 开运一号相机参数与尺度先验

状态：**已收到设备参数截图；作为外部设备先验登记，尚未完成图像级标定**

这份资料来自用户补充的《开运01星相机参数》截图。它补上了此前项目中缺少的相机几何信息，但这些字段没有写入当前 15 个 FITS 的标准 WCS 头，因此不能直接被当成每一帧已经验证的 WCS。

机器可读记录见 [`开运一号相机参数.json`](./开运一号相机参数.json)。

## 1. 用户补充的原始参数

| 参数 | 补充值 | 在本项目中的含义 |
| --- | ---: | --- |
| 像元尺寸 | `9 μm` | 计算标称像元角尺度的输入 |
| 像素分辨率 | `4096×4096` | 与当前 15 个 FITS 的实测 `NAXIS1/NAXIS2` 一致 |
| 位深 | `16 bit` | 与当前 FITS 的 `BITPIX=16` 一致；不等于已知满阱、增益或饱和阈值 |
| 入瞳口径 | `120 mm` | 可用于计算理想衍射尺度；不等于实际 PSF 或有效通光口径已完成标定 |
| 焦距 | `220 mm` | 计算标称几何视场和像元角尺度的输入 |
| 谱段 | `450–750 nm` | 宽谱响应范围描述；不是 Johnson V 或 Gaia G 的等价声明 |
| 全视场 | `9.78°×9.78°` | 另一条独立的标称角尺度来源 |

当前 FITS 的曝光时间仍由文件头读取，实际数据核验为 `1500 ms`。相机截图没有提供曝光、增益、读出噪声、满阱、非线性、暗电流、平场或响应曲线，因此这些量不能由本表补齐。

## 2. 由参数直接推导的结果

### 2.1 传感器物理尺寸

```text
4096 × 9 μm = 36.864 mm
```

因此按截图参数，主动成像面约为 `36.864 mm × 36.864 mm`。

### 2.2 两条像元角尺度先验

由焦距和像元尺寸计算：

```text
scale_focal = 206265 × 0.009 / 220
            ≈ 8.438 arcsec/pixel
```

由标称视场直接计算：

```text
scale_fov = 9.78 × 3600 / 4096
          ≈ 8.596 arcsec/pixel
```

由 `36.864 mm` 有效宽度和 `220 mm` 焦距计算的几何视场为：

```text
FOV_geometry = 2 × atan(36.864 / (2 × 220))
             ≈ 9.578°
```

两种视场标称值相差约 `2.1%`，对应的像元角尺度相差约 `1.87%`。如果把 `9.78°` 视为严格值，它反推出的等效焦距约为 `215.44 mm`，而不是截图中的 `220 mm`。

这不一定说明某个参数错误，可能来自焦距取整、有效成像面/裁剪口径、厂家视场定义、镜头畸变或规格书四舍五入。但在没有星表残差之前，不能擅自挑一个数字写进默认 WCS。

因此当前项目登记为：

```text
像元角尺度先验范围：8.438–8.596 arcsec/pixel
默认 WCS：不预填、不硬编码
验证方式：用唯一星表匹配拟合尺度、旋转、parity，并检查留一残差和空间残差趋势
```

命令行中的 `--pixel-scale-arcsec` 仍然是显式先验参数；它不会因为这张截图自动变成已验证真值。

### 2.3 入瞳和采样的解释

焦比的标称值为：

```text
f/# = 220 / 120 ≈ 1.83
```

在 `550 nm`、理想圆孔、无像差的条件下，第一衍射零点角尺度约为 `1.15 arcsec`。这只是理想衍射尺度，不是当前图像的实际 FWHM，也不能直接据此判定星点应占多少像素。与约 `8.44–8.60 arcsec/pixel` 的几何尺度相比，实际可见 PSF 更可能受镜头像差、离焦、平台抖动、探测器响应和数字化过程影响，必须从未饱和亮星或注入实验中测量。

## 3. 对现有算法的影响

### 可以立即使用的部分

- 用 `8.438` 和 `8.596 arcsec/pixel` 做 WCS 初值敏感性对照，而不是当最终结果。
- 对图像平面运动速度给出一个有边界的角速度换算。例如历史结果中的 `37.829 px/s`，在两条尺度先验下约为 `0.0887–0.0903°/s`；在 WCS 未验证前，正式结论仍应写作 `37.829 px/s`。
- 用 `f/#≈1.83` 解释为什么不能把理想衍射极限直接当作实际 PSF，并继续使用实测 PSF、局部背景和多帧证据筛选亮点。
- 把 `450–750 nm` 纳入测光限制说明：当前的 `m_inst` 仍是同一设备内的仪器星等，不能直接命名为 `m_V`、Gaia `G` 或绝对星等 `M_V`。

### 不能由这张图直接得到的部分

1. **完整 WCS**：还缺图像 x/y 轴对应的天空方向、旋转角、RA 轴正负号、镜头畸变/SIP 和曝光期间姿态变化。
2. **物理星等**：还缺相机/镜头/探测器的总响应曲线、有效波段、增益、读出噪声、饱和和非线性参数，以及同设备标准星或可靠零点。
3. **绝对星等 `M_V`**：还缺经过可靠身份确认的目标表观星等、距离/视差和消光；对人工目标还要考虑距离、相位角、反照率、姿态和光变。
4. **运动目标真值身份**：相机参数只能提供像面到天空的尺度先验，不能单凭一条亮线或一个点源证明它是哪颗卫星。

## 4. 与 AOE 轨道数据的衔接

主办方提供的 RST19 页面确认，本赛题使用开运一号的 15 张天基图像，并把 15 帧中的运动目标识别列为星图分析任务。[RST19 太空目标识别仿真组介绍](https://spacemapper.cn/special/rst19)

SpaceMapper 的轨道数据页面列出 AOE 及国际轨道库，并提供 TLE、JSON、CSV、API 等数据形态，同时列出 SGP4、数值积分、J2/J4 和光学定轨等算法类别。[AOE 轨道数据页面](https://spacemapper.cn/zh-cn/satellite/orbital)

但是，网页入口本身不是当前 15 帧运动目标的真值记录。要把它用于本项目的“轨道核验层”，还需要实际下载或获授权提供：

| 必需数据 | 用途 |
| --- | --- |
| 目标对象 ID/名称 | 把轨道记录和图像候选建立可审计身份链 |
| TLE 或状态向量及历元 UTC | 在每个 `DATE-OBS` 推算目标状态 |
| 坐标系、时间系统、传播器和版本 | 防止 TEME/ECI/WGS84/Topocentric 混用 |
| 轨道质量、协方差或误差字段 | 给预测位置设置合理门限，而不是只看单条轨道线 |
| 开运一号逐帧平台位置、姿态和时间同步 | 把目标状态变换到相机视线 |
| 图像轴向、尺度和畸变标定 | 把预测 RA/Dec 投影到具体像素 |

完整核验链应为：

```text
AOE 目标轨道
  → 按 DATE-OBS 传播
  → 目标相对开运一号的视线 / 角速度
  → 相机 WCS 投影到 (x, y)
  → 与逐帧候选轨迹比较位置残差、速度残差和出现帧
  → 输出“轨道支持的身份候选”，而不是直接改写检测标签
```

尤其要区分：FITS 首行的 J2000/WGS84 位置和速度是观测平台辅助遥测；AOE 记录是待核验的目标轨道。二者不能把字段直接拼接成“目标轨道”。

## 5. 目前应如何写进论文和答辩

可以把设备条件写成：

> 根据主办方补充的开运一号相机参数，探测器像元尺寸为 9 μm、阵列为 4096×4096、焦距约 220 mm、入瞳口径约 120 mm、标称视场为 9.78°×9.78°，谱段覆盖约 450–750 nm。由像元尺寸/焦距和标称视场分别得到约 8.438 和 8.596 arcsec/pixel 两个尺度先验；由于两者存在约 2% 的规格差异，本文不将其直接当作最终 WCS，而以星表唯一匹配、局部仿射拟合和留一残差进行验证。光度结果在响应曲线和零点未获得前仅报告仪器星等，不将宽谱范围直接等同于 V/G 波段。

这段表述既使用了新增设备信息，也主动回答了答辩时最容易被问的两个问题：为什么没有直接把 `9.78°` 写死，以及为什么不能把 `450–750 nm` 直接叫作 V 波段。
