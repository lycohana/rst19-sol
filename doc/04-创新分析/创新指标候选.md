# 创新指标候选

状态：**候选方案；需要基础检测结果和实验验证**
对应赛项：创新赛项

## 1. 选择原则

创新赛项要求从图像中得到有价值的分析数据。一个可进入比赛材料的指标至少应回答：

1. 数据从哪些像素、头字段或检测结果计算出来？
2. 计算公式、单位和时间/空间粒度是什么？
3. 为什么它具有科学性，哪些假设会使它失效？
4. 对实际场景有什么用途？
5. 如何用合成数据、重复测量或交叉验证证明它不是随机数字？

以下是围绕当前 15 帧数据的候选指标，不代表已经得到有效创新数据。

## 2. 优先候选

### 指标 A：图像质量与可探测性指数

**输入**：每帧像素、二维背景和背景 RMS。
**候选输出**：背景中位数、RMS/MAD、动态范围、饱和率、坏值率、可检测源数量、指定 SNR 下的经验检测极限。

**方法**：

- 对排除辅助数据和 mask 后的区域做分块统计；
- 用合成点源注入得到不同 SNR/亮度下的恢复率曲线；
- 用统一阈值比较 15 帧的有效观测能力。

**现实意义**：可用于自动选择质量较好的观测帧、比较成像状态、为星点/运动目标检测提供动态阈值。

**科学边界**：背景 RMS 不是完整噪声模型；若没有增益、读出噪声和暗电流资料，只能称为图像质量/经验可探测性指标，不能直接解释为仪器灵敏度。

### 指标 B：星场配准与姿态稳定性

**输入**：多帧高置信静态星点、FITS 头中的 `DATE-OBS`、`AZIMUTH`、`ELEVATIO` 和辅助姿态字段。
**候选输出**：帧间平移、旋转/仿射参数、配准残差 RMS、星点位移分布、姿态变化率、四元数范数和异常帧标记。

**方法**：

- 用静态星点拟合帧间变换；
- 记录内点数量和残差的时间序列；
- 将图像平面抖动与姿态辅助量做相关分析；
- 若相机内参和 WCS 未知，只报告像素平面稳定性，不推导角秒级指标。

**现实意义**：可用于评估星图识别和运动目标识别的配准难度，也可作为观测质量监控量。

**科学边界**：像素位移不是姿态角变化的同义词；镜头畸变、光轴偏差和 WCS 缺失都会影响解释。

### 指标 C：星点检测完整性与经验极限

**输入**：星点检测目录、背景 RMS、合成注入结果、测光通量。
**候选输出**：检测召回率曲线、误检率、不同区域的完整性、星点计数对阈值的敏感度、指定召回率下的经验极限。

**方法**：

- 在真实背景中注入已知位置和通量的 PSF；
- 按亮度、位置、FWHM 和拥挤程度分箱；
- 统计在 50%、80%、90% 或预先约定召回率下的恢复阈值；
- 比较全局阈值与局部 RMS 阈值。

**现实意义**：比单独报告“找到 N 颗星”更能说明算法在暗源和复杂背景下的可靠范围。

**科学边界**：注入 PSF 必须尽量接近真实点扩散函数；如果真实源形状未建模，完整性曲线只能是近似评估。

### 指标 D：运动目标动力学特征

**输入**：高置信运动轨迹、`DATE-OBS`、差分通量和拟合残差。
**候选输出**：像素速度、方向、加速度候选、轨迹长度、持续帧数、亮度变化率、目标与静态星场的相对运动量。

**方法**：

- 先用常速度模型拟合；
- 只有在时间跨度和定位精度允许时，才比较加速度模型；
- 用轨迹内点、拟合 RMS 和合成注入误差给出可信区间；
- 没有像元尺度和 WCS 时保留为 pixel/s、pixel/s²。

**现实意义**：可以用于目标分类、优先级排序、后续跟踪和观测计划设计。

**科学边界**：像素运动不能直接等同于天体真实空间速度；未进行视场几何和卫星运动校正时，不能推导轨道。

## 8. 合规、可解释的星点识别流程

这里的“合规”指不伪造真值、不把未经标定的量写成物理量，并且能够让评审从输入、参数、输出和失效条件复核结果。建议固定以下五层流水线：

### 8.1 数据完整性和掩膜层

1. 检查 FITS 主 HDU、`BITPIX`、尺寸、数据长度和首行辅助区；
2. 按主办方格式说明解码辅助字段，但保留原始存储值，不擅自应用 `BSCALE/BZERO`；
3. 屏蔽首行前 208 字节对应的图像像素、NaN/Inf、零值和已知坏像素；
4. 若没有官方饱和阈值，只记录原始最大 ADU，不输出“饱和率”。

这一步的目的，是防止辅助字段、截断区域和坏值参与背景统计或被误报成星点。掩膜位置、占比和处理参数必须写入结果，而不能只留在代码默认值里。

### 8.2 背景和噪声层

对图像分块计算局部背景 `B(x,y)` 和局部尺度 `σ_B(x,y)`，使用 sigma-clipping 或稳健 MAD 抑制星点和长线对背景的污染：

```text
MAD = median(|I - median(I)|)
σ_MAD = 1.4826 × MAD
```

当前 rst19 基线使用分块背景/RMS；创新实验应比较全局背景、128 px 分块背景和更小分块的差异，并保存每个版本的背景中位数、RMS、分位数和异常区域占比。官方 Photutils 文档也将 2D 背景拆成网格估计、sigma clipping、背景 RMS 估计和插值地图几个独立步骤，而不是用一个全图均值代替背景模型。[Photutils Background2D](https://photutils.readthedocs.io/en/stable/api/photutils.background.Background2D.html)

### 8.3 候选峰层

用与点扩散函数接近的 Gaussian PSF 做匹配滤波，再在滤波响应上做局部峰检测：

```text
C(x,y) = (I - B) ⊗ P
candidate ⇔ C(x,y) ≥ k · σ_C(x,y)
```

其中 `P` 为归一化 PSF，`k` 是可记录的检测阈值，当前实验为 `4σ`。`min_distance` 只控制峰之间的空间抑制距离，改变它会明显改变候选数量，所以不能把它当作与阈值无关的“算法常数”。Photutils 的 DAOStarFinder 文档也明确区分了卷积后峰值阈值、Gaussian 核尺寸、sharpness/roundness 形状约束以及峰检测的最小间距。[Point-like Source Detection](https://photutils.readthedocs.io/en/stable/user_guide/detection.html)

### 8.4 点源质量层和测光层

候选峰不能直接当作恒星。每个候选至少保留：

| 字段 | 含义 | 当前用途 |
| --- | --- | --- |
| `snr` | 峰值相对背景噪声的 SNR | 亮度显著性 |
| `filter_snr` | 匹配滤波响应的 SNR | PSF 相似源的检出强度 |
| `flux_snr` | 孔径通量 / 通量误差 | 最暗可信源排序 |
| `fwhm_x/y` | 两个方向的宽度 | 排除异常细长结构 |
| `ellipticity` | 点源椭圆程度 | 排除拖影、边缘和异常形状 |
| `sharpness` | 峰形相对尖锐程度 | 区分点源与平坦/尖刺异常 |
| `footprint_pixels` | 有效局部足迹大小 | 排除孤立热像素或过大结构 |
| `flags` | `EDGE/MASKED/SATURATED/LINE_ARTIFACT` 等 | 给出可审计拒绝原因 |

只有通过质量层的源才进入固定星场配准、星表匹配和最暗可信源判定；被拒绝的候选仍可在审计层查看，但不能参与静态星场模型。这个分层比单独报告“检测到 N 颗星”更容易回答科学性问题。

### 8.5 星表与真值核验层

星表的正确角色是建立预期星场和外部核验，而不是替代图像检测。推荐顺序是：

1. 先验证 FITS 辅助 RA/DEC、相机方向和像元尺度的定义；
2. 用亮、孤立、未饱和、形状稳定的质量源做初始匹配；
3. 对匹配残差做留出验证，不用全部匹配点同时拟合和验收；
4. 再逐步加入暗源，记录 unmatched 是噪声、星表不完整、波段差异、WCS 误差还是运动目标；
5. 绝对星等必须有零点、曝光、波段和颜色项校准；当前 `m_inst` 只能作为相对测光量。

## 9. 高速长轨迹的单图与序列两级判定

单图长轨迹不能用点源筛选硬判为恒星，也不能凭一张图直接判定“在运动”。当前单帧接口使用独立线状层：

```text
R = I - B
T = max(100 ADU, 15 × noise)
support = R ≥ T
```

对连通域计算协方差矩阵特征值 `λ1 ≥ λ2`，并使用：

```text
length ≈ 4√λ1
width  ≈ 4√λ2
axis_ratio = √(λ1 / λ2)
```

当前默认几何门槛为：有效面积至少 40 像素、长度至少 `max(18, 6×FWHM)`、细长比至少 4；触边的小结构还要满足更高长度门槛。输出给用户时：

- 单帧长线：橙色 `candidate`，可以标出位置、长度、宽度、方向和残差 SNR；
- 跨帧长线：在配准坐标中预测关联，至少连续出现 3 帧、有足够位移且直线拟合 RMS 合格，才标为 `moving`；
- 漏帧不重连，避免把两个偶然伪迹串成一条轨迹。

这套规则与深度学习方案的职责不同：论文中的 ASTA 方案先用 U-Net 提取候选，再用概率 Hough 细化长线，并依靠人工标注数据评价 precision/recall；本项目当前采用可解释的残差、PCA 和跨帧拟合，适合在没有大规模人工训练集时做可复核基线。后续可把 Hough 作为对照实验，而不是未经训练就直接引入黑盒模型。[Stoppa et al. 2024](https://arxiv.org/abs/2407.19461)

## 10. 15 帧可交付的创新数据

### 数据 1：图像质量与可探测性

当前已输出：候选峰范围、质量源范围、背景 MAD/RMS、分位数、零值比例和有效像素数；并已在真实首帧的相对空白窗口上完成不同强度的 Gaussian 注入-回收，计算：

```text
recall = TP / (TP + FN)
precision = TP / (TP + FP)
```

用 50%、80%、90% 召回率对应的通量/SNR 作为经验检测极限。当前首帧真实背景实验显示，候选层在 24 ADU 附近进入高召回区，质量层约在 36–56 ADU 之间从中等召回进入完全回收区；这些是当前 Gaussian、FWHM=3 像素、相对空白窗口的经验边界，不是整幅图的恒星真值或普适检测极限。完整表格、背景选择规则和限制见检测器实验记录。

这组结果可以形成一个有科学边界的创新结论：在当前真实背景的相对空白窗口中，算法的候选发现能力和严格质量判定能力存在明显“性能阶梯”。候选层适合做高召回审计，质量层适合做静态星场配准和星表匹配；把两者合并成一个“检测到 N 颗星”的数字会掩盖暗源损失。另一方面，真实背景中的未知星点、固定结构和热像素尚未有逐星标签，所以注入保护区外的约 53,427 个候选/23,627 个质量源只能报告为背景检测，不能当作误检数量。Gaussian 实验输出保存在 `tmp/real-background-psf-support/real_background_injection.csv` 和同名 PNG 中；它是可复现的首轮完备率证据，不是最终比赛真值。

作为 PSF 模型敏感性对照，旧目录 `tmp/real-background-empirical/real_background_injection.csv` 使用的是模板筛选修复前的历史经验核：当时记录为 64 个模板源、中位 FWHM 约 `1.934 px`、核和约 `3.288`，不能直接作为当前 PSF 统计。修复后，经验核要求源通过质量层，并用完整候选表排除邻近污染；首帧当前得到 20 个干净隔离模板源。修正后的对照输出为 `tmp/real-background-empirical-clean/real_background_injection.csv`，在 `hybrid + FWHM=2 px`、每档 8 源/1 次下，质量召回为 `0/0/0/0/0/0.25/0.625`（对应 `12/16/24/36/56/84/128 ADU`）。这不是说经验 PSF 一定更差，而是实证显示模板源选择、核截断、归一化和质量 SNR 会共同改变结果；当前以可解释的 Gaussian 为默认，经验核作为模型不确定性与局部 PSF 审计工具。2026-09-02 起 GUI 默认是 `hybrid + FWHM=2 px`，两套结果不能只按数量排名。

### 数据 2：星场稳定性与姿态变化

当前实测：全局平移配准末端约 `0.188 px`，15 帧中的最大累计位移约 `0.254 px`，对应观测跨度上的末端平均量级约 `0.0089 px/s`。辅助字段的端点变化为 roll 约 `−0.298°`、pitch 约 `+0.680°`、yaw 约 `−1.182°`；四元数范数约为 1。这里的科学解释只能是“辅助姿态字段的变化”和“像素平面配准稳定性”，不能把两者直接画等号，也不能在 WCS 缺失时换算角速度。

### 数据 3：运动目标轨迹和短期预测

当前连续长线轨迹覆盖第 9–15 帧，使用小平移时间中值近似差分后，以真实 `DATE-OBS` 分别对 X/Y 做常速度 OLS，得到 `vx=+28.017 px/s`、`vy=−25.419 px/s`、速度模长 `37.829 px/s`、图像坐标方向 `−42.216°`、位移约 `340.689 px`、拟合 RMS `2.213 px`。逐张单图审计显示第 9–15 帧分别都有 1 个独立长线候选，第 2–8 帧没有达到同一几何门槛；因此这条序列不是把密集点源全部标成运动，而是先有 7 个独立帧级线状证据，再做跨帧拟合。多帧线状检测先用时间中值参考压制固定星场，再对当前帧做残差连通域和 PCA 几何筛选；本数据的累计配准平移小于 `0.75 px`，因此采用分块原坐标近似，差分噪声按 `sqrt(2)·σ` 计。

本轮补上了论文所需的小样本不确定度。7 点模型自由度为 5，使用 Student-t `t95=2.571`；速度模长的 95% 区间为 `37.226–38.433 px/s`，方向为 `−42.216° ±0.901°`。以 5 个中位帧间隔，即 `+7.505 s` 为预测窗口，OLS 轨迹均值外推为 `(2407.89, 3663.47) px`，逐轴 95% 半宽为 `X±7.95 px / Y±6.85 px`。这里的区间没有包含配准系统误差、模型失配和未来单次观测噪声，因此主图把它标为 `OLS mean 95% CI`，而不是目标必然落入的概率区域。只有 2 点时程序不给小样本区间，单帧候选不输出速度。外推继续只称为 `forecast`，不能写成轨道预测。

第 1 帧的单帧长线不与第 9–15 帧合并。定量 sanity check 显示，若用两组中心跨 8 个帧间隔强行连接，隐含平均位移约为 `(53.6, +473.0) px/frame`；而第 9–15 帧实测约为 `(41.7, −37.9) px/frame`，Y 方向相反，且线形主轴也从约 `96.7°` 变为约 `137.8°`（无向线角）。因此当前证据只能支持“第 1 帧单帧候选”和“第 9–15 帧连续候选”两个分组，不能为了补齐 15 帧而制造一条跨越第 2–8 帧的轨迹。

### 数据 4：辅助遥测向量摘要

对 `j2000_x/y/z`、`wgs84_x/y/z` 及相应速度字段计算向量模长、XY 平面方位角和仰角，逐帧输出到 `frame_evidence.csv`。同时以第 1 帧位置为参考计算 `Δr`，让表格同时回答“当前位置量级”和“这段观测内移动了多少”。格式说明明确位置单位为 `m`，但速度行原文写成 `m`；因此报告保留 `*_raw` 字段，并额外给出“位置差分速度—辅助速度”的自洽检查。当前可将位置标为 `m`，将速度标为 `m/s?`：后者由原始位置和 `DATE-OBS` 的数值一致性高度支持，但仍需主办方确认 DOCX 是否漏写 `/s`。

### 数据 7：载体位置—速度—方向的连续性检查

这组指标不是把辅助字段直接包装成轨道结论，而是检查其内部是否具有连续、可解释的时间序列结构。当前真实 15 帧的结果为：

| 参考系 | 第 1 帧 `|r| / m` | 第 15 帧 `|r| / m` | 相对第 1 帧 `Δr / m` | `|v| / m/s?` 范围 | 速度方位角范围 |
| --- | ---: | ---: | ---: | ---: | ---: |
| J2000 | 6,881,848.0 | 6,881,884.5 | 159,926.4 | 7,610.48–7,610.55 | 66.16–68.83° |
| WGS84 | 6,881,848.0 | 6,881,884.4 | 161,608.2 | 7,690.44–7,690.67 | −21.26–−18.09° |

这组数字表现出两个可以用于答辩的现象：速度模长在 21 秒内较稳定，方向随帧缓慢变化；位置模长和相对位移也随时间连续。更重要的是，使用 `DATE-OBS` 对位置做差分后，J2000 中间帧相对误差中位数约 `0.00243%`、最大约 `0.00749%`；WGS84 分别约 `0.00263%`、`0.00752%`。这使“速度字段实际按 `m/s` 存储、DOCX 漏写 `/s`”成为强证据支持的解释，但不是主办方正式更正。当前 UI 的“辅助遥测”页把位置模长、相对第 1 帧位置变化、速度模长、速度方位角、仰角和自洽误差一起显示，便于把“原始字段—派生量—物理解释边界”分开。

后续可以在拿到单位定义后继续计算：

```text
位置差分速度 = (r[t] - r[t-1]) / Δt
速度残差     = v[t] - 位置差分速度
方向变化率   = unwrap(azimuth[t]) / Δt
```

若位置差分速度与辅助速度在单位统一后相符，可作为格式解码和数据一致性验证；本批数据已经给出很强的相符证据。仍应优先向主办方确认速度行的 `/s`，并检查字节序、字段顺序、参考系、时间戳是否为曝光中心以及速度字段是否采用其他定义，而不是直接把差异解释为异常机动。还要明确：这里的 `|v|` 是载体辅助状态向量的速度量级，不能与图像长线的 `37.84 px/s` 直接比较；两者属于不同坐标系和不同观测量。

### 数据 5：注册中值拼图

按累计平移把 15 帧缩小到统一预览尺寸后做中值叠加，输出 `registered_mosaic.png`。中值拼图有两个用途：

1. 固定星场应被增强，随机噪声和短时运动目标应被削弱；
2. 可作为姿态/配准质量的直观图证，同时和单帧、差分图并列比较。

它不是科学图像的最终标定产品，因为当前只使用平移配准、没有完整 WCS、PSF 变化或辐射定标。答辩时应同时展示配准前后对比和残差图，避免把拼图的视觉变清晰误认为算法已经得到物理真值。

### 数据 6：注册中值差分和残差显著性

在同一组平移变换下，将每帧缩放到统一输出尺寸并配准到第 1 帧坐标，构造注册中值参考：

```text
reference = median(registered_frame_1, ..., registered_frame_15)
residual_t = registered_frame_t - reference
```

当前导出器同时保留两种数据：

1. `difference_evidence.csv` 使用原始 FITS 数值的下采样注册栈，残差统计单位为 ADU，记录残差中位数、稳健 RMS、绝对残差 P99、正/负峰相对背景 RMS 的显著性和超过 `5σ` 的像素数；
2. `registered_difference.png` 用橙色表示正残差、蓝色表示负残差，按整幅图的高分位残差做显示裁剪，只作为定位和质量检查图，不改变 CSV 中的原始统计。

本轮真实 15 帧结果的注册残差稳健 RMS 中位数约为 `1.30 ADU`。第 1 帧的正残差峰约为背景 RMS 的 `761σ`，主要由只在单帧出现的强长线候选贡献；这正说明差分图可以作为线状候选的独立证据，但不能把残差显著性直接等同于目标真值。当前差分仍是“平移配准 + 中值参考”基线，没有完成空间变 PSF 匹配、光度归一化或 proper image subtraction，因此下一轮还要用空白区、负样本和注入目标测量误报率。

差分图应和原图、注册拼图、线状轨迹表一起展示。若静态星在差分图中成片出现正负成对残差，应优先检查配准模型和 PSF 变化，而不是把这些残差全部提交为运动目标。proper image subtraction 的统计前提可参考 [Zackay、Ofek 与 Gal-Yam 2016](https://arxiv.org/abs/1601.02655)，但不能声称当前轻量实现已经满足其最优条件。

### 数据 8：创新指标集中展示页

为了避免答辩时在多个窗口之间拼接结论，Tkinter 的“15 帧证据”窗口新增“创新摘要”页。该页不重新检测，也不产生新的科学量，而是把已经写入 `SequenceResult` 的证据按语义分组展示：

| 分组 | UI 展示 | 解释边界 |
| --- | --- | --- |
| 时序关系 | 帧数、总时长、中位帧间隔、曝光 | 由真实 `DATE-OBS` 和 `EXPOSURE` 得到 |
| 固定星场 | 最大累计平移、稳定点源轨迹数 | 当前是全局平移基线，不是完整仿射/WCS |
| 运动证据 | 线状候选的帧范围、位移、X/Y 速度、速度 95% 区间、方向区间、拟合 RMS；另列逐帧点源关联的 `fast_point_motion` 轨迹 | 两类证据分开计数；`moving` 是跨帧算法候选，区间未覆盖系统误差，仍需真值或注入验证 |
| 短期外推 | 末帧后 `+5` 个中位帧间隔的预测 X/Y 与逐轴 95% 半宽 | OLS 轨迹均值区间，不是未来单次观测区间或轨道预测 |
| 辅助遥测 | J2000/WGS84 速度模长范围、相对首帧位置变化 | 是载体状态字段，不与图像 `px/s` 互换 |
| WCS 校准 | 匹配内点/总匹配、局部像元角尺度、旋转、parity、内点 RMS、各向异性 | 由先验 WCS 引导的局部仿射反校准，不是全天空盲解算 |
| 角速度 | 线状跨帧候选的切平面 `arcsec/s` | 只有完成局部 WCS 校准才显示；是视运动率，不是轨道速度 |
| 结论边界 | 未校准时 `WCS / 物理速度：待标定` | 没有像元角尺度时不显示角秒或真实天体速度 |

当前真实序列中，这个页签应能直接读出：15 帧、总时长 `21.014 s`、中位帧间隔 `1.501 s`、最大累计配准约 `0.254 px`；第 1 帧为独立单帧长线候选，第 9–15 帧为连续线状候选，图像平面拟合速度 `37.829 px/s`（95%：`37.226–38.433`）、方向 `−42.216° ±0.901°`、位移约 `340.689 px`，以 `+7.505 s` 为窗口的 OLS 轨迹均值外推坐标约为 `(2407.89, 3663.47)`，逐轴半宽 `X±7.95 / Y±6.85 px`。页面中的这些数值均保留“候选”“图像平面”和“区间未覆盖系统误差”的语义；没有局部 WCS 校准时继续显示“待标定”，避免把可视化结果包装成轨道解算或物理真值。

## 11. 当前生成结果

命令：

```powershell
python -m rst19.sequence_cli doc\00-项目资料\原始数据 `
  --threshold-sigma 4 --min-distance 4 --psf-fwhm 3 --min-flux-snr 5 `
  --min-presence 12 --motion-min-displacement-px 2 `
  --max-motion-fit-rms-px 0.75 --json-out tmp\sequence_metadata.json

python -m rst19.innovation_cli tmp\sequence_metadata.json --out-dir tmp\innovation
```

当前输出目录包含：

- `innovation_report.json`：关系、质量、配准、姿态辅助量、遥测向量和轨迹预测；
- `frame_evidence.csv`：15 行逐帧数据；
- `motion_evidence.csv`：逐条线状候选/轨迹，包含 X/Y 速度、标准误、速度/方向 95% 区间和外推逐轴区间；
- `motion_points_evidence.csv`、`motion_cutouts/`、`motion_cutouts.csv`、`motion_cutout_contact_sheet.png`：逐帧线状证据、原图裁剪、裁剪坐标和接触表；
- `point_motion_evidence.csv`、`point_motion_points_evidence.csv`、`point_motion_trajectory.png`：逐帧点源关联运动证据；其中 `fast_point_motion` 是宽筛候选回到原始 ADU/PSF 后的算法层级，不与线状差分候选合并，也不自动表示物理目标真值；
- `quality_counts.png`、`registration_shift.png`、`telemetry_velocity.png`；
- `motion_trajectory.png`、`registered_mosaic.png`；前者只把跨帧组作为轨迹绘制，显示全部观测质心、OLS 拟合线、外推段和逐轴置信椭圆，单帧长线留在独立裁剪/审计图中。
- `difference_evidence.csv`、`registered_difference.png`：注册中值差分及正/负残差质量统计。
- `telemetry_prediction.csv`：J2000/WGS84 末帧状态的常速度位置外推；这是 `m/s?` 假设下的短期基线，不是轨道传播。
- `telemetry_position.png`：J2000/WGS84 相对首帧 XY 投影和末帧常速度外推图；不与图像平面长线混画。

这些文件是创新分析的“结果底稿”，不是自动生成的比赛结论。真正冻结提交版本前，还需要星表匹配留出验证、合成目标注入-回收率、人工运动目标标注和仿射/WCS 对照。
