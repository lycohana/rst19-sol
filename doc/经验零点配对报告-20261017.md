## 3. 四个科学问题

### Q1 饱和占比 / 剔除后剩余（实测）
P1：124 对中 15 对（12.1%）命中任一饱和判据（14 个 DN==0 削顶 + 1 个回绕 + 1 个峰值超限），剔除后 109 对用于拟合。
P2：38/247 = 15.4%，剔除后 209 对。

### Q2 剔除饱和后 ZP 散度与趋势（实测）
- 单参数零点（g_ref = m_inst + ZP）：ZP = **19.057 ± 0.013**，稳健核心 n=35，核心内 RMS 0.321 mag。
- 但全部 109 个配对样本的留出散度是 **1.525 mag**（不是 0.32）——分布是“紧核 + 宽翼”，3σ 裁剪只保留 35 个。结论：这批数据不能被单个 ZP 以 0.3 mag 精度描述。
- 随 G 的系统趋势（全部未饱和配对，中位零点）：
  | G 区间 | n | 中位零点 |
  |---|---|---|
  | 8–11 | 18 | 17.61 |
  | 11–12 | 31 | 18.99 |
  | 12–13 | 60 | 19.67 |
  越亮零点越小（亮星通量被压低），跨度 2.06 mag。
- 随 BP−RP：0–0.5 → 18.37 (n=9)；0.5–1 → 19.48 (n=64)；1–1.5 → 19.38 (n=33)。蓝色段的偏离由亮星主导（见上一条），线性颜色项本身不显著（见 Q3）。
- 随视场位置：
  - 半径分箱中位零点 19.39(7) / 19.21(22) / 18.92(20) / 19.52(31) / 19.38(21) / 19.90(7)，峰峰 0.98 mag，**无单调趋势**。
  - 8×8 空间块的块间中位偏移散布 1.075 mag，但每块中位只有 2 颗星、块内散度中位 1.514 mag ⇒ 纯抽样噪声预期约 1.25×1.514/√2 ≈ 1.34 mag。**该块间散布与抽样噪声一致，不构成真实空间结构证据**。

### Q3 加线性颜色项是否显著改善留出散度（实测）
在同一份“两模型共同内点”子集（n=35）上做 5 折交叉验证：

| 模型 | σ_out（留出，同子集） |
|---|---|
| g_ref = m_inst + ZP | 0.299 mag |
| g_ref = m_inst + ZP + C·(BP−RP) | 0.345 mag |

C = **−0.046 ± 0.029**（1.6σ，不显著），比值 1.155 ⇒ **颜色项没有改善，反而略差**。
P2 上 C = +0.279 ± 0.033，比值 0.935（略好）；r=1.5 时 C = +0.066 ± 0.022（比值 1.06）；r=2.0 时 C = +0.020 ± 0.017（比值 1.002）。
⇒ 颜色项符号随配置翻转、幅度在 0–0.28 之间摆动，**不成立**。亮度项（Q2）才是主导系统项。

### Q4 位置残差与是否需要 SIP（实测）
- 纯仿射（3 项/轴）在最终配对上 RMS = **1.381 px**；同配对加二次项（6 项/轴，xi², xi·eta, eta²）= **0.754 px**，比值 0.546。
- P2：0.959 → 0.763；r=1.5：1.500 → 0.960；r=2.0：1.631 → 1.294。
⇒ **需要带畸变项（SIP 等价）的模型**，可把几何 RMS 砍掉约 20–45%。
- 但 1.2 px 门限下的配对量几乎不受影响（纯仿射重配 107 对 vs 二次模型 124 对）：配对产量受 ~0.7 px 随机散布的尾部限制，而不是受畸变限制。
- 半径分箱的残差中位 0.79/0.89/0.68/0.70/0.82/0.61 px，无随半径增长的趋势 ⇒ 残余以随机项为主。

## 5. 顺带诊断：rst19-photometric-auto 栈溢出（只诊断，未修）

最小复现（内容无关，2 行星表同样崩）：

```powershell
backend\target\release\rst19-photometric-auto.exe tmp\frame1_only\20260330163205413_9901.fits --catalog tmp\gaia\frame1_gaia_g13.csv --out tmp\rust-pairs\diag\photo-auto.json
# exit = -1073741571 (0xC00000FD / STATUS_STACK_OVERFLOW)
```

崩溃前最后输出：stderr 仅有 `thread 'main' (<pid>) has overflowed its stack`，没有任何进度行。
（教训：默认栈下崩溃时进度行会丢失，不能据此判断崩溃阶段。）

实测边界（这些是本次测出来的，不是推断）：
1. 同一个可执行文件，仅以 `RUSTFLAGS='-C link-arg=/STACK:8388608'` 重新链接（不改任何源码），相同命令 **跑完全程**（exit 3，输出到 100%）。64 GB 栈更强，同样跑完。⇒ 纯栈耗尽，不是数据损坏、不是内存越界。
2. 给荒谬的 `--pixel-scale 0.5` 与 `--pixel-scale 60` 时仍然崩 ⇒ **不在板解阶段**。
3. 同一 FITS 用 `fits::read_fits(path, false)` 在我的新 bin 里正常读入 ⇒ **不在 FITS 读取**。
4. 结合 1 的进度输出（5.0% 正在检测星点 → 67.0% 检测完成），崩溃区间落在 `pipeline::analyze_frame`（photometric_workflow.rs:377）的单帧检测栈内。

推断（未能定位到函数，见下）：最可能是检测栈内的深递归，需要 ~1–8 MB 栈。
用花括号精确匹配对可达模块做的自调用扫描，命中三处真递归：
- `backend/src/spatial.rs:21` `build`、`:58 visit`、`:92 visit`（kd-tree，中位切分 ⇒ 深度 ~log2(N) ≈ 15）
- `backend/src/statistics.rs:4` `pairwise_sum`、`backend/src/statistics32.rs:16` `pairwise_block`（配对求和，深度 ~24）
这三处的深度都解释不了 1–8 MB，所以我不敢把话说死：**精确递归位置未定位**。
原因：release profile 带 `strip = true`（无符号），而本机 MSVC 工具链没有可用调试器（`rust-lldb` 直接报 “not applicable to the 'stable-x86_64-pc-windows-msvc' toolchain”，无 cdb/gdb）。
要定位，需要一次带符号的 debug 构建 + 可用调试器或 `/STACK` 二分；本次已把二分做到 1 MB 崩 / 8 MB 通。

旁路（未采用，仅记录）：`[profile.release]` 加 `rustflags = ["-C", "link-arg=/STACK:8388608"]`，或 `build.rs` 下发同一 link arg。

## 6. 与 Lead 已知事实的对照

一致：
- 生产配置 candidate=66469 / quality=27552 —— 本次读入同样 66469 行、用 27552 行（manifest counts 一致）。

- “亮星通量被压低、G−m_inst 随亮度单调” —— 完全确认：17.61 / 18.99 / 19.67。
- “双向最近邻 + 1.2 px 得 88 对、位置残差中位 0.83 px” —— 我同门限得 124 对（仅质检通过）/247 对（含全部），中位 0.731/0.700 px，量级一致。
- 网格噪声估计、Gaia 可达、WCS 参数 —— 与本 bin 的 8.1606″/px、129.85°、parity +1、中心 (2048,2048) 复用一致（拟合出的线性部分复现该尺度与旋转到 1e-3 相对精度）。

差异 / 冲突（需要 Lead 知道）：
1. **验收“配对 ≥ 200”在默认配置下不成立**：1.2 px + 仅质检通过只有 124 对。要 ≥200 必须放宽到 --include-rejected-sources（247 对）或 r≥1.5（174）/r=2.0（276，但残差中位 1.246 px 已 >1.0）。我把 P2 作为“满足验收”的配置报出，没有偷偷改默认门限。
2. **ZP 对配对配置极不稳定**：18.12（P2）/19.06（P1）/19.90（r=1.5）/19.63（r=2.0），跨度 1.78 mag。每个数都是各自样本的“紧核”，差异来自样本构成而非拟合误差。任何“首个可信经验零点”都必须带上这个系统项。
3. 颜色项与 Lead 提到“亮星被压低”不同源：数据里没有可测的颜色效应（C 在 0 附近且符号翻转），系统项在亮度方向。
4. Lead 的 G=11–12 分箱零点 18.43 是我的 18.99（差 0.56），首末两箱几乎重合（17.60/17.61、19.66/19.67）。中间箱差异推断来自该区间样本数与饱和/混合程度的差别。
