## 2. 星表到底解决什么问题

星表不是一个“把所有星点直接查出来”的图片数据库。它主要解决四个问题：

### 2.1 从像素坐标获得天球坐标

检测器先只能得到像素坐标 `(x, y)`。星表提供参考源的赤经、赤纬和其他属性；二者通过 WCS 或盲解算建立映射，才能把图像中的源标注成 `RA/Dec`。

Astropy 的 WCS 文档将 WCS 定义为不同坐标系之间的几何变换，典型用途就是把图像像素映射到天球坐标，并支持 pixel-to-world 和 world-to-pixel 两个方向。当前文件的主 FITS 头并没有标准 `CRPIX/CRVAL/CTYPE/CD` 或 SIP 畸变卡片；`AZIMUTH/ELEVATIO` 只提供部分指向信息，格式说明中的逐帧 `ra/dec`、四元数等字段位于首行保留的 `208` 字节辅助区，而不是标准 WCS 头。因此这些辅助字段可以作为光轴/姿态先验，但不能直接当作完整 WCS。

本地首帧主头实际只有 `24` 个已解析卡片；标准 WCS 检查项 `CRPIX1/2`、`CRVAL1/2`、`CTYPE1/2`、`CD1_1/CD1_2/CD2_1/CD2_2`、`CDELT1/2`、`CROTA2` 和 SIP 阶数卡片均不存在。这个结果把“当前还不能直接给检测框标 RA/Dec”从资料推测变成了文件级事实：辅助姿态审计可以证明光轴先验自洽，但不能替代星表匹配所需的像元尺度、图像轴方向、旋转和畸变标定。

### 2.1 辅助姿态能提供什么先验

对格式说明和 15 个本地 FITS 做了逐帧交叉审计。格式说明给出相机指向本体 `-Y` 轴；用矢量在前、标量在后的四元数构造旋转矩阵，把 `-Y` 轴投影到 J2000 后得到的光轴 RA/Dec 与辅助字段的最大角残差约为 `1.1×10^-10 arcsec`，四元数范数范围为 `0.9999999999999998--1.0000000000000002`，`p_az/p_el` 与头部方位/俯仰为 `15/15` 一致。这是本项目关于数据格式的一个新验证：辅助 `ra/dec` 不是孤立的手工字段，而能被同一文件中的姿态和相机轴约定复现。

它能支持“有先验的星表检索”：按逐帧光轴缩小搜索区域、检查姿态变化、为后续的尺度/旋转扫描提供中心约束。15 帧辅助 RA/Dec 自身变化约 `8.60/7.79 arcsec`（RA/Dec 坐标范围），而姿态角 `roll/pitch/yaw` 的范围分别约 `0.298/0.681/1.183 deg`，说明不能把一个固定中心和一个固定姿态无条件套到整段序列。

它不能单独解决“星表匹配”：格式说明没有给出图像 x/y 轴对应的相机横纵轴、像元角尺度、焦面旋转、畸变模型和曝光期间姿态积分。因此当前只能称为光轴/姿态先验，不能把辅助 RA/Dec 直接写到每个像素，也不能以目录预期源数替代图像检测数。可复现审计产物为 `tmp/auxiliary-attitude-audit/auxiliary_boresight_audit.csv/json`，命令为 `rst19-aux-audit doc/00-项目资料/原始数据`。

### 2.2 给检测到的源分配星表身份

如果某个图像源与星表源在 WCS 变换后的预测位置相符，就可以输出：

```text
catalog_source_id
ra, dec
catalog_magnitude
pixel_x, pixel_y
match_residual
match_probability
```

这能把“这里有一个亮点”升级为“这个亮点与某个星表源相符”。但匹配必须有残差、质量标记和唯一性检查，不能只因 RA/Dec 看起来合理就接受。

星表文件本身也必须经过输入安全门：`source_id` 去除首尾空白后必须唯一，位置、星等和自行等数值必须有限；显式 `0` 不能被当成缺省值。每次匹配还应保存星表文件的 SHA-256、行数、列顺序、版本/查询条件和 WCS 配置，保证“换了一版星表”不会被误认为同一次实验。当前实现只把这些检查作为匹配前的可复现性门槛，不会因此把候选升级为物理恒星。

### 2.3 约束星点计数

星表可以作为预期星场，帮助区分固定恒星、噪声峰、热像素和运动目标。但最终星点数应至少分成三类：

```text
N_detected  = 图像中通过检测和质量筛选的源数
N_matched   = 与星表成功匹配的检测源数
N_unmatched = 已检测但未匹配的候选源数
```

比赛若要求“从图片中找出所有星点”，优先报告 `N_detected` 的定义和结果，`N_matched` 作为身份确认和质量核验。直接把 `N_matched` 当成全部恒星数，会漏掉星表不完整、星等太暗、波段不匹配、变量源或匹配失败的真实星点。

### 2.4 给星等识别提供参考

星表中的 `G`、`V` 或其他星等可以作为参考属性，但它们不是当前相机像素值的替代品。要从图像通量得到可比较的物理星等，仍需要孔径/PSF 测光、背景扣除、曝光时间归一化和零点/颜色项标定。

星表最适合提供：

- 参考星的已知星等；
- 多个参考源的颜色和质量信息；
- 图像检测源与目录源的身份对应；
- 对“最暗可信检测源”的外部一致性检查。

它不能自动解决相机滤光片响应、增益、饱和、非线性和检测极限问题。

### 2.5 对公开 StarImage_SimuIden 路线的拆解

| 公开路线 | 本项目吸收 | 当前边界和修正 |
| --- | --- | --- |
| 灰度阈值、连通域、质心 | Gaussian/DoG 多提议器宽筛，再回到原始 FITS 做局部背景、孔径测光、形态和 PSF 支持 | 固定全图灰度阈值无法表达局部 RMS；当前 `84,594` 个候选不是 `84,594` 颗星，必须保留候选/质量两层 |
| 角距/图结构匹配 | 用星对、三角形、邻接图缩小模式搜索；匹配后保存残差、唯一性和次优解间隔 | 角距只约束几何，不证明亮点是恒星；没有完整 WCS、FOV 和星表版本前，不能把匹配数写成星数 |
| 亮星估计 PSF、增强暗目标 | 用隔离质量源构造经验 PSF，并做留一、空间模板和单/双 PSF 对照；暗源回到原始像素测量 | 当前只有 `20` 个全局模板，pair 所在局部没有足够模板；经验核相关度低只能说明失配或混叠风险，不能单独判假 |

因此两条路线的关系不是“选一个替代另一个”，而是职责分层：外部路线提示我们需要星表匹配、经验 PSF 和时序跟踪；当前数据证据又要求在这些步骤之前加上局部噪声建模、值域/固定结构审计、候选与质量分层，以及拥挤源的一对一去混叠。尤其不能把“灰度阈值找到的连通域数”“角距匹配成功数”或“增强后可见的亮点数”直接当作物理恒星总数。

#### 2.5.1 旧项目与当前数据的血缘及“无 Gaia 匹配”说法

本轮对旧项目 `new/fits/` 与本仓库 `doc/00-项目资料/原始数据/` 的 15 个 FITS 做 SHA-256 文件级对照，结果为 `15/15` 同名文件完全一致。因此旧项目的检测结果可以作为同一数据集的历史基线，但不能把它的参数或输出自动升级为真值。更重要的是，旧项目随附的可读 Python 实现实际调用的是 `DAOStarFinder`、全图 MAD 背景和代理星等；其“11 种像素尺度下无 <2\" Gaia 紧匹配峰”的说法写在注释/README 中，随附依赖和源码中没有可复现的 Gaia 查询或 plate-solving 流程。公开仓库页面也主要提供 README 和 MATLAB App 安装包，而不是可逐行审计的完整实现（[公开仓库](https://github.com/Aoyeww/StarImage_SimuIden)）。

所以当前论文不把“无 Gaia 可匹配背景恒星场”写成已经完成的排除性事实，而写成：**旧项目提供了一个尚未独立复现的负向线索；当前数据仍缺少获授权星表、完整 WCS、像元尺度和匹配残差，不能据此断言图中没有物理恒星。** 这一区分很关键：没有找到匹配，可能来自仿真星场、姿态/坐标约定错误、FOV 或像元尺度错误、波段/星等极限不一致，也可能来自星表缺失；只有在 WCS 初值、搜索范围、历元传播、唯一匹配和留出残差都记录后，负匹配才具有可解释性。

## 3. 星表选择

### 3.1 Gaia DR3：属性完整，适合标注和测光参考

Gaia DR3 提供大规模天体测量和宽带测光数据，包括位置、视差、自行以及 G、BP、RP 等测光字段。它适合用于：

- 星表身份标注；
- 参考星位置和自行传播；
- 参考星星等和颜色项；
- 结果质量分析和后续创新指标。

不建议把全量 Gaia DR3 直接作为比赛程序的内存查找表。应该先根据视场中心、视场半径、星等范围和质量条件得到一个任务子集，再保存查询参数、数据发布日期/版本、列名和本地文件校验值。

需要特别注意：Gaia 的星等属于 Gaia 光度系统，本相机的响应曲线未提供时，`phot_g_mean_mag` 不能直接写成 `Mv`。如果截图中的 `Mv` 指 V 波段星等，需要有 V 波段目录或颜色转换模型并给出残差。

### 3.2 Tycho-2 / 任务导星表：适合解算初始 WCS

星表匹配的第一阶段不一定需要最暗星。盲解算更需要一组亮、孤立、形状稳定、在图像中高 SNR 的参考星。可以从 Tycho-2、Hipparcos 或任务方提供的导星表构造“解算星表”，再用 Gaia 子集做完整属性回填。

Astrometry.net 的公开索引资料展示了这种分层思路：较宽视场可使用基于 Tycho-2 的 4100 系列索引，较窄视场可使用由 Tycho-2 与 Gaia-DR2 构建的 5200 系列索引；索引按角尺度划分，不需要每次把全量星表拿来组合搜索。具体索引系列和尺度必须根据当前相机真实视场测量后选择。

### 3.3 任务星表：最适合最终比赛方案

如果主办方能提供或允许构建任务星表，建议保留一份与本设备匹配的轻量表，至少包含：

| 字段 | 用途 |
| --- | --- |
| `source_id` | 稳定身份键 |
| `ra`, `dec` | 参考历元的天球位置 |
| `ref_epoch` | 位置和自行的参考历元 |
| `pmra`, `pmdec` | 位置传播和长时间跨度匹配 |
| `mag_ref` | 解算排序或测光标定参考 |
| `color` | 波段转换和颜色项 |
| `quality_flags` | 排除变量、重复、异常或低质量源 |
| `isolated_radius` | 避免拥挤/重叠参考源 |
| `index_cell` | 空间索引，减少查询范围 |

任务星表应记录生成脚本和筛选条件，避免“星表文件换了一版但程序结果仍被当作可比”的问题。

## 4. 从图像到星表的完整流程

### 阶段 A：图像源检测

先按 [星点识别方法](./星点识别方法.md) 做背景估计、局部 RMS、点源检测和质量筛选，得到前 K 个高置信源：

```text
detected = {x, y, peak, flux, snr, fwhm, shape, mask_flags}
```

盲解算优先使用亮度高、未饱和、孤立且形状稳定的源；不要把所有噪声峰、最暗候选和运动目标一开始都放入模式组合，否则组合数和误匹配概率会迅速上升。K 的具体范围需要在实际数据上扫描，例如比较 30、50、100、200 个源，而不是固定照搬外部工具参数。

### 阶段 B：生成图像模式

对检测源构造可与星表比较的几何特征：

1. **星对**：保存两点间距离、方向和亮度差，速度快但容易出现重复候选。
2. **三角形**：保存排序后的三边比例或角度，具有平移、旋转和尺度不变性，适合作为轻量起点。
3. **四边形/四星模式**：几何唯一性更强，适合盲解算，但组合和索引成本更高。
4. **邻接图**：以星点为节点、邻近关系/角距为边，适合在已有大致视场中心或连续帧先验时缩小搜索。

三角形的比例特征在小视场、近似相似变换下有效；出现明显镜头畸变、宽视场或检测误差时，必须加入容差、分区建模或在初解后做 WCS/SIP 精化。

### 阶段 C：从星表生成模式索引

不要运行时对星表中所有源做全组合。离线构建索引：

```text
星表筛选
  → 按空间网格/HEALPix 分区
  → 按亮度和邻域选择导星
  → 生成星对/三角形/四边形
  → 量化几何特征
  → 哈希或 KD-tree 索引
```

Astrometry.net 的论文和文档给出了成熟的四星/五角星模式思路：先做稳健源检测，再对四星或五星星群的几何模式进行哈希，与预建索引比较，产生 WCS 假设，最后用更多源验证而不是接受第一次命中。这个流程适合拿来设计本项目基线。

### 阶段 D：WCS 初解

匹配到一个候选模式后，先拟合一个小视场的切平面模型。可用 gnomonic/TAN 投影表示：

```text
(ra, dec) → (xi, eta) → (x, y)
```

先拟合平移、旋转和尺度，再视残差增加仿射项或 SIP 畸变项。需要注意像素坐标约定：

- 图像数组通常是 `[row, column] = [y, x]`；
- WCS 的 pixel API 通常按 `(x, y)`；
- 0-based/1-based `origin` 不一致会产生系统性偏移；
- 整数像素中心、图像翻转和 RA 方向也必须单独验证。

### 阶段 E：全场验证

对得到的 WCS，把星表源投影回图像坐标，进行全场匹配：

```text
catalog sky position
  → WCS world_to_pixel
  → predicted (x, y)
  → nearest-neighbor / gated assignment
  → robust residual fit
```

建议用以下指标接受或拒绝一个解：

| 指标 | 含义 |
| --- | --- |
| `n_inliers` | 通过残差门限的匹配数量 |
| `inlier_ratio` | 候选源中真正支持该解的比例 |
| `rms_pixel` | 匹配残差 RMS |
| `max_residual` | 最大残差，检查离群点 |
| `scale` | 图像角尺度是否在相机可能范围内 |
| `orientation` | 旋转方向是否符合设备坐标约定 |
| `second_best_gap` | 最优解与次优解的分数差 |
| `spatial_residual_trend` | 残差是否随位置呈系统性变化 |

接受条件不能只使用“匹配数量最多”。一个错误的宽松 WCS 也可能碰巧匹配很多密集星点；应同时看残差分布、唯一性、尺度合理性和保留星点的交叉验证。

## 5. 已知 `ra/dec` 时如何降低难度

当前辅助数据给出了卫星光轴指向的 `ra/dec`，这比完全失去姿态的盲解算多一个先验。但它还不能直接给出像素到天空的完整映射，因为仍缺相机内参、像元尺度、旋转方向和畸变。

可以采用“有先验的局部匹配”：

1. 从辅助数据读取光轴 `ra/dec`，并记录观测时间。
2. 先给相机视场设置一个宽范围，例如由小到大枚举可能的角尺度；不要未经测量固定一个 FOV。
3. 在光轴周围按候选 FOV 查询星表，只取亮度足够高且质量合格的导星。
4. 计算检测源的星对/三角形距离，与候选星表模式比较。
5. 用最优模式拟合 WCS，再把搜索范围扩大到完整视场，做全场匹配。

这种方法比全天空盲搜快、误匹配少，且可以利用连续 15 帧中上一帧的 WCS 作为下一帧先验。但如果头部 `ra/dec` 的定义不是光轴中心，或坐标系/时间有误，必须保留盲解算回退路径。

## 6. 星表与星点计数的正确结合

### 6.1 不要只数匹配成功的源

推荐在结果文件中同时输出：

```text
star_count_detected
star_count_matched
star_count_unmatched
star_count_catalog_predicted
completeness_estimate
```

其中：

- `star_count_detected` 是图像检测定义下的星点数；
- `star_count_matched` 是获得目录身份的子集；
- `star_count_unmatched` 需要进一步判定是噪声、运动目标、星表缺失还是匹配失败；
- `star_count_catalog_predicted` 只是理论上位于视场中的目录源数，不能直接当成图像实际看到的星数；
- `completeness_estimate` 应来自注入实验或明确的目录选择函数。

### 6.2 用星表反查未匹配候选

对未匹配候选逐一检查：

1. WCS 残差是否在整幅图边缘明显变大；
2. 候选是否在星表星等极限之外；
3. 是否存在 Gaia 重复源、拥挤源、变量源或 catalog quality flag；
4. 是否靠近饱和星、坏点、首行辅助区域或差分残差；
5. 是否在多帧中有相对星场运动。

这一步正好把星表路线连接到星图分析：固定星匹配成功的源可作为静态星场，长期未匹配但沿一致轨迹运动的源才是运动目标候选。

### 6.3 星表不能替代双峰去混叠

星表匹配必须建立在“一个检测源至多占用一个目录源”的一对一约束上。当前截图 pair 的局部间距控制显示，两个候选固定峰距 `4.123 px`，但注册后局部间距中位数只有 `2.000 px`，`13/15` 帧收缩、`11/15` 帧同时向对方移动；在这种情况下，即使两个位置都能被最近邻星表查询命中，也不能直接把两个匹配行相加为两颗恒星。应同时检查匹配残差、唯一性、双 PSF 模型证据、源间孔径协方差和跨帧位置。

因此星表在这里承担的是身份确认和反查职责：若两个候选分别对应两个稳定、唯一、低残差的目录源，并且在空间变 PSF/联合去混叠后仍保留，才可升级为两个独立源；若两个候选只共享一个目录源、残差随局部结构方向变化，或一个候选始终落在异常值域邻域，则应保留候选但标记为 `ambiguous_blend`，不把目录预测数当作图像星数。

经验 PSF 形状应排在星表身份确认之前。当前 pair 的全局经验核来自首帧 `20` 个隔离质量源；在 15 帧注册预测位置上，`82931/82934` 的相关度中位数为 `0.560/0.403`，相对残差为 `0.828/0.915`，而 pair 所在的 `4×4` detector 单元没有足够的局部隔离模板。这个结果不等于“相关度低就不是星”，但说明最近邻查询即使分别找到目录行，也无法消除图像层的混叠与 PSF 失配。星表流程应把经验/分区 PSF、唯一性、留出残差和跨帧位置作为联合前置条件；详细审计见 [检测器实验记录 8.63](./检测器实验记录.md) 和 `tmp/empirical-pair-psf-audit-code-pattern-current-v1/`。

跨帧强制测光又给出一个星表匹配前的排他性检查：该 pair 的固定/局部 `flux_snr` 共变为 `0.980/0.990`，按其它源的逐帧中位数归一后仍为 `0.979/0.990`，但按 pair 总响应分层后高响应组内相关降至 `0.265/0.151`。同时两个 `r=4 px` 孔径在 `15/15` 帧共享重复高位码，`9/15` 帧共享范围异常负值。因此，即使目录最近邻能为两个像素位置各返回一行，也必须先检查一对一匹配、共同像素/值域污染、联合 PSF 残差和留出稳定性；两个目录命中不能抵消“两个测量共享同一局部结构”的事实。该共变值是探索性控制量，不是星表身份概率；复现产物为 `tmp/pair-flux-covariance-audit-code-pattern-current-v1/`。

经验 PSF 的坐标锚点控制把这一要求具体化：质心锚点的固定 K=2 在 raw 下虽有 `11/15` 帧达到局部证据线，但同窗最佳单源位置控制为 `0/15`；峰值锚点固定与控制均为 `0/15`。因此星表匹配不能用“两个候选各自最近邻命中”来替代图像层模型比较；应把坐标锚点、局部 PSF、源间协方差和一对一留出残差一起作为身份升级条件。相关审计见 [检测器实验记录 8.65](./检测器实验记录.md) 和 `tmp/empirical-pair-fit-code-pattern-current-centroid-v2/`。

## 7. 星表与最暗星/星等的正确结合

当前代码已经把星表应当接入的位置固定下来：单帧检测先输出 `quality_sources`，星表匹配只接收这些通过局部测光、形状和有效像素检查的源；序列分析再使用质量源估计静态星场和帧间平移。这样可以避免把低 SNR 候选、饱和/边缘伪迹直接用于 WCS 模式组合，也避免把星表匹配成功数误写成图像检测总数。

现有命令行入口支持 `--catalog`、光轴 `RA/Dec`、像元角尺度、旋转、奇偶性和匹配半径；主界面的“星表核验”窗口也支持同一组先验参数，但这些参数必须由相机标定或主办方资料提供。匹配器默认在半径门控生成的稀疏候选连通分量内使用全局最大基数、最小总残差的一对一分配，并保留 `greedy` 作为旧实现对照；如果多个分配的总残差接近，仍应将其标记为歧义，而不是把算法选中的一行包装成物理身份。当前 FITS 的辅助 `ra/dec` 只作为光轴先验，尚未被当作完整 WCS；在没有验证 `CRPIX/CRVAL/CD` 或等价模型前，界面只显示检测/预测像素坐标、匹配残差和目录属性，不显示伪造的天球坐标。

### 7.2 从匹配结果反校准局部 WCS

当前实现增加了一个明确的两阶段流程：

```text
人工/任务先验 WCS
  → 半径约束的一对一匹配
  → 至少 6 个有效且非共线匹配点
  → 切平面 (ξ, η) → 像素 (x, y) 的仿射拟合
  → MAD 离群剔除
  → 留下尺度、旋转、parity、原点和残差证据
```

拟合模型写成：

```text
[x]   [a11 a12 bx] [ξ_arcsec]
[y] = [a21 a22 by] [η_arcsec]
                      [1]
```

其中 `ξ/η` 是以当前光轴先验为切点的东/北切平面角坐标，`a` 矩阵的单位是 `px/arcsec`。使用完整 `2×2` 矩阵有两个好处：一是可以从逆矩阵把图像速度分量换算为东/北方向的 `arcsec/s`；二是可以报告各向异性，避免把有剪切或非正交的拟合结果伪装成完美圆对称 WCS。程序另外给出一个不含剪切的等效 TAN 近似，供现有可视化接口复投影，但完整仿射矩阵和残差才是审计依据。

拟合有以下安全门槛：

- 匹配少于 6 个、切平面上近似共线或几何条件数过大时直接拒绝；
- 用确定性的 MAD 残差规则迭代剔除离群点，保留匹配总数、内点数、内点 RMS、全体 RMS 和最大残差；
- 反校准不会扩大原有检测结果，也不会把 `N_matched` 改写为恒星总数；
- 反校准依赖先验 WCS 提供初始匹配，因此不等同于 astrometry.net 一类全天空盲解算；
- `arcsec/s` 只代表图像目标在局部天空切平面中的视运动率，不能直接称为卫星或目标的轨道速度。

拟合结果可以从窗口导出为 JSON，包含参考 WCS、输入 FITS/星表路径、完整仿射矩阵、内点源 ID 以及校准统计。程序还给出对每个内点的 leave-one-out（留一）残差，用来识别“某一颗星过度支撑拟合”或几何杠杆点。留一残差仍然来自同一帧、同一星表，不是独立帧验证；正式提交前应再用未参与拟合的星或另一帧做真正的留出验证。

GUI 的“星表核验”窗口在匹配成功后提供“根据匹配拟合 WCS”按钮。拟合成功后会显示 `inlier/matched`、像元角尺度、旋转、parity、内点 RMS 和各向异性；“15 帧证据 → 创新摘要”在已有校准时才显示线状候选的切平面角速度，没有校准仍显示“待标定”。当前没有在仓库内下载或内置外部离线星表，CSV 必须由用户或主办方提供，并保留版本、筛选条件和授权边界。

### 7.1 两种“最暗星”不能混为一谈

需要分别定义：

- **目录最暗星**：在星表筛选范围中星等数值最大的源；它可能根本没有在当前图像中被检测到。
- **图像最暗可信星**：在图像中被检测、测光质量合格并与目录/标定一致的源；这是比赛“从图片找出”的候选答案。

建议最终输出：

```text
faintest_detected_source_id
faintest_detected_x_y
faintest_detected_flux
faintest_detected_snr
faintest_catalog_id
faintest_catalog_mag
instrumental_mag
calibrated_mag
mag_error
catalog_band
quality_flags
```

### 7.2 用匹配星做零点拟合

在有足够高质量匹配星时，可以拟合：

```text
m_catalog - m_inst = ZP + C × color + spatial_term + residual
```

参考星选择要排除饱和、边缘、拥挤、变量、低 SNR 和明显异常残差源。至少保留训练/拟合星与留出验证星，报告零点残差和不同亮度区间的误差。

若只有 Gaia G 而没有本相机的响应曲线，输出应写成“基于 Gaia G 的近似转换”或“相对/仪器星等”，不能把 G 无转换地命名为 `Mv`。

## 8. 星表与运动目标识别的连接

星表路线可以显著改善运动目标检测，但不能单独完成运动目标识别：

1. 对每帧完成 WCS 或相对配准；
2. 将星表静态源投影到每帧，建立静态星掩膜/参考目录；
3. 对静态星附近的残差做 PSF matching 或差分；
4. 把持续出现但相对静态星场发生位移的候选交给轨迹关联；
5. 用星表匹配状态作为特征，而不是作为唯一判定条件。

如果目标是空间目标、卫星或碎片，它可能不在 Gaia 恒星表中；“未匹配星表”只能是候选条件，必须叠加多帧轨迹、残差形状、亮度变化和伪迹排除。

## 9. 推荐实现路线

### 路线 1：工具基线，最快验证主办方思路

使用 Astrometry.net 或同类 plate solver：

1. 从 FITS 提取图像并屏蔽首行辅助区域；
2. 先用亮星检测结果生成源列表；
3. 根据真实 FOV 选择 Tycho-2/Gaia 索引尺度；
4. 求解 WCS 并输出匹配源；
5. 将 WCS 回写到副本或保存为独立 `.wcs` 文件；
6. 在图像上叠加 RA/Dec/星等，比较是否能复现主办方截图风格。

优点是可以快速确认“图像是否可被星表解算”和“FOV/方向是否正确”；缺点是依赖外部工具和索引，参数透明度、离线发布和定制创新空间需要额外处理。

### 路线 2：有先验的自研匹配器，推荐作为比赛主体

利用辅助 `ra/dec` 和连续帧先验，构建轻量的任务星表匹配器：

1. 读取本地任务星表子集；
2. 按光轴和 FOV 分区查询；
3. 对检测源和星表源生成三角形/星对特征；
4. 用角距/比例容差产生候选变换；
5. 用 RANSAC + 全场投影验证；
6. 拟合 TAN + 可选 SIP WCS；
7. 逐源回填 `source_id/ra/dec/mag/residual`；
8. 保存候选解、次优解和失败原因。

优点是流程可解释、可控、容易做比赛答辩和创新分析；缺点是需要自行处理模式索引、坐标约定、畸变和星表版本。

### 路线 3：连续帧跟踪模式，服务运动目标

第一帧用盲解算或有先验匹配获得 WCS，后续帧用静态星点估计小变换和局部更新，不必每帧全天空盲解算。每帧仍需保留质量检查；当内点数或残差异常时，回退到重新解算。

## 10. 实验设计

建议先做一个小型消融实验，而不是直接追求最终数字：

| 实验 | 变量 | 观察指标 |
| --- | --- | --- |
| A | 亮星数量 K = 30/50/100/200 | 解算成功率、耗时、误匹配率 |
| B | 星对 vs 三角形 vs 四边形 | 候选数、唯一性、残差 |
| C | 有 `ra/dec` 先验 vs 完全盲解算 | 搜索范围、成功率、速度 |
| D | 不同星等上限和质量筛选 | 匹配完整性、暗星覆盖 |
| E | 不同 WCS 模型 | `rms_pixel`、边缘残差趋势 |
| F | 不同时间传播处理 | 长时间跨度下的位置偏差 |

每组实验保存输入文件、星表版本、筛选条件、FOV 范围、阈值、WCS 参数、匹配结果和失败原因。只有这样才能把“星表路线”从演示图变成可复核的科学方案。

## 12. 风险清单

| 风险 | 表现 | 缓解办法 |
| --- | --- | --- |
| WCS 方向反了 | RA/Dec 标注整体镜像或旋转 | 检查 `x/y`、像素原点、RA 轴方向，用已匹配星验证 |
| FOV 错误 | 模式候选过多或完全无解 | 扫描角尺度，先用亮星测量源间角距 |
| 星表波段不匹配 | 亮度排序和截图的 `mag` 不一致 | 明确 G/V/自定义量，拟合颜色转换并报告误差 |
| 星表历元未传播 | 高自行星位置偏差 | 使用 `ref_epoch`、`pmra/pmdec` 做位置传播；长跨度再评估视差 |
| 目录不完整 | 检测到的暗星无法匹配 | 分开记录 `N_detected` 与 `N_matched`，做完整性实验 |
| 误解星表为真值 | 匹配数等于“实际恒星数” | 用注入实验、人工抽检和残差/唯一性证据确认 |
| 运动目标被当成恒星 | 目标被硬匹配到附近目录星 | 使用多帧相对运动、匹配残差和轨迹一致性复核 |
| 过拟合 WCS | 训练星残差很小，其他星很差 | 保留留出星，限制模型阶数，检查空间残差趋势 |
| 个人/网络依赖 | 线上查询无法复现 | 冻结星表子集、查询 ADQL、版本、哈希和本地索引 |

## 13. 当前结论

星表路线值得作为本项目的主线增强方案，但应拆成三个可验证目标：

1. **WCS 可解算**：能否从当前 FITS 和亮星模式稳定得到像素到 RA/Dec 的变换。
2. **源身份可匹配**：匹配是否具有足够内点、低残差和唯一性。
3. **测光可标定**：星表星等与图像通量之间是否有可报告的零点/颜色模型。

推荐顺序是“先验证 WCS，再做逐源匹配，再做星等标定，最后用星表辅助运动目标识别”。在第一个目标没有通过前，截图上的 RA/Dec 文字只能是可视化标签；在第三个目标没有通过前，`13.56Mv` 只能作为示例数值，不能作为正式星等结论。

- [Wei et al. 2024, A Star Identification Graph Algorithm Based on Angular Distance Matching Score Transfer](https://doi.org/10.1109/JSEN.2024.3350089)：公开项目页面列出的角距图匹配论文，用于模式匹配路线对照，不作为当前数据真值。
- [Wei et al. 2025, Real-Time Detection, Tracking, and Anomaly Analysis of Dim Small Space Targets Using Star Sensors](https://doi.org/10.1109/TIM.2025.3573015)：公开项目页面列出的点目标检测、跟踪与异常分析论文，用于时序分支对照，不替代当前数据上的注入和真值验证。
- [Wohlberg & Wozniak 2021, PSF Estimation in Crowded Astronomical Imagery](https://arxiv.org/abs/2101.01268)：拥挤场中经验 PSF 估计和局部模型适用域的参考。
