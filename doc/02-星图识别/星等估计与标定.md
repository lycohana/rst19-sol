# 星等估计与标定

状态：**已实现仪器星等、公共 Gaia DR3 显式接入、星表光度标定、15 帧相对标尺、逐源质量状态，以及视差/GSP-Phot 距离的绝对星等质量门控；首帧已实测通过自动板解与 Gaia G 经验定标，但同设备响应曲线和最暗源全场覆盖仍待验证**

## 1. 先明确“亮度最低”的含义

星表路线可以提供参考星身份和目录星等，但不能跳过图像检测、背景扣除和测光标定。完整的星表匹配、WCS 和“目录最暗星/图像最暗可信星”区分见 [星表路线深度研究](./星表路线深度研究.md)。

天文学中的星等是对数亮度标度，数值越大通常表示源越暗。因此“亮度最低的星”应解释为：在满足检测可信度和标定条件的候选星中，星等数值最大的那一颗，而不是像素值最小、峰值最低或背景最暗的像素。

星表中的数值还必须保留来源：`phot_g_mean_mag` 是 Gaia DR3 的 G 波段表观星等，`magnitude` 是兼容字段，`magnitude_source` 则记录实际采用的列或变换来源。若 CSV 同时给出 `magnitude` 与 `phot_g_mean_mag` 且两者数值冲突，读取器会拒绝该行；这样可以避免一个自定义波段或手工覆盖值被自动标成 Gaia-G。

按题面“找出图片中亮度最低的星并标注该星的星等”的表述，比赛主结果应优先解释为**观测到的表观星等 `m`**；绝对星等 `M` 是把恒星放到 10 pc 后的本征亮度，不是这张照片直接观测到的亮度。没有可靠距离和同波段消光时，程序应提交 `m_cal`（若未标定则为 `m_inst`）并说明口径，不应把一个仪器星等改名为 `M_V`。

### 公共资料能补什么，仍缺什么

Gaia DR3 的公开主星表可以提供参考源的 `ra/dec`、`phot_g_mean_mag`、BP/RP 星等和通量误差、视差及视差误差；这些字段足以支持“图像源—目录源”匹配和多参考星的经验表观测光标定。字段定义见 [Gaia DR3 主星表数据模型](https://gea.esac.esa.int/archive/documentation/GDR3/Gaia_archive/chap_datamodel/sec_dm_main_source_catalogue/ssec_dm_gaia_source.html)。

本相机给出的 `450–750 nm` 是标称波段范围，不等于完整系统响应曲线。Gaia DR3 还公开了基于 BP/RP 光谱的合成测光资料，覆盖 `330–1050 nm`，并提供接近 `V` 的标准系统合成星等；它适合作为公共参考，但仍需用当前相机的颜色项验证，不能无转换地把 Gaia `G` 写成本相机 `V`。[Gaia DR3 合成测光说明](https://gea.esac.esa.int/archive/documentation/GDR3/Gaia_archive/chap_cu9pvp/sec_cu9pvp_colours/)

如果要进一步给出绝对星等，Gaia GSP-Phot 公开了模型距离、`M_G` 以及 `A_G` 等同一模型下的消光量和区间；官方说明其结果依赖 BP/RP 光谱、表观 G 和视差的模型拟合，并提醒低质量视差和高消光区域存在系统误差。因此它可以作为**带来源、带区间的绝对星等证据**，不能代替本相机的物理测光标定。[Gaia GSP-Phot 方法和数据范围](https://gea.esac.esa.int/archive/documentation/GDR3/Data_analysis/chap_cu8par/sec_cu8par_apsis/ssec_cu8par_apsis_gspphot.html)

当前仍需要从 FITS、辅助数据或额外标定观测中确认：

1. 光轴的 RA/DEC、旋转和奇偶性，或通过板解得到可靠 WCS；只有相机焦距和视场不能完成天球匹配。
2. 本设备的零点、响应曲线和颜色转换；公共星表不能替代当前相机的 `ZP`、颜色项、平场和非线性标定。
3. 增益、偏置、暗电流、读出噪声、饱和与坏像素等测量误差参数；没有这些参数仍可做经验相对测光，但误差不能写得过小。
4. 留出参考星验证、最暗端的完整率和误检率；“星表匹配成功”不等于“全图最暗星已经被证明”。
5. 对 `M` 而言，还必须有已确认身份的恒星距离/视差和**同一光度波段**的消光。`A_0`、`A_V`、`A_G` 不是可以互换的字段，结果必须保留它们的波段、系统和来源。

AOE/TLE 等轨道资料主要帮助确定卫星的位置、时间和运动目标的几何关系，对动目标分析有用；它们本身不能给当前相机提供光度零点、滤光片响应或恒星星等真值。FITS 原始文件是测光输入，真正缺的是配套标定和逐星真值，而不是再找一份“FITS 格式说明”。

单个像素最小值不能用于找最暗星，原因包括：

- 星光会分布在多个像素上，必须测量源的总通量或 PSF 参数。
- 背景、噪声、坏点和负值可能比星点峰值更低。
- 最暗候选通常最接近检测极限，误检和选择偏差更严重。
- 未经零点和响应曲线标定的原始计数只能支持同一图像内的相对排序，不能自动变成物理星等。

## 2. 可执行的两级结果

### 2.1 级别一：相对亮度/仪器星等

当没有标准星、滤光片响应、增益和零点资料时，先输出同一帧内可比较的仪器量：

1. 用 [星点识别方法](./星点识别方法.md) 得到候选源。
2. 对每个候选源在原始图像上用局部背景环做背景扣除后的孔径测光或 PSF 测光。
3. 同时传播局部背景 RMS、背景环有限像素数、孔径像素数和可选的 gain/read-noise，得到 `flux_error` 与 `flux_snr`。
4. 得到净通量 `F`，并按一致的曝光时间归一化。
4. 计算仪器星等：

```text
F_rate = F / t_exp
m_inst = -2.5 × log10(F_rate)
```

这里只能稳定地比较同一图像或同一成像系统下的相对亮暗。若使用不同曝光或不同帧，还要处理背景、增益、非线性和帧间响应变化。

### 2.2 级别二：绝对/标准系统星等

有可靠参考源和标定参数后，才能把仪器量转换为目标光度系统中的星等。一个常见的工程模型是：

```text
m_std = m_inst + ZP + C × color + extinction_term + residual
```

不同资料对零点、消光项和颜色项的符号约定可能不同，代码中必须通过标准星拟合验证，而不能只照抄公式。`ZP`、颜色系数、消光系数和残差应由参考星在同一设备、同一观测条件或已知转换模型下估计。

## 当前代码已经补齐的星等链路

当前实现不再把一个 `m_inst` 数字直接包装成“星等结果”，而是保留以下血缘：

```text
原始 FITS ADU
  → 局部背景扣除/孔径净通量
  → m_inst = -2.5 log10(ADU/s)
  → 星表一对一匹配
  → 多颗参考星拟合 ZP + 颜色项
  → m_cal（声明光度系统和波段）
  → 可靠视差 + 消光门控
  → M（绝对星等估计，带误差和状态）
```

### 结果字段

`FrameAnalysis.as_dict()` 现在包含 `photometric_calibration` 和逐源的
`source_photometry`。每个源至少可以有以下字段：

| 字段 | 含义 | 没有条件时的行为 |
| --- | --- | --- |
| `instrumental_magnitude` | 当前设备、当前曝光归一化后的仪器星等 | 没有正净通量时为 `null` |
| `calibrated_magnitude` | 经过参考星拟合后的表观星等 | 没有匹配、颜色或有效标定时为 `null` |
| `absolute_magnitude` | 由 `m_cal`、可靠视差或明确来源的模型距离和消光得到的结构化结果 | 缺距离、视差质量不足且无模型后验，或缺消光时保留 `status`，不制造数字 |
| `instrumental_magnitude_error` | 近似的测光误差，基线为 `1.0857 / flux_SNR` | SNR 不可用时为 `null` |
| `calibrated_magnitude_error` | 测光误差与标定残差的平方和近似 | 只有成功应用标定时生成 |
| `photometric_system/band` | 结果属于哪个光度系统/波段 | 未声明时为 `unknown`，不能默认写成 V |
| `status/flags` | `INSTRUMENTAL_ONLY`、`CALIBRATED`、`NO_PARALLAX`、`LOW_PARALLAX_SNR` 等 | 用于解释落选、不可计算和审计证据 |

### 多参考星标定

`fit_photometric_calibration()` 使用匹配结果中的多颗高质量参考星，而不是拿一颗星的差值当零点：

```text
m_catalog - m_inst = ZP + C1 × color + C2 × color²
```

当前默认拟合一次颜色项。算法会排除质量失败、低 `flux_SNR`、边缘/掩膜/饱和、匹配残差过大和缺颜色的参考源；随后进行确定性留出验证、MAD 离群剔除和加权最小二乘。GUI/CLI 默认要求至少 6 颗参考星；接口仍允许在明确的诊断实验中降低门槛。输出至少包括：

- 参考星总数、MAD 剔除后的内点数和留出验证数；
- 零点、颜色系数、颜色覆盖范围；
- 拟合 RMS、留出 RMS、残差 MAD；
- `VALID`、`VALID_NO_HOLDOUT`、`INSUFFICIENT_CALIBRATORS`、
  `INSUFFICIENT_COLOR_RANGE` 或 `INSUFFICIENT_INLIERS` 状态。

因此，“匹配成功很多”仍不等于“标定成功很多”：如果参考星颜色范围退化、全部集中在一个亮度/空间区域或留出残差很差，结果会明确降级，而不是继续显示一个伪精确零点。

### 绝对星等的质量门控

对已经属于明确光度波段的表观星等，代码使用：

```text
M = m_cal - 5 log10(d / 10 pc) - A
d = 1000 / (parallax_mas - parallax_zero_point_mas)
```

当视差为非正数，或 `parallax_error / corrected_parallax > 0.2` 时，不输出简单倒数得到的绝对星等，而返回 `INVALID_PARALLAX` 或 `LOW_PARALLAX_SNR`，并标记 `USE_DISTANCE_POSTERIOR`。如果目录同时提供了带明确来源的 `distance_pc` 及其上下界（例如 Gaia DR3 GSP-Phot 的 `distance_gspphot`、16/84 百分位），程序会转入独立的模型距离路径，状态写为 `VALID_MODEL_DISTANCE`，并添加 `PARALLAX_QUALITY_FALLBACK_TO_MODEL_DISTANCE`；这不是把低 SNR 视差硬倒数，而是明确使用另一套带模型假设的距离证据。模型距离会在对数距离空间用上下界传播误差，并保留 `distance_source`、`distance_lower_pc` 和 `distance_upper_pc`。缺少消光时返回 `MODEL_DISTANCE_NO_EXTINCTION`，保留距离诊断但不制造数值 `M`；不能声称是完整消光修正后的绝对星等。

因此绝对星等结果至少要区分：`VALID`（视差质量通过）、`VALID_MODEL_DISTANCE`（使用明确来源的距离模型）、`LOW_PARALLAX_SNR`（没有可用模型后验时拒绝点估计）和 `MODEL_DISTANCE_SOURCE_REQUIRED`（有距离数字但没有可追溯来源）。`M_G` 的数值存在不等于距离测量独立可靠；答辩时必须同时展示距离来源、区间、消光波段和误差。

现在结果对象和质量报告又把“数字存在”和“可以正式引用”分开：

| 字段 | 允许的解释 |
| --- | --- |
| `absolute_magnitude.value` / 报告中的 `absolute_magnitude` | 兼容旧缓存的诊断值；即使存在，也可能缺少距离区间、来源或消光语义 |
| `absolute_magnitude.is_strict` | 严格门是否通过；只有 `true` 才能把该值作为正式 `M_G`/`M_V` 使用 |
| `distance_interval_status` | `PROVIDED` 或 `DERIVED_FROM_PARALLAX_ERROR` 才表示有完整区间；`REQUIRED`、`ONE_SIDED`、`NOT_PROVIDED` 只能作诊断 |
| `error_status` | `AVAILABLE` 表示表观星等、距离和消光误差链完整；`INCOMPLETE` 不会伪造一个误差条 |
| `strict_M` / `strict_absolute_magnitude` | 报告层重新审计后可正式使用的值；不合格时为 `null` |
| `absolute_magnitude_value_role` | `STRICT`、`DIAGNOSTIC_ONLY` 或 `ABSENT`，用于 GUI 和创新统计的明确分流 |

因此旧 JSON 中只有 `M=4.2`、`M_G=4.2` 或 `status=VALID`，但没有 `is_strict` 和完整距离区间时，系统会保留数值帮助复核，却只标记为 `DIAGNOSTIC_ONLY`。`VALID_MODEL_DISTANCE_NO_INTERVAL` 也只能展示为“模型距离诊断值”，不能进入正式绝对星等计数。`M_G` 和 `M_V` 的波段身份会分别保留；任何没有明确波段的裸 `M` 都不能在导出时被自动改名为 `M_V`。

对于未匹配的运动目标、线状目标或没有可靠星表身份的源，系统不会计算 `M`。它们可以保留 `m_inst` 作为图像测量量，但不能被强行解释成恒星的绝对星等。

### 公共 Gaia 数据能补上什么

公共资料可以解决“参考恒星是谁、它在天空中的位置和目录亮度是多少”这部分，不能凭空补上相机的物理响应。当前仓库提供了显式的 Gaia DR3 TAP 查询入口：它只在用户主动运行命令时联网，导入模块、运行普通 `rst19` 和打开 GUI 都不会发起请求。

本数据的首帧辅助区给出的光轴先验为 `RA=129.533548°`、`DEC=-1.845372°`；相机资料给出的标称视场约 `9.78°×9.78°`，正方形视场的外接半径约 `6.92°`。因此可以先用一个不超过外接视场的查询范围生成候选星表：

```powershell
python -B -m rst19.gaia_remote_cli `
  --ra 129.533548 --dec -1.845372 --radius 6.92 `
  --min-g-mag 8 --max-g-mag 18 --limit 20000 `
  --out tmp\gaia-dr3-field.csv
```

命令会同时生成 `tmp\gaia-dr3-field.csv.meta.json`，记录查询中心、半径、星等筛选、查询语句、返回行数和数据表名。`--min-g-mag` 不是说亮星不存在，而是给后续测光/匹配避开可能饱和的参考星；`--max-g-mag` 只应按图像的实际检测极限调整。查询返回的 CSV 已兼容现有 `--catalog` 入口，且明确记录 `Gaia DR3 / Gaia Vega / G`、`BP-RP`、视差、视差误差、自行和 Gaia 质量字段。

本轮还把 Gaia 质量字段贯通到 `CatalogSource` 和光度拟合：`phot_g_mean_flux_over_error` 用于识别目录 G 测光本身过弱的参考星，`ruwe`、`visibility_periods_used`、`duplicated_source` 和 `phot_variable_flag` 用于排除明确不适合作为零点锚点的行。默认光度拟合门限为 G 通量 SNR `20`、`RUWE ≤ 1.4`、`visibility_periods_used ≥ 8`，并排除 `duplicated_source=true` 和 `phot_variable_flag=VARIABLE`；字段缺失会保留该星，但不会被伪装成“质量已验证”。`phot_bp_rp_excess_factor` 只保留作审计，暂不使用一个脱离颜色和样本范围的固定阈值硬切。Gaia 官方说明 excess factor 应结合颜色及校正形式解释，不能把一个原始比值直接当成恒星/非恒星标签。

需要特别记录一个容易被忽略的接口事实：Gaia DR3 的 `gaia_source` 不提供对称的 `phot_g_mean_mag_error` 列，官方给出的是 `phot_g_mean_flux` 和 `phot_g_mean_flux_error`，并说明 G 星等误差在通量空间并不对称。当前代码查询这两个原始字段，再用

```text
sigma_m ≈ (2.5 / ln 10) × sigma_F / F
```

生成 CSV 兼容的 `magnitude_error`；这只是本地一阶近似，不能在论文中写成 Gaia 官方的对称星等误差。字段依据见 [Gaia DR3 gaia_source 数据模型](https://gea.esac.esa.int/archive/documentation/GDR3/Gaia_archive/chap_datamodel/sec_dm_main_source_catalogue/ssec_dm_gaia_source.html)。

还要检查查询是否被服务端截断。`6.92°` 外接圆面积约为 `150 deg²`，不适合无条件当作一次完整下载；大视场查询即使 HTTP 成功，也可能只返回部分行，且返回顺序会让结果看起来偏亮。本次实测一次无星等筛选、`TOP/MAXREC=5000` 的大圆锥查询恰好返回 `5,000` 行，返回的 `G` 范围约为 `7.71--21.90`，因此只能判定为截断/不完整，不能据此声称视场内只有这些星。对照的小范围查询中，`G=8--13` 的 `1°` 圆返回 `450` 行，`G=8--18` 返回 `9,203` 行；这说明“返回多少行”强烈依赖查询范围、星等窗口和服务端上限。实际使用应缩小查询范围、降低参考星星等上限，或按小圆/网格分块查询后按 `source_id` 去重；返回行数和星等分布必须写入实验记录。

为避免把大圆锥的部分返回误当成完整星表，当前还提供了显式的分块入口。它将目标范围拆成有重叠的小圆，在本地按球面距离裁剪并按 `source_id` 去重；每一块的返回数、`MAXREC/limit`、截断状态和异常都会写入审计文件。该命令仍然只在用户主动执行时联网：

```powershell
python -B -m rst19.gaia_tiled_cli `
  --ra 129.533548 --dec -1.845372 --radius 6.92 `
  --tile-radius 1 --min-g-mag 8 --max-g-mag 18 --limit 5000 `
  --out tmp\gaia-dr3-field-tiled.csv
```

大视场分块结果只有在所有块未饱和、无查询错误且未超过块数上限时才标记为 `complete=true`；否则命令返回非零状态，但仍保留 CSV 和 `.tiled.meta.json` 作为部分结果和失败证据。`--dry-run` 可以只规划分块而不联网；当前首帧的 `6.92°` 外接圆按 `1°` 块半径会规划为约 `339` 个块，因此正式测光前还应按已验证的 WCS 和检测极限缩小范围，而不是无条件下载整个外接圆。

如果不想手工填写首帧辅助区的 RA/DEC，可以让工具从 FITS 中读取光轴先验，再显式查询 Gaia DR3：

```powershell
python -B -m rst19.gaia_frame_cli path\to\frame.fits `

  --min-g 5 --max-g 13.5
```

这个入口只把 FITS 辅助数据用于规划查询中心，不把它误当成完整 WCS。没有另行指定 `--radius` 时，查询半径取标称 `9.78°×9.78°` 正方形视场的外接半径约 `6.9155°`；`G=5--13.5` 是当前设备的参考星工作窗口，不是“图像中只有这些星”的上限。输出 CSV 旁边会生成 `.meta.json`，记录中心、半径、星等窗口、分块数量、重复数和 `complete` 状态。

命令只负责“得到可追溯的公共参考子表”，不会自动宣称 WCS 已解出，也不会在查询不完整时继续拟合零点。若命令返回 `incomplete`，先缩小已验证的图像范围或提高分块能力，并保留审计文件；不要把部分目录当作全场星数真值。GUI 的 **研究工具 → 星表核验 → 在线获取 Gaia DR3** 使用同一条显式路径，联网完成后仍需检查匹配残差，再运行测光定标。

如果希望让程序自动尝试“先验光轴/像元尺度 → 星对板解 → 仿射 WCS 细化 → Gaia G 光度标定”，可在拿到完整 CSV 后运行：

```powershell
python -B -m rst19.photometric_workflow_cli path\to\frame.fits `
  --catalog tmp\public-catalog\frame.gaia-dr3.csv `
  --out tmp\photometric-auto\frame.json
```

该命令只读取本地 FITS 和 CSV，不联网；GUI 的 **自动板解 + 测光** 按钮执行同一条链路，若未填写 CSV 则先显式获取 Gaia。自动流程把匹配半径分成两级：默认先用 `3.0 px` 的宽门提出覆盖充分的几何候选，再用 `1.0 px` 的细门独立复核几何板解；细门解通过时才采用它，细门证据不足时保留宽门解并让后续光度门控决定能否使用。随后测光层仍用 `1.0 px` 细门重新匹配光度参考星；在当前密集星场中，若把 `3.0 px` 直接用于测光，WCS 误差之外的近邻随机误配会进入光度留出验证。宽门、最终采用的板解半径和测光半径会写入 JSON 的 `matching_policy`，也可用 `--photometry-match-radius` 显式覆盖。`status=CALIBRATED` 才允许把结果读作声明为 `Gaia Vega/G` 的经验表观星等；`WCS_*` 或 `WCS_VALID_PHOTOMETRY_*` 状态只保留 `m_inst`，不会把巧合近邻或未通过光度门控的数字冒充标准星等。命令退出码为 `0` 表示已标定，`3` 表示分析完成但没有得到可接受的标定，`2` 表示输入/读取错误。

首帧的实测诊断现在已经形成了“几何可行、光度尚未收敛”的分层证据：半径 `0.1°/0.25°/0.5°` 的小范围查询分别返回 `4/29/109` 行，`1°` 范围在 `G=8--13` 和 `G=8--18` 窗口分别返回 `450/9,203` 行；而 `6.92°` 大范围查询在 `TOP=5000` 下被截断，因此不能把一次大圆查询的返回数当作完整星表。随后使用首帧检测结果、Gaia `G=5--10` 参考子表和显式星对几何候选，在 `3 px` 匹配门、至少 8 个匹配、视场覆盖度 `≥2%`、留一残差门控下得到一组 `VALID` 几何候选：唯一匹配 `98` 个、覆盖度 `0.9644`、像元尺度 `8.4329 arcsec/px`、RMS `0.8141 px`、留一 RMS `0.8432 px`。这证明先验姿态与公共星表可以支持局部板解，但不证明全部检测源都已正确识别。

将首轮仿射结果用于二次匹配后，参考目录扩展到首帧中心 `1°` 内的 `G=10--13` 子表，唯一匹配增加到 `1,151` 个，匹配 RMS 降至 `0.6792 px`；但光度标定留出 RMS 仍约 `0.3973 mag`，且当前目录只覆盖到约 `m_G=11.78` 的已标定源。这组结果不能被写成“最暗星为 `11.78`”，因为图像检测工作集明显还包含更暗候选，当前只是“已匹配公共参考源中的最暗值”。因此系统新增 `selection_scope`、候选总数和已标定候选数，明确区分 `CALIBRATED_MATCHES` 与 `CALIBRATED_MATCHES_PARTIAL`，禁止用部分星表覆盖冒充全图最暗恒星。

为减少“先猜旋转再做最近邻”带来的巧合匹配，当前还增加了显式的星对几何候选接口 `rst19.plate_solver.solve_plate`。它只接收调用方已经准备好的图像检测点、目录点和光轴/尺度先验，不主动联网；先用成对距离提出正向/反向相似变换，再通过一对一匹配、仿射细化、残差、视场覆盖和留一验证决定是否接受。留一验证必须实际产生有限的验证残差；若验证样本为空，不能把“没有验证”解释为通过。`status=VALID` 才允许下游把变换当作 WCS 候选，`NO_SOLUTION`/`REJECTED` 只保留失败证据，不能拿来拟合零点。当前真实首帧已经得到上面的 `VALID` 几何候选；下游还会使用完整仿射矩阵二次匹配，而不是把仿射模型压成只含平均尺度的 TAN 近似。需要注意，几何 `VALID` 只说明像素—天球映射在当前证据下可用，光度 `VALID` 仍需独立检查参考星质量、颜色覆盖、饱和/非线性和留出残差。

有本地 CSV 后可以显式运行同一算法，命令只读取 FITS 和 CSV，不访问网络：

```powershell
python -B -m rst19.plate_solver_cli path\to\frame.fits `
  --catalog tmp\gaia-dr3-field-tiled.csv `
  --center-ra 129.533548 --center-dec -1.845372 `
  --pixel-scale-arcsec 8.5 --epoch 2016 `
  --out tmp\plate-solution.json
```

退出码为 `0` 只表示 `status=VALID`；`3` 表示候选存在但没有通过匹配数、残差、覆盖度或留一验证，`2` 表示输入/读取错误。这样失败也会留下可审计 JSON，而不是让后续光度流程误用一组巧合近邻。

随后仍需用真实图像的像元尺度、旋转、奇偶性和匹配残差做几何验证。例如，只有在先验 WCS 可靠时，才把该 CSV 传给单帧测光：

```powershell
rst19 path\to\frame.fits `
  --catalog tmp\gaia-dr3-field.csv `
  --center-ra 129.533548 --center-dec -1.845372 `
  --pixel-scale-arcsec 8.5 --rotation-deg 0 --parity 1 `
  --fit-photometry --photometric-system "Gaia Vega" --photometric-band G `
  --photometric-color-name BP-RP --json-out tmp\frame-photometry.json
```

这条路线能把匹配恒星的结果推进到 `m_G`，并在视差、消光和质量条件满足时给出 `M_G`。公共 Gaia DR3 的 `gaia_source` 还提供部分源的 `distance_gspphot`、`ag_gspphot` 及 16/84 百分位区间；下载器会把这些 GSP-Phot 字段原样保留，并用 `ag_gspphot` 生成带来源标记的本地消光字段。当前结果层已经真正消费这些字段：高质量视差优先，视差缺失或质量不足时才使用带来源的 GSP-Phot 模型距离，并在逐源 `absolute_magnitude` 中保留模型标记和距离区间。它们仍然只是“单星模型估计”的绝对星等证据，不能替代高质量视差/距离后验，也不能把模型值说成本相机直接测得的距离。它不能把未匹配的运动目标变成 Gaia 恒星，也不能把 `G` 无转换地改名为 `V`。当前数据仍缺少已经实测并授权使用的同设备零点、增益/读出噪声、平场、非线性/饱和曲线和本相机完整响应曲线；因此最稳妥的比赛表述是“基于 Gaia G 参考星的经验表观星等标定，并对部分匹配星给出带来源的绝对星等估计”，而不是宣称完成实验室级绝对辐射标定。

#### 亮星定标表与深星表必须分开核验

对于本题，公共资料应按用途分成两层，而不是随手拿一张 CSV 同时承担所有任务：

1. **定标参考层**：优先查询 `G≈5–13.5` 的 Gaia DR3 源，用于星对板解、零点和 `BP-RP` 颜色项。`G<5` 的源可能接近相机饱和或出血结构，不能无条件当作参考星；过亮源应先做饱和/非线性审计。
2. **全场候选层**：再查询覆盖检测极限的更深窗口（例如 `G=8–18`，实际要按本机 `m_cal` 极限调整），用于检查匹配覆盖和哪些检测源可能落在目录极限之外。它不能因为“更深”就自动成为完整星表，也不能替代亮星定标层。

如果一张表同时覆盖 `G=5–18` 也可以，但必须确认分块查询的 `complete=true`，并检查每个 tile 没有达到 `TOP/MAXREC` 上限。当前旧的 `G=8–18` 宽场 CSV 不能作为正式标定表：它从口径上缺少 `G<8` 的亮参考星，实际返回还在约 `8,193` 行处停止，且侧车审计没有给出完整覆盖证据。板解器现在会在有先验光轴和图像尺寸时优先从视场内核心选取亮星，避免宽目录中的场外亮星挤占几何点预算；但这只是避免误选，不能修复目录缺亮星或被截断的问题。换句话说，公共 Gaia 资料可以解决“参考星身份、Gaia G 表观星等、部分匹配星的 `M_G` 模型证据”，不能单独解决“开运一号相机的严格绝对零点和自然波段响应”。

### 15 帧相对光度创新

即使没有同设备零点，15 张连续曝光仍可以估计帧间零点变化和稳定源的相对星等。当前相对模型为：

```text
m_ij = μ_j + z_i + spatial_terms(x_ij, y_ij)
```

其中 `μ_j` 是源的相对亮度，`z_i` 是第 `i` 帧的相对零点，整体规范固定为 `median(z_i)=0`。拟合使用质量通过、静态、非变量参考源，按测光误差加权，并用源分块留出验证和残差 MAD 剔除异常观测；它是创新分析证据，不是标准系统星等或绝对星等。

对已整理的观测行（字段见 `rst19.relative_photometry.Observation`）可以直接运行：

```powershell
python -B -m rst19.relative_photometry_cli tmp\relative-observations.json `
  --spatial-order 0 --validation-fraction 0.2 `
  --out tmp\relative-photometry.json
```

相对结果和 Gaia 标定结果应分开报告：前者回答“同一序列中哪些源亮度稳定、帧间响应如何变化”，后者回答“在声明的光度系统中星等是多少”。二者不能互相替代。

### 可复核的星等质量报告

为了避免把 JSON 中一个数值误读成“绝对星等”，当前提供五级可观测性审计：`INSTRUMENTAL_ONLY`、`RELATIVE_CALIBRATED`、`APPARENT_CALIBRATED`、`ABSOLUTE_ELIGIBLE` 和 `GEOMETRY_UNAVAILABLE`。报告还会汇总 WCS、星表、标定、视差、消光和绝对结果的缺失条件，并检查“`m_cal/M` 有数值但状态却无效”的 false-valid 情况。

```powershell
python -B -m rst19.photometric_report_cli tmp\frame-photometry.json `
  --require-wcs --out tmp\photometric-quality-report.json
```

默认审计只记录问题；若用于提交前检查，可增加 `--strict`，让状态与数值矛盾直接以失败退出。这样答辩时可以同时展示星等数字、使用的星表/波段/零点、误差预算以及仍缺少的条件。

### GUI 与 CLI 使用

GUI 的源表现在并列显示 `m_inst`、`m_cal` 和 `M`；悬停信息还显示标定状态、星等误差和 flags。打开“研究工具 → 星表核验”并完成匹配后，系统会自动尝试光度标定；点击“根据匹配拟合 WCS”通过几何门控后，程序会用完整仿射矩阵重新匹配并重做当前帧测光，主界面也同步这份已验证的结果。最暗源大卡片在几何和光度证据均通过时优先显示声明波段的 `m_G,cal`（或相应 `m_<band>,cal`），并在副行保留 `m_inst`；没有验证通过时仍显示 `m_inst`，不会把先验 WCS 或自定义零点包装成标准星等。WCS 局部拟合仍是单独按钮，因为它是几何校准，不应和光度校准混成一个“校准成功”。

CLI 示例：

```powershell
rst19 path\to\frame.fits `
  --catalog path\to\gaia_subset.csv `
  --center-ra 129.53 --center-dec -1.84 --pixel-scale-arcsec 8.5 `
  --fit-photometry `
  --photometric-system "Gaia Vega" `
  --photometric-band G `
  --photometric-color-name BP-RP `
  --parallax-zero-point-mas 0.0 `
  --json-out result.json
```

CSV 至少应包含 `source_id`、`ra`/`ra_deg`、`dec`/`dec_deg`、
`phot_g_mean_mag` 或明确的 `magnitude`；建议同时提供 `bp_rp`、
`parallax`、`parallax_error`、`a_g` 和相应误差。使用 Gaia `G` 时，
输出应称为 `m_G` / `M_G`，不能写成 `m_V` / `M_V`。当前开运一号的
`450–750 nm` 是宽谱范围，不足以证明它与 Gaia G 或 Johnson V 相同。
`--parallax-zero-point-mas` 不应凭经验随意填写；应跟随所用星表数据
发布版本、样本类型和参考文献。默认值为 `0` 只表示“不额外修正”，
不是声明 Gaia 视差零点一定为零。

### 2.3 当前 `-5.43` 与外部示例 `13.56` 的复核

当前第一张 FITS 的最暗可信源复算链为：

```text
净通量 F       = 约 222 ADU
曝光 t_exp     = 1.5 s
通量率 F_rate  = 222 / 1.5 = 148 ADU/s
m_inst         = -2.5 × log10(148) = -5.4257
```

因此界面显示的 `-5.43` 在当前“仪器星等、零点取 0”的定义下是数学自洽的，但它既不是 `m_V`，也不是绝对星等 `M_V`。出现负数只说明当前对数坐标的零点是任意的；它不表示目标在物理上比太阳亮。

主办方截图中的 `13.56` 没有随截图给出 FITS 文件名、波段、星表版本、匹配 ID、零点、颜色项、消光和距离。若**暂时把它当作同一源、同一波段的标准表观星等**，只能得到一个诊断性差值：

```text
ZP_diag = 13.56 - (-5.4257) ≈ 18.99 mag
```

`18.99 mag` 只能表示“两个口径相差一个可能的光度零点”，不能直接写入程序成为标定零点。要把这个差值升级为可发表的 `ZP`，必须用多颗高 SNR、未饱和、非拥挤参考星拟合，并报告波段/颜色项、消光项、离群剔除规则、训练/留出残差和零点不确定度。当前星表核验窗口只做位置/身份核验；当次没有匹配结果时，星表没有参与 `m_inst` 计算。

还要把三种星等分开：

| 量 | 含义 | 当前状态 |
| --- | --- | --- |
| `m_inst` | 由 ADU/s 定义的未标定仪器星等 | 当前已计算 |
| `m_std` / `m_V` | 加入同设备零点、颜色和消光模型后的标准表观星等 | 当前没有可靠实测标定时显示“待标定” |
| `M_V` | `m_V - 5 log10(d/10 pc) - A_V` | 缺少距离/视差、消光和可靠 V 波段量时不可计算 |

所以，检测到一万八千颗还是两万多颗，最多改变“最暗可信候选”落在哪个检测极限附近，不能提供光度零点，更不能提供距离。数量差异不能解释 `-5.43` 与 `13.56` 的概念差异。

### 2.4 测光字段归属的回归约束

最暗源的 `flux_rate` 必须由最终选中的 `source.flux / exposure_s` 重新计算，不能复用遍历候选时的循环变量。否则界面可能把 A 源的 `m_inst` 与 B 源的 `ADU/s` 拼在一起，造成看似“星等公式不一致”的假象。该归属已有回归测试；它只修正字段血缘，不改变 `m_inst` 的定义。

## 3. 推荐测光流程

### 步骤 A：测量源通量

当前代码以圆孔径和局部环实现轻量离线测光；Photutils 的 aperture photometry 同样以孔径求和为核心，并支持 circular/elliptical aperture 和 annulus。推荐每个候选源同时计算：

- 圆孔径净通量；
- 环形局部背景中位数或 sigma-clipped 统计；
- 孔径面积、有效像素数和背景噪声；
- 受 mask、边缘和邻近源污染的标志。

在未知相机增益时，至少使用背景项和背景均值估计项：

```text
σ_F² = N_ap × σ_b² + (N_ap² / N_bg) × σ_b²
flux_snr = F / σ_F
```

若提供 `gain_e_per_adu`，代码再加入 `max(F,0)/gain` 的源 Poisson 方差；若提供 `read_noise_adu`，加入孔径读出噪声方差。`snr`、`flux_snr` 和 `filter_snr` 是不同物理量，最暗源选择使用 `flux_snr`。

背景扣除可写为：

```text
F_net = sum(source_aperture) - bkg_per_pixel × effective_area
```

拥挤或拖影明显时，对比 PSF photometry。PSF 方法需要背景扣除和可解释的 PSF 模型，适合在亮度范围较宽、源互相影响的场景中提高通量估计一致性，但参数更敏感。

### 步骤 B：质量筛选

参与“最暗星”竞争的候选必须至少满足：

- 净通量为正，且达到预先定义的 SNR 阈值；
- 未饱和、未越界、没有严重坏点或辅助数据污染；
- 局部背景估计有足够有效像素；
- 形状接近点源模型，或异常形状有明确解释；
- 在孔径半径、背景环半径或 PSF 初值改变时，测光排序不过度跳变。

最暗星应取通过质量筛选后 `m_std` 或 `m_inst` 最大者，同时输出它的通量、`flux_error`、`flux_snr`、坐标、测光方法和筛选理由。当前 GUI 和 CLI 输出的 `faintest_detected` 已包含这些相对测光字段；无零点时不能把它叫作 Gaia G、Johnson V 或 `Mv`。

### 步骤 C：误差与检测极限

不能只给出一个小数点后很多位的星等。至少应报告：

```text
source_id
x, y
flux, flux_error
snr, flux_snr, filter_snr
magnitude, magnitude_error
calibration_mode
quality_flags
```

如果候选接近检测极限，应给出“最暗可信星”和“检测极限”两个概念：前者是当前图像中实际检测到的最暗合格源，后者是通过注入实验估计的可恢复阈值。二者不是同一个数。当前默认 `flux_snr≥5` 是质量筛选基线，不是由比赛示例数量倒推出来的真值。

## 4. 绝对标定的前置条件

当前材料已提供 `ra`、`dec` 和姿态辅助信息，但尚未确认完整 WCS、相机内参、像元尺度、滤光片/响应曲线、增益、零点、消光条件和参考星真值。因此，直接把本图像计数转换成标准星等会存在科学性风险。

如果使用 Gaia DR3 做参考，至少需要：

1. 建立可靠的像素到天空坐标映射，或先做 plate solving；
2. 按观测历元、视场和亮度范围检索候选星；
3. 处理 Gaia `G` 波段与本设备响应的差异，不能默认二者相等；
4. 排除变量星、拥挤源、饱和源和有质量标记问题的参考源；
5. 用多个参考星拟合零点/颜色项，并用留出参考星检查残差。

Gaia DR3 文档说明其数据包含 G、BP、RP 等宽带测光和天体测量信息，可以作为参考目录来源；这不等于 Gaia G 星等可以未经转换直接替代本设备的目标星等。

本项目把“可由公共数据补齐”和“必须由相机资料补齐”明确分开：Gaia DR3 的
XP 是覆盖约 `330--1050 nm` 的低分辨率通量标定光谱，在已知目标通带时可以
做合成测光；但本数据目前只有“可见光 `450--750 nm`”这一范围描述，没有
开运一号完整的 `T(λ)` 响应曲线。因此现阶段优先报告 `m_G,cal`；如果用
`450--750 nm` 矩形响应做实验，只能标为“近似自定义波段/伪星等”，不能
冒充真实相机波段。Gaia GSP-Phot 还可以为部分已识别恒星提供模型距离、消光
和 `M_G`，但这些是公共目录的天体物理推断，不是从本 FITS 直接测得的相机
绝对光度。

## 5. 推荐比赛输出

在标定资料不完整时，建议把输出分层写清：

| 输出 | 可交付条件 | 表述方式 |
| --- | --- | --- |
| 最暗可信候选 | 完成背景扣除、测光和质量筛选 | 报告相对排序/仪器星等，并给出误差 |
| 标准系统星等 | 有参考星、WCS 或可靠匹配、零点和响应转换 | 报告标定方法、参数和残差 |
| 检测极限 | 有合成注入和回收率曲线 | 报告指定召回率对应的极限，不冒充实际星等 |

## 6. 文献依据与本项目的取舍

本项目采用“宽筛提案 → 原始 ADU 细筛 → 多帧/星表复核”的路线，原因不是把某一篇论文的阈值照搬进来，而是把不同方法负责的证据层分开：

- Bertin & Arnouts 的 SExtractor 工作说明，大视场自动源提取应同时处理检测、去混叠、测量和形状分类；它适合作为宽筛/源表工程的经典参照，但检测目录本身不等于物理恒星真值。[SExtractor: Software for Source Extraction](https://doi.org/10.1051/aas:1996164)
- Stetson 的 DAOPHOT 工作针对拥挤场恒星测光，强调 PSF 建模和邻近源影响；这支持我们把圆孔径测光作为基线，把拥挤/混源候选交给 PSF 与去混叠细筛，而不是仅凭局部峰数计星。[DAOPHOT: A Computer Program for Crowded-Field Stellar Photometry](https://doi.org/10.1086/131977)
- Landolt 的 UBVRI 标准星工作说明，标准星序列和颜色范围是建立标准光度系统的基础；因此本项目没有把外部截图的 `13.56` 直接当成零点，而是要求同设备参考星拟合并留出验证。[UBVRI Photometric Standard Stars](https://doi.org/10.1086/116242)
- Gaia EDR3 光度处理论文明确区分内部/外部光度标定、背景与拥挤处理以及 G/BP/RP 光度系统；因此 Gaia `G` 不能在没有响应曲线和颜色转换时直接改名为本设备的 `V` 或 `M_V`。[Gaia EDR3: Photometric Content and Validation](https://arxiv.org/abs/2012.01916)

这些文献共同支持本项目的答辩边界：源提取、测光、标准化和绝对星等是不同层级；SNR/形状/持续性是证据，不是自动生成真值标签的替代品。
