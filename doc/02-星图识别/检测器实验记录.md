## 1. 结果定义

代码中故意保留两层数量：

| 名称 | 代码字段 | 定义 | 能否直接作为物理恒星真值 |
| --- | --- | --- | --- |
| 候选峰 | `candidate_count` | Gaussian PSF 匹配滤波后，超过阈值且经非极大值抑制的峰 | 不能；包含伪迹和低质量源 |
| 审计返回 | `returned_count` | 实际计算了局部测光属性的候选源数 | 不能；仅受显式 `max_sources` 影响 |
| 可信点源 | `quality_count` / `star_count` | 通量 SNR、形状、有效像素、边缘、掩膜和饱和检查均通过的源 | 仍需真值/星表/注入实验确认 |
| 最暗可信源 | `faintest_detected` | 在可信点源中，净通量为正且 `flux_snr` 达标的最大 `m_inst` 源 | 是图像内相对答案，不是未经标定的物理星等 |

因此，任何比赛材料都不能只写“程序检测到 N 颗星”，必须同时写检测定义、参数和质量规则。

版本说明：本记录按研究轮次追加，8.38 是 `CODE_PATTERN` 门控后的单帧口径（初版 `29,153`）；8.40 是修正“峰值本身落在重复码上才拒绝”后的最新口径 `29,263`。更早章节中的 `29,271`、`29,295`、`29,153` 等数字保留为历史对照，不与 8.40 的 `29,263` 混算。15 帧类别表若未特别注明，仍可能是门控前或初版门控的序列基线，需在最终提交前按同一缓存版本重跑。

## 2. 当前检测器

### 2.1 数据掩膜

每帧先屏蔽格式说明中的首行前 104 个像素位置、非有限值和整型传感器接近饱和上限的值。对于当前 `BITPIX=16` 数据，自动饱和上限为 `32767 - 32 = 32735`；这是防止把整型边界值当亮星，不是相机真实物理满阱值的替代品。

当前数据背景约为 21 ADU，并存在大量精确 0 值。对于整型图像且背景不为 0 的情况，代码把精确 0 作为无效像素候选进行掩膜；如果未来拿到的相机数据证明 0 是合法信号，可用 `mask_zero_pixels=False` 关闭这一规则。零像素出现在背景环中时不会单独否定整颗星；只有孔径内受污染或背景环有效像素不足才会增加质量标志。

### 2.2 局部背景和噪声

全图 sigma-clipping 的中位数/MAD 用于建立可比较的全局基线；检测实际使用 128×128 网格上的局部背景 `B(x,y)` 和 RMS `R(x,y)`，再线性插值到像素位置。局部噪声不是把每个像素的波动简单当作独立白噪声，而是保留为当前数据的经验 RMS。

外部源提取工具也采用背景图与背景 RMS 图，而不是只用一个全图标量；例如 [SExtractor 背景建模文档](https://sextractor.readthedocs.io/en/stable/Background.html)明确区分 background map 与 RMS map，并指出网格大小会影响估计。当前实现是轻量离线版本，仍需用空白区/注入实验验证 128 像素网格是否最优。

### 2.3 PSF 匹配滤波

对 `D(x,y)=I(x,y)-B(x,y)` 使用 FWHM 为 3 像素的圆 Gaussian 核，`sigma = FWHM / 2.35482`。匹配响应采用掩膜归一化卷积，避免无效像素的 0 值人为压低附近响应；再在响应图上做局部极大值和最小间距抑制。

这一步与旧程序直接把原始像素局部极大值交给 DAOStarFinder 的思路不同，但仍属于点源检测基线，不代表已经完成经验 PSF 拟合。若亮星的实测 PSF 呈椭圆、拖尾或随视场变化，应把实测 PSF/空间变 PSF 纳入后续实验。

### 2.4 局部孔径测光和 SNR

对每个候选峰，在原始图像上用半径 `r=4` 像素的圆孔径测量净通量：

```text
F = sum_aperture(I - B_local)
```

背景环取 `r+2` 到 `r+4` 像素，并对环内值做 sigma-clipping。没有相机增益资料时，通量误差至少包含孔径内背景噪声和背景均值估计误差：

```text
σ_F² = N_ap × σ_b² + (N_ap² / N_bg) × σ_b²
```

如果提供增益，还会加入 `max(F,0)/gain` 的源光子 Poisson 方差；如果提供读出噪声，则加入孔径像素数乘以读出噪声方差。代码同时输出：

- `snr`：峰值 `(peak-B_local)/σ_b`；
- `flux_snr`：净通量 `F/σ_F`；
- `filter_snr`：匹配滤波响应的检测 SNR。

最暗星筛选使用 `flux_snr`，不再把峰值 SNR 当作孔径通量 SNR。没有增益、暗电流、读出噪声、滤光片响应和标准星资料时，代码不会伪造绝对星等。

### 2.5 点源质量规则

默认参数如下，全部会写入 JSON 的 `detection.parameters`：

| 参数 | 默认值 | 作用 |
| --- | ---: | --- |
| `threshold_sigma` | 4.0 | 匹配滤波候选阈值，偏向保留候选 |
| `min_distance` | 3 px | 候选峰最小间距 |
| `psf_fwhm` | 3.0 px | 检测 Gaussian 核 FWHM |
| `background_box_size` | 128 px | 局部背景/RMS 网格 |
| `min_flux_snr` | 5.0 | 可信点源的孔径通量 SNR 下限 |
| `0.8 ≤ fwhm ≤ 12` px | — | 排除极窄尖峰和异常宽源 |
| `ellipticity ≤ 0.65` | — | 排除明显拉长源；椭圆率为 `|FWHM_x-FWHM_y|/max(FWHM_x,FWHM_y)` |
| `0.005 ≤ sharpness ≤ 0.85` | — | 排除过于弥散或单像素尖峰 |
| `footprint_pixels ≥ 2` | — | 孔径内至少有两个像素超过 1 个局部 RMS |

边缘、孔径内掩膜、饱和、背景环有效像素不足、非正通量和低通量 SNR 都会成为拒绝标志。拒绝源不会从审计返回列表消失，而是保留 `flags` 和 `quality_passed=False`，便于解释数量差异。

### 2.6 线状结构审计

当前数据中存在跨越多个 PSF 宽度的亮线。单纯“匹配滤波 + 局部极大值”会沿亮线产生多个局部峰，若直接把这些峰当成点源，会同时抬高星点数和运动轨迹数。修正版在点源测量前对显著正残差做 8 邻域连通域分析，并对每个足够大的连通域计算 PCA 主轴：只有面积、主轴长度和主/次轴方差比同时满足条件时才标记为线状结构。

`LINE_ARTIFACT` 不是把候选从结果中删除，而是给与线状掩膜相交的候选加拒绝标志。这样“全部候选”仍能复核亮线怎样被拆峰，“可信星点”和后续 15 帧轨迹则不使用这些候选。该规则仍是当前数据的工程基线，真实拖影目标必须通过注入实验和逐帧 cutout 区分，不能仅凭“细长”一项武断删除。

`persistent` 是为了解决“源在部分帧被噪声、饱和或局部异常影响而缺测”的召回问题，不应与严格静态源混写。抽样小图中，严格静态源在 12--15 帧内保持紧凑点状；1/15 的瞬态候选大多是孤立噪声峰或偶发结构；8--11/15 的持续候选多数也保持点状，但其中低 SNR、饱和邻域和帧间质量变化仍需要星表或人工复核。因此程序和答辩材料同时显示两个数字，不把 `16,187` 包装成“检测到 16,187 颗恒星”。审计目录中的 `source_track_contact_sheet.png`、`source_track_audit.csv` 和 `source_track_audit_summary.json` 是可重复抽检的证据。

这次实验还暴露了一个必须保留的边界：序列默认的 `6,000` 源上限只是配准工作集优化；上表使用 `--source-limit 0`，才可以用于全量时序对照。简单的时间均值/中值叠加不能直接代替星点检测：它会降低随机噪声，却也会让固定阈值吸收更多低幅度结构，候选数量反而上升。后续如需进一步提高弱星召回，应做注册坐标的强制测光/多帧共识检验，并同时记录注入回收率，而不是直接降低 `flux_snr` 门槛。

### 3.7 2026-08-31：3×3 PSF 支持反尖峰复测

#### 3.7.1 为什么只看旧质量规则还不够

对首帧质量表中的代表性候选做原始像素小窗抽检时，发现过一个典型反例：峰值约 260 ADU 的单像素脉冲，周围像素仍接近背景，但由于孔径内有少量随机正噪声，旧规则仍可能同时满足 `flux_snr≥5`、FWHM 范围、sharpness 上限和 `footprint_pixels≥2`。这不是“所有质量源都是噪声”的证据，却足以说明 1σ footprint 不能独立承担 PSF 真实性检查。

当前实现增加 `psf_support_pixels`：在候选峰周围 3×3 原始残差核心内，统计超过

```text
max(2 × local_noise, 0.1 × peak_excess)
```

的有限像素数，默认至少要求 3 个。支持不足的候选仍返回，但带 `INSUFFICIENT_PSF_SUPPORT`，不进入 `quality_sources`。这个规则不改变孔径测光，只增加一条形态证据；因此候选数不会因该规则减少，质量层会减少。

#### 3.7.2 当前首帧与 15 帧结果

同一首帧、同一 `4σ / min_distance=4 / aperture_radius=4 / PSF FWHM=3 / flux_snr≥5` 参数下，当前复测为：

| 指标 | 最新值 | 旧值/说明 |
| --- | ---: | --- |
| 候选峰 | `53,482` | 与加入支持审计前相同 |
| 返回候选 | `53,482` | 没有显式 `max_sources` 截断 |
| 质量通过 | `23,627` | 加入支持审计前为 `25,943` |
| `INSUFFICIENT_PSF_SUPPORT` | `11,201` | 与其他拒绝旗标可重叠 |

#### 3.7.3 人工自检结论

当前输出目录 `tmp/source-quality-audit-psf3/` 的源级接触表显示，孤立单像素尖峰被放入拒绝层；`tmp/sequence-source-audit-psf-support/source_track_contact_sheet.png` 显示严格静态样本多数在 12–15 帧保持紧凑点状，1 帧瞬态多为孤立噪声或偶发结构，而持续候选仍混合低 SNR 暗星与固定热点。故当前报告采用三层措辞：候选峰用于召回审计，严格静态用于高置信星场，持续候选只作为低置信补充；在获得星表或人工逐星标签前，不把 `16,187` 写成真实恒星总数。

源级表的支持分层也用于防止“质量数被一条规则黑箱改变”：通过质量规则的 `23,627` 个源中，`22,631` 个达到 `support_3x3≥4`，`17,693` 个达到 `support_3x3≥5`，但正式默认仍使用最低 `≥3/9`，因为更高支持要求可能继续损失弱星。所有 `quality_passed=True` 的行都满足支持下限；`support_3x3=0/1/2` 的候选仍能在 `source_catalog.csv` 中按 `INSUFFICIENT_PSF_SUPPORT` 找到。这个分布是形态审计，不是逐星真值标签。

另外用首帧亮且孤立的质量源提取经验 PSF 做了一轮模型敏感性实验。需要修正一处历史口径：旧实验目录 `tmp/real-background-empirical/` 使用的是筛选逻辑修复前的 `64` 个模板源（中位 FWHM `1.934 px`、核和 `3.288`），不能作为当前模板的有效样本统计。修复后，模板构造器要求源通过质量层，并用完整候选表检查邻近污染；首帧当前得到 `20` 个干净孤立模板源，中位测得 FWHM `2.497 px`、中位椭圆率 `0.068`、核和 `3.647`。同一截图局部用该经验核做单/双源拟合，原始掩膜下为 `ΔBIC=-3.13`、次分量 SNR `1.36`；屏蔽极端范围码后为 `-4.01`、`0.98`；同时屏蔽 `-1` 与极端范围码后为 `-4.04`、`0.94`。三组都远低于 `ΔBIC≥10` 且次分量 SNR `≥5` 的双源确认线，说明此前的“两个框”对 PSF 形状选择并不敏感：第二框更像异常值域污染下的非高斯主亮斑被宽筛拆出的提案。

这次复核还发现一个可复现的工程—科学交界问题：若只把 `quality_sources` 传给经验 PSF 构造器，质量未通过但仍位于附近的候选不会参与隔离检查，拥挤污染可能被误吸收进模板。因此真实背景注入入口已改为传入完整候选表，由构造器内部同时执行质量筛选和全候选邻域排除。修复后的实验表写入 `tmp/real-background-empirical-clean/real_background_injection.csv`；在首帧真实背景、`hybrid + FWHM=2 px`、每档 8 个注入源的单次试验中，经验 PSF 的质量召回为 `12/16/24/36/56/84/128 ADU = 0/0/0/0/0/0.25/0.625`。这不是最终完备率，只说明模板选择、总通量归一化和质量层之间存在可测模型不确定性；空间变 PSF、留出模板源和重复试验仍需后续完成。

#### 3.7.5 注册中值“降噪后直接数峰”的反例

为确认 15 张图的共同信息是否能够直接替代逐帧检测，另做了一次注册中值原型：使用当前 15 帧累积平移，把每帧背景归一到同一基线后取时间中值，再以与单帧相同的 `4σ / min_distance=4 / PSF FWHM=3 / flux_snr≥5 / PSF 支持≥3/9` 规则检测。原型的堆叠噪声约 `4.138 ADU`，但得到 `64,573` 个候选峰和 `41,154` 个质量源，均高于单帧的 `53,482 / 23,627`。

这不是程序把噪声“处理坏了”，而是一个必须保留的实验边界：中值叠加降低随机噪声，也同时保留固定热点、固定图样、背景结构和所有静态低幅信号；如果仍用原有固定 sigma 门槛，更多结构会一起进入候选。它还会改变点源的 PSF 形状和孔径通量口径，不能直接拿堆叠质量数与单帧质量数比较。当前因此不把“注册中值图直接检测”接入正式星点数；15 帧共同信息只通过逐帧质量源的出现帧数、配准坐标抖动、直线拟合和独立星表匹配进入可靠性分层。后续若要使用堆叠，只能在堆叠上发现弱源后回到每帧做强制 PSF 测光，并用已知注入源验证完备率和误检率。

## 4. 为什么不能把外部 18,000 当答案

旧项目对同一首帧使用 DAOStarFinder、FWHM=3、排除边缘和 shape 过滤，在阈值约 50×MAD 时得到 8,511 个源；旧代码的“星等”还是峰值 SNR 代理量。当前直接原始局部峰值基线在 4σ 下可达到 83,233，主要因为检测对象、阈值尺度、坏像素处理和后续形状/光度筛选完全不同。

结构过滤前的历史对照是 30,266 个质量通过源；启用线状审计后的同口径结果是 30,195 个。两者都不是已经证明的物理恒星数，也不是向 18,000 靠拢后的数字。若将某个外部示例数字写入参数，就会把验证目标和结果混为一谈。正确做法是：

1. 以本记录的定义输出候选峰和质量通过数；
2. 用合成注入实验测召回率、误检率和质心误差；
3. 用可靠 WCS/星表给通过源做身份核验，并保留未匹配原因；
4. 用人工抽检或主办方标注确认固定图样/热像素是否被误计；
5. 只有在上述验证完成后，才把某个数量写进正式比赛结论。

## 5. 15 帧关联的证据链

序列代码 `src/rst19/sequence.py` 按以下顺序工作：

```text
单帧质量源
  → 高 SNR 源互相最近的一对一匹配，估计相邻帧全局平移
  → 扣除累积平移得到配准坐标
  → 逐帧唯一关联
  → 轨迹出现帧数、总位移、线性拟合 RMS
  → static / moving / transient
```

默认 15 帧要求轨迹至少出现 `ceil(0.8×15)=12` 帧；只有总位移不少于 2 px 且直线拟合 RMS 不超过 0.75 px 才判为 `moving`。这个阈值是当前图像像素坐标中的工程基线，不能在没有像元角尺度和时间间隔时直接写成角速度或真实轨道速度。

本轮严格序列实验使用线状审计、`min_distance=4`、`4σ`、PSF FWHM=3、`flux_snr≥5`、PSF 支持 `≥3/9`、轨迹至少出现 `12/15` 帧、总位移至少 2 px、点轨迹拟合 RMS 不超过 0.75 px，并已在本地真实 15 帧上完成。当前结果为 9,938 条严格静态点源轨迹、6,249 条低置信持续候选、0 条点源 `moving` 轨迹和 60,750 条瞬态点源轨迹；独立线状层得到 1 条连续第 9–15 帧的 `moving` 候选，以及 1 条仅出现在第 1 帧的单帧候选。使用注册时间中值差分后，连续线状候选按实际时间拟合的像素平面速度约 37.829 px/s、位移约 340.689 px、图像坐标方向约 −42.216°、拟合 RMS 约 2.213 px；它仍没有主办方目标真值、像元角尺度、WCS 和运动目标注入回收率支持，不能直接写成 1 个真实运动目标。线状层使用独立的几何拟合门槛（当前 FWHM=3 时拟合 RMS ≤ 4.5 px），不能把点轨迹的 0.75 px 门槛误套到线状目标上。

需要特别区分历史记录：旧结果中的 24,426/19,061 和 15 帧、2.139 px 等数字来自不同参数或旧版实现，不能与本轮结果做单因素“算法变好/变坏”的比较。本轮 `min_distance=4`、互相最近的一对一配准、点源质量层和线状审计层均已固定在结果报告中。

## 8. 真实 FITS 背景注入-回收实验

为检验合成均匀背景与比赛图像之间的差距，新增真实首帧背景实验。实验先在未注入的首帧上运行一次完整检测，记录基线候选数和质量数；随后只在内存副本中叠加 Gaussian PSF。注入位置由固定随机种子生成，并同时满足以下控制条件：

1. 距离基线候选源至少 12 像素；
2. 距离同一批注入位置至少 12 像素；
3. 局部窗口的 98 分位超额不超过局部噪声与全局噪声的 3 倍；
4. 距离图像边缘至少 14 像素。

因此这是一项“真实背景、人工 Gaussian 源、相对空白窗口”的完备率实验，不是完整的真实恒星真值评测。注入测试保留原始 FITS 的 int16 边界/零值掩膜口径；测试图像虽然需要转为浮点以内存叠加源，但显式继承基线检测器的饱和和零值参数，避免实验与序列基线发生 dtype 口径漂移。

| 128 | 8 | 1.000 | 1.000 | 53,435 | 23,635 |

结果表明，在当前首帧的相对空白窗口和 Gaussian FWHM=3 像素假设下：

- 候选层从 16 到 24 ADU 迅速进入高召回区，本次 8 源试验在 24 ADU 时达到 1.000；
- 质量层明显更严格，24 ADU 为 0.375，36 ADU 为 0.875，56 ADU 后达到 1.000；
- 这解释了为什么候选峰数可以保持在 5.3 万量级，而可信点源数显著更低：大量弱候选在通量 SNR、形状、局部有效性或线状审计阶段被拒绝；
- 注入区域外的背景检测数约为 53,427 个候选和 23,627 个质量源。它们是原图中尚未建立真值身份的背景检测，不应直接叫作 false positive；
- 注入后全图候选数的净变化出现约 -65.5 到 -52 ADU 的负值，原因是每次检测会重新估计全图背景和噪声，不能把这个净变化当成注入源数量变化。注入源是否被找到，应以已知注入坐标附近的一对一回收结果为准。

本实验比均匀噪声实验更接近真实数据，但仍不能替代完整 precision/false-positive 评测。当前局限包括：只使用首帧、只使用 Gaussian 而非实测 PSF、只覆盖相对空白窗口、每档只有 32 个真值源，尚未覆盖边缘、密集星邻域、零值邻域、饱和邻域、空间变 PSF 和真实长线污染。后续应把注入位置分层，并增加实测亮星 PSF、椭圆 PSF 和不同背景区域的重复实验。

### 8.1 实测 PSF 对照实验（当前 PSF 支持口径）

#### 3.7.6 PSF 相关系数只作为审计，不作为硬拒绝

针对“PSF 支持仍可能放过形状异常源”的疑问，另在首帧每个质量源的 7×7 原始残差窗中计算了 Gaussian FWHM=3 像素模板相关系数，并抽取低相关、临界相关和高相关小图。低相关样本中确实有一部分像噪声或邻近结构，但也有多个清晰的紧凑亮星；原因可能包括实测 PSF 比 Gaussian 更窄、亚像素采样、源重叠、局部背景梯度和长线旁瓣。若直接设 `correlation≥0.52`，离线首帧会减少约 249 个当前质量源，但没有星表或人工真值证明这些源应被拒绝。

因此相关系数当前只保留为下一轮模型诊断，不进入 `quality_passed` 的默认判定。小图输出在 `tmp/psf-correlation-audit/contact_sheet.png`，其用途是检查“一个指标是否把真实星像误伤”，不是提供真值标签。后续只有在同总通量注入、实测 PSF 留出验证和星表匹配同时支持时，才考虑把它变成可配置的形态置信度门槛。

## 8.3 质量拒绝原因与空间均匀性诊断

### 8.4 特殊亮点复核：同样的 SNR 可能对应不同物理解释

用户截图中出现 `ID 67837 | FSNR≈14` 的亮点。截图是渲染后的局部图，缺少原始 FITS 文件名、完整 ADU 小窗、局部 RMS、PSF 拟合残差和 15 帧记录；`ID` 也只是某次运行内的候选编号。因此本记录不把该截图直接判为噪点或恒星，而是将其登记为“高显著性待复核候选”。

在当前首帧 `tmp/source-quality-audit-v2/` 的独立源级审查中，已经找到同一问题的本地反例：

| 审查 ID | `flux_snr` | FWHM / px | 椭圆率 | sharpness | 旗标 | 当前解释 |
| ---: | ---: | ---: | ---: | ---: | --- | --- |
| 24415 | 15.46 | 2.31 | 0.168 | 0.263 | 无 | 形状紧凑、通过质量层的点源对照 |
| 34636 | 12.50 | 2.93 | 0.007 | 0.253 | 无 | SNR 较低但形状规整，说明不能只按亮度排序 |
| 51935 | 14.47 | 1.75 | 0.063 | 0.859 | `SPIKE` | 与截图 SNR 同量级，却因尖峰形态被拒绝 |
| 8457 | 74.17 | 0.86 | 0.126 | 0.955 | `MASKED\|SPIKE` | 更高 SNR 仍可能是极窄伪影 |
| 753 | 807.04 | 4.17 | 0.430 | 0.057 | `LINE_ARTIFACT` | 极高 SNR 的细长结构，不应作为普通点源 |

该表不能给截图 ID 67837 赋予其中任何一行的身份，但它证明了一个方法学事实：SNR 只能回答“相对当前误差模型有多显著”，不能独立回答“是不是恒星”。[Hroch](https://arxiv.org/abs/astro-ph/0002435) 讨论了噪声、坏列、热像素和宇宙线与星点可能具有相近强度，并指出 sharpness/shape 的区分作用；[van Dokkum](https://arxiv.org/abs/astro-ph/0108003) 进一步说明边缘形态对宇宙线审计有价值；[2MASS 可靠性说明](https://www.ipac.caltech.edu/2mass/releases/allsky/doc/seca5_1.html) 则把真实源、噪声越阈、亮星伪影、宇宙线、流星轨迹和热像素作为不同可靠性来源处理。

#### 8.4.1 SNR 的统计边界

标准正态分布中，单侧 4σ 尾概率约为 `3.17×10⁻⁵`。将 `4096²` 像素粗略视为独立检验，期望正向越阈约 `531` 个；历史负峰对照为 `515`，可作为噪声尾部的数量级检查。但匹配滤波、局部极大值和 NMS 让像素相关，真实有效试验数并不是像素总数，所以不能把这个数直接当成全图假星数。

如果截图中的 `FSNR≈14` 经过正确标定，理想独立高斯噪声产生该显著性的概率约为 `7.8×10⁻⁴⁵`；这足以强烈反对“纯白噪声偶然峰”的解释，却仍不能排除误差低估、热像素、宇宙线、饱和邻域和线状结构。论文中要把它写成“反对纯随机噪声的强证据”，而不是“真实恒星概率 100%”。匹配滤波的前提和非理想边界可参见 [Lang 和 Hogg](https://arxiv.org/abs/2012.15836)、[Vio 和 Andreani](https://arxiv.org/abs/2107.09378) 以及 [Zackay、Ofek 和 Gal-Yam](https://arxiv.org/abs/1601.02655)。

#### 8.4.2 四层证据和复核动作

当前建议将亮点分成以下四层，而不是用单个 SNR 硬切：

```text
E1  局部正峰 / SNR 达到候选门槛
E2  E1 + PSF 支持、形状、边缘、掩膜和饱和审计通过
E3  E2 + 15 帧注册坐标中重复出现且质心/通量稳定，或通过有残差约束的星表匹配
E4  E3 + 注入回收、负向对照、独立标定或人工真值验证
```

`quality_passed` 目前最多近似 E2；严格静态轨迹是 E3 候选，仍不是逐星真值。对截图候选，必须回到原始帧检查：

1. 原始 ADU 小窗、局部背景/RMS 和 `peak_snr / flux_snr / filter_snr`；
2. FWHM、椭圆率、sharpness、footprint、`support_3x3` 和全部 flags；
3. 经验/分区 PSF 残差、径向轮廓和模板相关性；
4. 15 帧 detector 坐标与注册坐标的出现次数、质心散布和通量散布；
5. 负峰/空白区对照、固定坏列/热像素/饱和/长线邻近关系；
6. WCS 星表匹配的唯一性、像素残差和光度残差；
7. 同局部背景、同位置分层的人工源注入回收率。

更多判别依据、文献综述和答辩措辞见 [亮点真实性与伪影判别研究](./亮点真实性与伪影判别研究.md)。

## 8.5 多算法宽筛选—细筛选首轮结果

当前实现保留 Gaussian 匹配滤波作为提案 A，并加入窄/宽两个尺度的 DoG 提案 B。不同提案先按像素半径合并，保留 `proposal_methods`、`proposal_scales` 和 `proposal_snr`，再统一回到原始 FITS 做测光与质量检查。DoG-only 候选若靠近 Gaussian 主峰，先标记 `UNRESOLVED_BLEND`；随后比较“背景平面 + 单 Gaussian PSF”与“背景平面 + 双 Gaussian PSF”，只有 `ΔBIC≥10` 且新增分量幅度 `SNR≥5` 才解除混叠标志。该局部检验是第一版可解释去混叠，不等于已经完成空间变经验 PSF 的全场联合拟合。

### 8.5.1 处理边界

```text
A/B/C 各自提出候选
  → 同一帧半径聚类/NMS 去重
  → 保存候选来源、检测尺度和算法命中数
  → 对候选并集统一回到原始 FITS 测光
  → PSF/形态/尖峰/线状/掩膜/边缘/饱和细筛
  → 15 帧配准坐标与 detector 坐标确认
```

候选并集的目标是高召回，不是直接得到最终星数。`N_wide`、`N_fine`、`N_temporal` 和 `N_catalog` 必须作为四个不同量保存。算法一致命中可以作为软证据，但不能抵消明确的 `SPIKE`、`LINE_ARTIFACT`、`MASKED`、`SATURATED` 或 `INSUFFICIENT_PSF_SUPPORT` 标志；算法分歧也不应静默删除，而应保留为待审计层。

### 8.5.2 第一轮对照矩阵

| 对照组 | 候选方法 | 预期补充能力 | 目前状态 |
| --- | --- | --- | --- |
| A | 当前 Gaussian matched filter，固定 FWHM 基线 | 与现有结果连续，可复现当前 `candidate_count` | 已实现 |
| B | 双尺度 DoG 局部响应 | 补充固定 Gaussian 未提出的紧凑峰，并保留尺度来源 | 已实现并运行；未证明对孤立标准 PSF 提高召回 |
| C | à trous/Starlet 两尺度响应 | 在不同背景尺度下提供不依赖单一 Gaussian FWHM 的候选 | 已实现并运行；当前同坐标实验未证明优于 hybrid，保留为实验模式 |
| D | 局部阈值 + 连通域 | 检查非圆点源、弱扩展结构和线段被如何提出 | 可作为诊断对照，未纳入最终计数 |

| F | 配准差分、强制测光、Hough/RANSAC | 从 15 帧中提议运动轨迹并排除静态星场 | 当前只有平移关联基线，待扩展 |

### 8.5.3 必须保存的源级字段

每个候选在合并前后都要保留可追溯字段，避免“多个算法最后只剩一个 ID”：

```text
method_name / method_hits / detection_scale
candidate_id / merged_id / frame_index
x_peak / y_peak / x_centroid / y_centroid
peak_snr / filter_snr / flux_snr
fwhm_x / fwhm_y / ellipticity / sharpness / support_3x3
psf_residual / psf_correlation / delta_bic（如已校准）
flags / fine_status / temporal_status
injection_truth_id（若为注入样本）
```

其中 `method_hits` 只表示检测器是否提出过该候选，不是“算法投票得到的真星概率”；`delta_bic` 在没有校准 null 分布前只能作为模型比较诊断字段。

### 8.5.4 评价指标

对每个算法、候选并集和细筛结果分别报告：

| 指标 | 计算方式 | 解释 |
| --- | --- | --- |
| 宽筛选召回率 | 被匹配回的注入源 / 注入源总数 | 首要目标，按通量、FWHM、背景和位置分层 |
| 细筛精确率 / 源级 FDR | 细筛真源 / 细筛总源，或 false discoveries / discoveries | 判断算法是否把噪点和伪影送入质量层 |
| 重复计数率 | 合并前同一真源候选数及重复比例 | 检查多尺度响应造成的重复 |
| 分裂/合并率 | 一个真源被拆成多个或多个源被并成一个的比例 | 特别关注拥挤区和线状结构附近 |
| 伪影泄漏率 | 尖峰、热像素、线段、边缘样本通过细筛的比例 | 直接对应当前“全标注/误标注”问题 |
| 完备率曲线 | 回收率随注入通量、局部 RMS 和位置变化 | 不能只报告一个总召回率 |
| 质心误差与通量偏差 | 检测位置/测光值相对注入真值的误差 | 判断降噪、滤波和 PSF 失配的代价 |
| 运行时间/内存 | 各阶段耗时、候选数量和峰值内存 | 防止宽筛选把昂贵 PSF 拟合扩大到全图 |

### 8.5.5 真实数据、阴性数据和注入数据要分开

1. **真实 FITS**：用于记录候选规模、空间分布、算法交集和人工抽检，不把任何一类自动标为真值。
2. **真实背景注入**：在原始背景空白区和非空白区注入实测/合成 PSF，提供已知位置、通量、形状和运动速度的真值。
3. **阴性对照**：使用负峰、空白区和已知尖峰/线状区域，测量在没有正向点源时各算法产生多少候选；负峰不能覆盖只出现在正方向的热像素和宇宙线，所以不能单独使用。
4. **人工标签/星表**：用于独立验证和阈值校准；星表匹配是身份和几何证据，不替代图像内完备率。

本轮专门新增同坐标比较器，使 Gaussian、hybrid 和 ensemble 消费同一张背景、同一组注入坐标和同一套细筛规则。否则差异会混合随机位置和算法效应。ensemble 在 Gaussian + 双尺度 DoG 之外增加 B3-spline à trous 的第 1、2 层 Starlet 系数；所有附加提案仍须回到原始 FITS 接受同一套测光、PSF 支持、形状、掩膜、线状与 BIC 细筛。相关方法边界见 [亮点真实性与伪影判别研究](./亮点真实性与伪影判别研究.md) 第 10 节。

### 8.5.6 2026-08-31 同坐标对照结果

首帧全图在 `4σ / min_distance=4 / FWHM=3 / flux_snr≥5` 下：Gaussian 为 `53,482` 个候选、`23,627` 个质量源；hybrid 为 `61,585` 个候选、`24,131` 个质量源。hybrid 新增 `8,103` 个 DoG-only 审计候选，但最终只增加 `504` 个质量源，其中 `247` 个是经双 PSF 证据解除混叠的近邻候选，其余是与 Gaussian 候选距离不近的 DoG-only 候选。整帧参考运行时间约从 `22 s` 增至 `40 s`；这是 `FWHM=3` 的历史性能对照，不能直接决定当前 GUI 默认。2026-09-02 起 GUI 使用 `hybrid + FWHM=2 px`，Gaussian 仍作为严格基线。

公平注入不是分别随机选位置，而是在同一图像副本、同一坐标注入后分别运行两种模式。四个 `1024×1024` 真实背景裁块、每块 8 个孤立 FWHM=3 px 源，在 `12/24/56 ADU` 三档中两种模式的候选与质量召回完全相同，而 hybrid 候选总量增加约 `14%–17%`。改变注入 FWHM 为 `1.2/2.0/4.5/6.0 px` 后，本轮孤立源召回仍未出现差异。因此不能以“候选更多”证明暗星召回更高。

拥挤双源采用相同背景、相同坐标和成对注入。分离 `3–4 px` 时两种方法都主要把一对合并成一个源，`5 px` 未观察到稳定优势；分离 `6 px`（约 `2×` 检测 FWHM）、4 次重复、每档共 48 个注入源时：

| 峰值超额 / ADU | Gaussian 候选召回 | hybrid 候选召回 | Gaussian 质量召回 | hybrid 质量召回 |
| ---: | ---: | ---: | ---: | ---: |
| 24 | 0.833 | 0.833 | 0.042 | 0.042 |
| 36 | 0.875 | 0.917 | 0.479 | 0.479 |
| 56 | 0.917 | 0.958 | 0.917 | 0.958 |
| 84 | 0.938 | 0.979 | 0.938 | 0.979 |

结论限定为：当前 DoG + 双 PSF/BIC 细筛对足够亮、约 6 px 分离的近邻双源产生约 `4.2` 个百分点的回收提升；对孤立源、极近双源和低亮度双源没有已证实收益。负向反相图在 DoG 原始正峰门控后由 `25,551` 个候选降至 `1,426` 个，质量层只剩 `1` 个，说明统一细筛能压制绝大部分负向环响应，但这不是对热像素、宇宙线和正向固定图样的完整误检率。原始结果见 `tmp/source-audit-hybrid-v3-samples/`、`tmp/proposal-mode-comparison-crops/` 和 `tmp/proposal-mode-comparison-pairs/sep6-repeat4/`。

### 8.5.7 2026-09-01 Starlet 第三提案实验

ensemble 模式采用 B3-spline 核 `[1,4,6,4,1]/16` 的 à trous 平滑，构造 `w1=c0-c1` 与 `w2=c1-c2` 两个尺度。实现对掩膜做归一化卷积，要求原始像素同时为局部正峰，并把 `starlet_s1/starlet_s2`、尺度和响应 SNR 写入候选来源。Starlet 只负责宽筛；它没有独立降低通量 SNR、3×3 PSF 支持或伪影规则。

首帧全图的快速提案阶段耗时与候选规模为：Gaussian `3.79 s / 53,532`，hybrid `7.68 s / 61,656`，ensemble `11.06 s / 66,108`。完整原图细筛后，ensemble 为 `66,048` 个候选和 `24,275` 个质量源；相对 hybrid 增加 `4,463` 个候选，但只增加 `144` 个质量源。新增质量小图中既有貌似紧凑弱点，也有亮星邻域和接近空白的响应，不能把这 `144` 个直接称为新增恒星。

同坐标对照没有发现 Starlet 相对 hybrid 的回收增益：

- 真实背景 `1024×1024` 裁块、每档 16 个孤立源时，`12/24/56 ADU` 的 Gaussian/hybrid/ensemble 候选召回分别同为 `0.25/1/1`，质量召回同为 `0/0.3125/0.9375`；ensemble 候选量比 hybrid 约多 `6.5%`。
- FWHM=`1.2/2.0/4.5/6.0 px` 的 56 ADU 注入中，三种模式召回一致；当前 Starlet 没有修复极窄源的质量失败。
- 拥挤双源分离 5–6 px 时，hybrid 已相对 Gaussian 提升的档位，ensemble 与 hybrid 完全相同；没有额外去混叠收益。
- 将真实图反相并保留原零值掩膜后，Gaussian/hybrid/ensemble 分别产生 `458/1,801/1,916` 个候选，但三者最终都只剩 `2` 个质量源；说明统一细筛能大量压低 wavelet 环响应，同时也说明宽筛候选增加本身不等于可靠性增加。

因此当前产品决策是：Gaussian 仍为默认快速模式；hybrid 是已有同坐标证据支持的拥挤深筛；ensemble 作为可审计的小波实验模式保留，不写成“更先进所以更准”。只有在更大规模实测 PSF 注入、正向热像素/宇宙线阴性集、人工标签或星表确认中出现可复现的分层召回提升后，才考虑将 Starlet 纳入正式星数口径。原始输出位于 `tmp/source-audit-ensemble-v1/` 与 `tmp/proposal-mode-comparison-starlet/`。

## 8.6 2026-09-01 局部坏像素容错与三模式 15 帧抽测

本轮在代码加入了一个有边界的局部坏像素策略：对整型图像自动识别的精确 `0`，如果候选中心有效、圆孔径仍保留至少 `80%` 且不少于 `9` 个有效像素，则源只增加 `PARTIAL_MASKED` 说明而不被 `MASKED` 整体否决；负值、非有限值、饱和值、任意非零外部掩膜和中心被遮挡仍严格拒绝。该策略不改变原始 ADU、背景、通量或三个 SNR，只改变“孤立零值是否让整颗源退出质量层”的判定。

首帧在 `4σ / min_distance=4 / aperture=4 / PSF FWHM=3 / flux_snr≥5 / support_3x3≥3` 下的重新抽测为：

| 口径 | 候选 | 质量源 | 说明 |
| --- | ---: | ---: | --- |
| 原先严格把孔径内掩膜判死 | 58,411 | 24,641 | 历史同参数对照 |
| 精确零值局部容错 | 58,411 | 27,237 | `PARTIAL_MASKED=7,457`，其中 `MASKED` 仅剩 2 个 |
| 负值全部作为外部坏点掩膜 | 58,113 | 27,079 | 405 个负值；整体候选和质量数都略降，不作为默认 |

质量数增加不是 7,457，因为其中许多候选同时有 `LOW_FLUX_SNR`、`INSUFFICIENT_PSF_SUPPORT` 或其他标志。这个结果支持“孤立精确零值不能自动抹掉邻近真实 PSF”的工程修正，但没有证明所有零值都属于坏点；如果主办方确认零值是合法信号，可以显式关闭 `mask_zero_pixels`。

在同一组 15 张原始 FITS、同一注册/持续性/时序细筛参数下，三种宽筛提案的结果为：

| 模式 | 严格静态 | 持续候选 | 稳定/持续合计 | 候选共识通过 | 时间中值补检 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Gaussian | 5,276 | 16,263 | 21,539 | 16,134 | 8,522 |
| hybrid（Gaussian + 双尺度 DoG） | 4,617 | 21,027 | 25,644 | 20,811 | 8,063 |
| ensemble（再加两层 Starlet） | 4,214 | 22,401 | 26,615 | 22,202 | 8,309 |

这里的“稳定/持续合计”仍是算法候选，不是物理恒星真值。把各模式的轨迹中心在注册坐标中按 `3 px` 比对，hybrid 相对 Gaussian 的新增为约 `4,089` 个，ensemble 相对 hybrid 的新增为约 `982` 个；新增轨迹主要是 `candidate_consensus`，不是单帧质量源。hybrid 的候选共识审计中，达到持续帧数门槛的锚点有 `31,786` 个，最终通过 `20,811` 个；未通过的首要原因是 `PSF 支持不足 5,800`、与已有质量轨迹重叠 `4,868`、有效帧不足 `214`。ensemble 对应 PSF 支持不足升至 `7,685`。这说明多算法首先扩大了宽筛候选池，不能只凭最终数量选择模式。

当前产品口径因此保持：GUI 使用 `hybrid + FWHM=2 px` 作为偏召回的平衡默认，Gaussian 是速度优先/严格静态基线，ensemble/Starlet 只保留为实验对照。只有当相同坐标的人工源注入、正向热像素/宇宙线阴性集、实测 PSF 和可靠星表都支持分层提升，才可以把某个新增子集升级为正式星数。三种模式均通过同一套原图测光、PSF 支持、形状、掩膜、线状和跨帧审计，算法命中数本身不是投票概率。

本轮还把候选共识淘汰计数写入 `SequenceResult.candidate_consensus_audit` 和序列 JSON，并在 15 帧证据窗口显示“已有质量源重叠、PSF 支持不足、有效帧不足、形状”等主因。亮线只擦过长序列少数帧时最多允许 `20%` 的污染，整条轨迹持续被线覆盖仍拒绝；该规则在本组真实数据中没有造成可观的数量变化，保留它主要是避免一个偶发亮线把其余干净帧的稳定证据全部抹掉。

## 8.7 2026-09-01 注册稳健叠加的补漏对照

上一轮的时间中值适合压制运动目标和单帧异常，但对每帧都略低于候选门槛的稳定弱星，统计效率不如均值。为验证“先宽筛、后细筛”的下一层，新增了 `--temporal-proposal-mode`：

```text
median：原有注册时间中值，速度优先，默认
coadd ：逐像素 MAD 裁剪后求稳健均值，只作为弱星坐标提案
both  ：中值和稳健均值提案并集，召回优先、耗时最高
```

稳健叠加不是把 15 张图简单相加：每个像素先以时间中位数为中心做 `3×MAD` 裁剪，尽量去掉只在少数帧出现的亮线、宇宙线和瞬态。生成提案后仍回到每一帧原始 ADU，在预测位置做 Gaussian 强制响应、中心有效性、3×3 支持、孔径有效像素、形状、线状重叠、出现帧数和位置拟合审计。叠加图本身不进入质量星表，也不改变单帧 `flux_snr`、`m_inst` 或原始像素。

同一批真实 15 帧、`4σ / min_distance=4 / FWHM=3 / flux_snr≥5 / support_3x3≥3`、每帧源级工作集 `6000` 的对照如下：

| 时序提案 | 中值种子 | 叠加种子 | 严格静态 | 持续候选 | 稳定/持续合计 | 候选共识通过 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `median` | 29,710 | 0 | 5,276 | 16,263 | 21,539 | 16,134 |
| `coadd` | 29,710 | 30,455 | 5,276 | 16,646 | 21,922 | 16,517 |
| `both` | 29,710 | 30,455 | 5,276 | 16,898 | 22,174 | 16,769 |

相对 `median` 的注册坐标去重结果显示：`coadd` 新增约 `491` 条轨迹，`both` 在合并后新增约 `635` 条。`coadd` 新增轨迹中 `453` 条出现 15/15 帧、`32` 条出现 14/15 帧；在首帧的现有 hybrid 源表中，491 条均能在 3 px 内找到对应候选，其中 `405` 条当时通过单帧质量层，另有 `86` 条仍带低 SNR、局部掩膜或其他审计标志。这个结果支持它确实能补到一批 Gaussian-only 时序路径漏掉的稳定弱源，但不等于 491 颗新增恒星。

本轮审计还显示，`coadd` 模式的首要淘汰原因仍是 `PSF 支持不足=3,438`，其中 `valid=15、support=0` 占 `3,019`；它们虽然在多帧重复出现，却没有 3×3 核心支持，符合固定纹理/尖峰需要继续留在审计层的预期。`coadd` 最终把稳定/持续合计只提高约 `1.8%`，而不是把叠加后的 49,589 个单图质量源全部纳入，因此当前不把它偷偷改成默认星数口径。

产品决策：GUI 和 CLI 默认仍使用 `median`，界面新增“稳健叠加（召回优先）”和“两者并集（最慢）”选项；需要研究漏检时使用 `coadd`，需要最大召回对照时使用 `both`。这两个模式必须同时保存 `temporal_proposal_mode`、中值/叠加种子数和候选共识审计。正式比赛参数仍需用同坐标多帧人工源注入、正向热像素/宇宙线阴性样本、分区实测 PSF 和授权星表留出验证决定。

## 8.8 2026-09-01 时序参考 SNR 的分层抽测

仅增加 `coadd` 提案还不能回答“弱星是否在参考图中被门槛挡掉”。因此把两个 SNR 门槛拆开：`candidate_consensus_min_snr` 继续约束普通逐帧候选，`temporal_reference_min_snr` 只约束时间中值/稳健叠加产生的补充坐标。这样可以在不改变普通候选口径的情况下，单独测量多帧宽筛的召回收益。

| 普通候选门槛 | 时序参考门槛 | 严格静态 | 持续候选 | 稳定/持续合计 | `support=0` 淘汰 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 15σ | 15σ | 5,276 | 16,898 | 22,174 | 3,019 |
| 15σ | 12σ | 5,276 | 20,249 | 25,525 | 3,019 |
| 12σ | 12σ | 5,276 | 20,725 | 26,001 | 3,527 |
| 10σ | 10σ | 5,276 | 24,213 | 29,489 | 3,972 |

15σ→12σ 的“分层降低”新增 `3,344` 条注册坐标，其中 `2,947` 条出现 `15/15` 帧。对新增坐标逐帧原图做确定性抽样的近似检查中，`2,919/3,344` 条同时达到多数帧 3×3 核心支持和紧凑形态代理；这不是完整孔径测光，也不是逐星真值，只能证明新增集合值得进入人工/星表复核。作为反例，普通候选门槛一并降到 10σ 后，持续候选继续增加，但 `support=0` 淘汰也升到 `3,972`，说明“多帧重复”不能替代 PSF 支持。

## 8.9 2026-09-01 局部峰重定位与多算法宽筛复测

本轮继续抽查“漏了很多”的可能来源。检查发现，时间参考图的候选坐标经过注册后通常是亚像素位置，但旧实现直接把它四舍五入到一个整数像素，在该点做逐帧强制响应。真实星像中心落在相邻像素时，PSF 相关和 `support_3x3` 会被定位误差拖低。当前实现先在预测位置 `±1 px` 的 `3×3` 窄窗口内寻找最高匹配响应，再用该局部峰计算支持、形状和相关性；它不扩大到远处邻域，也不改变原始 FITS 或单帧测光。

本轮算法路线的文献边界也进一步明确：SExtractor/DAOPHOT 说明局部背景、RMS、检测和 PSF 测光应分层处理（[Bertin & Arnouts 1996](https://aas.aanda.org/articles/aas/pdf/1996/08/ds1060.pdf)、[Stetson 1987](https://articles.adsabs.harvard.edu/pdf/1987PASP...99..191S)）；Starlet/WAVDETECT 说明多尺度变换适合候选生成，但系数相关和边缘响应不能直接当源级概率（[Starck & Pierre 1998](https://aas.aanda.org/articles/aas/pdf/1998/05/ds6380.pdf)、[Freeman et al. 2002](https://arxiv.org/abs/astro-ph/0108429)）；Lang & Hogg 强调匹配滤波的“最优”依赖 PSF、噪声独立性和协方差假设（[Principled point-source detection](https://arxiv.org/abs/2012.15836)）。因此当前实现把多尺度/多算法放在宽筛，把原图局部测光、PSF 相关、3×3 支持和 15 帧重复性放在细筛，尚未把任何算法命中数当成概率。

源级 FDR 是下一步统计校准方向，而不是当前固定 `nσ` 的替代名称。Miller 等与 Hopkins 等说明在全图大量相关检验时，需要估计 null 分布并控制平均错误发现比例（[Miller et al. 2001](https://arxiv.org/abs/astro-ph/0107034)、[Hopkins et al. 2002](https://arxiv.org/abs/astro-ph/0110570)）。当前 FITS 存在局部 RMS、掩膜、线状结构和非高斯纹理，尚未建立经负峰、空白区和正向伪影校准的源级 null，因此代码暂不把理想 FDR 公式硬套到结果上；后续应在分区背景、实测 PSF 和注入真值上校准后，再增加 FDR 作为细筛的统计证据。

### 8.12 2026-09-02 近邻双框复核与极端负码控制

本节记录用户截图中“同一亮部被标成两个框”的可复现实验，而不是仅凭截图颜色判断。截图中心两个青色框对应首帧缓存中的 `ID 70269` 与 `ID 70320`，像素坐标约为 `(1269,3465)` 和 `(1274,3467)`，间距 `5.39 px`；同一区域上方的黄色补充候选对应 `ID 69978`，坐标约为 `(1272,3453)`。旧缓存使用 `hybrid + FWHM=2`，共有 `84,594` 个宽筛候选、`29,295` 个质量通过源。

| 候选 | 峰值 ADU | 通量 SNR | FWHM | 来源 | 本轮判断 |
| --- | ---: | ---: | ---: | --- | --- |
| 70269 | 30,884 | 82.82 | 3.91 px | Gaussian + DoG | 亮主源，仍通过质量层 |
| 70320 | 3,991 | 10.85 | 3.47 px | Gaussian + DoG | 近邻副候选，不支持独立第二星 |
| 69978 | 182 | 14.77 | 4.05 px | DoG-only | 弱而弥散的补充候选，保留待复核 |

对 `ID 70320` 的原始 `9×9` 测光孔径复查发现：中心显示值约 `3991 ADU`，但同一局部还含有 `31586` 的正码以及 `−31642/−30479` 等接近有符号 `int16` 范围端点的负码。正负极端值在孔径求和中可能抵消，使通量 SNR 看起来足够高；它不是一个可以只凭中心像素解释的干净 PSF。固定位置的单/双 Gaussian 比较在首帧 `FWHM=2 px` 下为 `ΔBIC=-2.59`、次分量 SNR `1.55`；即使临时遮掉极端负码，也只有 `ΔBIC≈3.14`、次分量 SNR `≈2.85`，均未达到本项目的 `ΔBIC≥10` 且次分量 SNR `≥5` 的双源证据线。15 帧固定位置复核也没有形成稳定的次分量证据。

旧规则仍会保留它，原因有三点：`min_distance=4` 只是候选抑制距离，不是物理去混叠；它同时命中了 Gaussian，旧版 `UNRESOLVED_BLEND` 只覆盖部分 DoG-only 情形；孔径通量和 SNR 没有检查极端负码。由此可见，“检测到两个局部响应”与“确认两颗恒星”是两个不同命题。本轮增加 `NEGATIVE_OVERFLOW`：只在有符号整型图像的测光孔径内审计低于负侧满量程 `90%` 的极端负码，不把普通负噪声全部删除，也不改写原始像素。首帧复算结果为：候选数仍为 `84,594`，质量数由 `29,295` 变为 `29,271`；`36` 个候选触发该审计，其中 `24` 个原本会进入质量层，`ID 70320` 被正确移出质量层。

这条规则是数据有效性防线，不等同于相机满阱或 ADC 的物理标定。取得主办方的原始数据格式、满阱、增益、偏置和坏点说明后，仍需重新标定阈值。对不同特征星的筛查顺序固定为：孤立紧凑源先看 PSF/形状；弱源再看局部背景和源级 SNR；近邻源必须做单/双 PSF；亮饱和或极端负码源先做范围审计；线状、边缘和掩膜区域单独标志；最后用 15 帧注册稳定性、星表残差和人工注入回收决定能否升级为物理恒星。`ID 69978` 目前只到“待复核候选”，不能因为它没有极端负码就直接判为真星。

### 8.13 2026-09-02 固定 `-1` 像素与数组类型的控制实验

| 局部掩膜 | `ΔBIC` | 次分量 SNR | 是否支持双源 |

### 8.14 2026-09-02 首要特征类别审计

此前的 `flags` 是完整拒绝原因集合，允许重叠，适合查“一个候选为什么被拒绝”，但不适合直接做类别构成统计。本轮在 `rst19-sources` 中增加互斥的 `feature_class`：按“数据范围 → 线状 → 边缘/掩膜 → 拥挤 → 尖峰/PSF 支持 → 弱通量/背景 → 形状 → 质量通过”的固定优先级给每个返回源一个首要类别；原始 `flags` 和 `quality_class` 不变。

当前 GUI 默认口径（首帧 `hybrid`、FWHM `2 px`、`4σ`、`min_distance=4`、通量 SNR `≥5`、PSF 支持 `≥3/9`）的类别审计为：

结果保存在 `tmp/stratified-real-background-gui-default/stratified_real_background_injection.csv`、同名 JSON 和 PNG。CSV 还保存每个分层位置的坐标、局部统计、特殊值域比例和基线邻源信息；`ambiguous_injection_count` 大于零时不得把该行解释成孤立点源完备率。实验仍没有提供真实 FITS 的逐星 precision、FDR 或天球身份；这些必须由授权星表/WCS、阴性样本和更大规模分层注入共同完成。

### 8.28 2026-09-02 扩大真实背景分层样本：从机制探针到条件对照

为避免把上一节每格 2 个位置的结果误当作稳定比例，沿用相同的首帧、GUI 默认 `hybrid`、经验 PSF 和 `24/56/128 ADU` 三档，将普通条件扩展为每格 8 个位置、1 个 trial；线状邻域另行扩展为每格 8 个位置。仍然没有逐星真值，所以这里的“召回”只针对已知注入源，并按 3 px 直接匹配半径排除不能独立归因的位置；`ambiguous` 是更宽的 8 px 基线邻域标记。

| 条件层 | 局部背景 / RMS（ADU） | 严格新增候选召回（24 / 56 / 128） | 严格新增质量召回（24 / 56 / 128） | 8 px 邻源歧义 | 严格分母 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `blank` 低纹理 | `20.9 / 5.6` | `0 / 1 / 1` | `0 / 0 / 0.625` | `0/8` | `8/8` |
| `high_background` 高局部噪声 | `25.1 / 10.0` | `0.25 / 0.875 / 1` | `0 / 0 / 0.5` | `0/8` | `8/8` |
| `edge` 边缘截断 | `18.2 / 7.6` | `0 / 0.875 / 1` | `0 / 0 / 0` | `0/8` | `8/8` |
| `crowded` 拥挤邻域 | `29.6 / 13.2` | `0 / 0.375 / 0.75` | `0 / 0.125 / 0.5` | `8/8` | `8/8` |
| `special_code` 特殊值域邻域 | `89.8 / 67.8` | `n/a` | `n/a` | `8/8` | `0/8` |
| `line` 线状伪影邻域 | `907.8 / 1077.7` | `0 / 0 / 0` | `0 / 0 / 0` | `8/8` | `8/8` |

为把“注入多亮”与“局部噪声多大”放在同一尺度上，定义一个只用于诊断的局部峰显著性比 `Q_peak=A_inj/R_local`，其中 `A_inj` 是注入峰值超额，`R_local` 是注入前局部 RMS；它不是孔径 `flux_SNR`，也不是源级后验概率。各层三档 `Q_peak` 约为：`blank=4.3/10.1/23.0`、`high_background=2.4/5.6/12.8`、`edge=3.2/7.4/16.8`、`crowded=1.8/4.3/9.7`、`special_code=0.35/0.83/1.89`，`line=0.02/0.05/0.12`。这个量揭示了一个重要边界：`edge` 在 128 ADU 时局部峰显著性并不低，却仍然 `0/8` 通过质量层，说明边缘损失不是噪声显著性单独造成的；`line` 的注入峰值甚至低于结构 RMS，点源回收为零具有可解释的条件原因。

扩大样本后，出现了三个比小样本更可靠的条件性现象。第一，`blank` 在 56 ADU 已达到 `8/8` 候选回收，但质量层仍为 `0/8`；在 128 ADU 才达到 `5/8`，说明“被宽筛看见”和“像一个合格点源”之间存在明显间隔。第二，`high_background` 在同一峰值下的候选召回低于 `blank`，而 `edge` 虽然在 56/128 ADU 可以被候选层找到，质量层始终为 `0/8`，支持局部 RMS 与孔径/PSF 完整性是两个不同损失来源。第三，`crowded` 的候选/质量召回均低于空白层，即使把 8 px 邻源标成歧义，8 个位置仍都避开了 3 px 直接匹配半径；这更像邻源混合和峰分裂造成的可检出性下降，而不是简单的 SNR 不足。

`special_code` 不能写成“召回率为 0 的孤立样本”：8 个位置全部落在基线候选的 8 px 邻域内，严格新增分母为 `0/8`；其局部 RMS `67.8 ADU` 也远高于普通背景。它只能作为“异常值域与候选共位时的污染控制”，不能用于估计特殊值域附近的恒星完备率。`line` 则在 8 个位置都距线状候选超过 3 px、但仍处于 8 px 邻域；三档均无新增回收，说明当前点源检测器在强线残差背景下几乎没有可用的点源回收能力。它不是线状运动目标的真值，也不能推出线旁没有恒星。

这组扩大样本仍只有 `1 trial × 8 sites`，不能给出正式置信区间；但它足以把“各类特征星”的差异从定性印象推进到可复现的条件对照：低纹理主要由注入峰值控制，高 RMS 降低候选显著性，边缘主要损失质量层，拥挤层需要去混叠/双 PSF，特殊值域必须先处理身份歧义，线状邻域应进入独立的残差模型。后续论文只保留这张核心表和上述机制结论，逐点坐标与局部统计留在机器可读 CSV/JSON 中。

### 8.29 2026-09-02 截图双框的最小间距消融：NMS 不是物理分辨率

为确认截图中的第二框是否只是 `min_distance` 的参数副作用，在同一首帧、同一 `auxiliary_mask`、`hybrid`、`4σ`、FWHM `2 px`、通量 SNR `≥5` 和 PSF 支持 `≥3/9` 下，仅改变候选峰最小间距：

| `min_distance` | 全图候选 / 质量 | 截图局部结果 |
| ---: | ---: | --- |
| `4 px` | `84,594 / 29,271` | 主峰 + 副峰均保留；副峰 `flux_SNR=10.85`，带 `NEGATIVE_OVERFLOW` |
| `5 px` | `80,117 / 28,382` | 主峰 + 副峰仍保留 |
| `6 px` | `73,118 / 27,109` | 仅保留主峰 |
| `8 px` | `61,324 / 24,992` | 仅保留主峰 |

两个局部峰的中心分离约 `5.39 px`，所以 `4/5 px` 不能消除它，而 `6/8 px` 可以通过非极大值抑制把副峰压掉。这个实验只证明 NMS 会改变候选账本和显示数量，不证明副峰不是恒星；若把 `min_distance` 直接调到 `6/8 px`，也可能把真实近邻双星合并。此前双源控制显示 `3 px` 易合并、`6 px` 较易分开，说明截图处在过渡区，最终判断仍必须依赖单/双 PSF、原始值域、跨帧注册和星表身份。

因此 GUI 默认保留 `min_distance=4 px` 作为偏召回的宽筛参数，把近邻响应放入 `UNRESOLVED_BLEND`/待复核队列；正式星数不能由改变 NMS 间距得到。当前复核输出来自同一检测口径，未修改 FITS 原始数据。

### 8.30 2026-09-02 真实背景等强双源间距控制

为把 `min_distance` 消融与实际“能否分开两个源”区分开，在同一首帧真实背景、同一辅助掩膜和同一组注入坐标上，注入等强 Gaussian 双源；每一对的两个源峰值相同，所以跨间距比较时每对总注入通量相同。`--sources 8` 表示 4 对双源，分别由 Gaussian、hybrid、ensemble 三种提案模式检测，结果如下：

| 双源间距 | 注入峰值 | 三种模式候选 / 质量召回 |
| ---: | ---: | ---: |
| `3 px` | `56 ADU` | `0.5 / 0.5` |
| `3 px` | `128 ADU` | `0.5 / 0.5` |
| `5 px` | `128 ADU` | `1.0 / 1.0` |
| `6 px` | `128 ADU` | `1.0 / 1.0` |

三种提案模式在每一行完全一致，说明这里的转折主要来自源间距与 PSF 重叠，而不是 DoG/Starlet 某一个算法凭空制造或消除了副峰。`3 px` 的 `0.5` 表示每对通常只恢复一个源；`5/6 px` 的高亮度 `1.0` 表示在干净等强条件下两个源可以分开。截图的 `5.39 px` 处于这个过渡区，但截图副峰并非等强干净 Gaussian 源，还带异常正负码、固定 `-1` 邻域且跨帧不稳定，所以该控制只能说明“几何上可能分裂”，不能把截图副峰升级为第二颗恒星。

结果保存在 `tmp/real-pair-separation-3px-gui-default/`、`tmp/real-pair-separation-5px-gui-default/` 和 `tmp/real-pair-separation-6px-gui-default/` 的 `proposal_mode_comparison.csv/json/png`（5/6 目录为 CSV/PNG，具体以目录内容为准）。后续还需要做强弱通量比、实测经验 PSF 和异常值域遮罩的双源控制，才能把该间距曲线用于正式完备率。

### 8.31 2026-09-03 固定总峰值超额的双源强弱比控制

等强双源只能回答“在干净、对称条件下，5--6 px 是否具有几何分离能力”，不能解释截图中主峰很亮、副峰明显较弱的情况。本轮新增 `rst19-injection --pair-flux-ratio-audit`：在同一首帧真实背景、同一批注入位置、同一双源间距 `5.4 px` 下，固定两源**峰值超额**之和 `A_p+A_s=256 ADU`，只改变 `r=A_s/A_p`。这样总峰值超额、局部背景和候选结构保持可比；这不是固定总积分通量的实验，弱源变弱造成的损失不会被误认为总峰值变化。

采用 GUI 默认提案 `hybrid`、检测/注入 Gaussian `FWHM=2 px`、`4σ`、`min_distance=4 px`、通量 `SNR≥5`、每个条件 8 对、1 个 trial。结果为：

| `r=A_s/A_p` | `A_p/A_s`（ADU） | 单源候选 / 质量召回 | 成对候选解析率 | 成对质量解析率 |
| ---: | ---: | ---: | ---: | ---: |
| `0.50` | `170.7 / 85.3` | `1.000 / 0.8125` | `1.000` | `0.625` |
| `0.25` | `204.8 / 51.2` | `1.000 / 0.500` | `1.000` | `0.000` |
| `0.125` | `227.6 / 28.4` | `0.6875 / 0.500` | `0.375` | `0.000` |

这里“成对解析”要求同一对真值分别被两个不同候选一对一命中；一个位于两源匹配半径重叠区的中间峰不会被计作两颗。8 对结果显示：当 `r=1/4` 时，宽筛仍能在 `8/8` 对中拆出两个局部响应，但质量层 `0/8` 对通过；到 `r=1/8` 时，候选层也只剩 `3/8` 对可解析。这个结果给出本文关于截图双框的关键补充：**“两个框”可以是宽筛层的局部峰分裂，而不是两个已经通过 PSF、通量和数据有效性检查的独立点源；弱峰首先在质量层失效，继续变弱后才在候选层消失。**

该实验仍是 `1 trial × 8 对`，不是正式完备率；它也使用 Gaussian 注入核，尚未覆盖分区实测 PSF、不同总通量和每个位置的多次随机重复。因此它用于解释“为什么会出现两个标记”和确定后续抽样方向，不用于给真实 FITS 估计双星比例。机器可读结果在 `tmp/pair-flux-ratio-256-gui-default-n8/pair_flux_ratio_audit.csv/json/png`，命令为：

```powershell
rst19-injection --pair-flux-ratio-audit `
  --real-fits doc/00-项目资料/原始数据/20260330163205413_9901.fits `
  --total-peak-levels 256 --secondary-ratios 0.5 0.25 0.125 `
  --trials 1 --pairs 8 --psf-fwhm 2 --min-distance 4 `
  --min-psf-support-pixels 3 `
  --out-dir tmp/pair-flux-ratio-256-gui-default-n8
```

所以当前对截图的判定仍保持三层语义：副响应在候选层真实存在；它的原始孔径被极端正负码污染且没有独立双 PSF 证据；15 帧也没有形成稳定的质量级双源。该控制加强了“不能把两个框直接写成两颗星”的证据，但没有把“附近绝对没有被污染的真实伴星”作为已证事实。

### 8.32 2026-09-03 总峰值超额与实测 PSF 对照：弱副源的两个独立瓶颈

为避免把 256 ADU 的单一结果误读成普遍规律，本轮在相同真实首帧、相同 5.4 px 双源间距、相同 4 对/条件和 1 个 trial 下，把双源总峰值扩展为 `256/512/1024 ADU`，只扫描 `r=A_s/A_p=0.5/0.25/0.125`。Gaussian 结果如下；表中“源召回”是 8 个注入真值的单源候选/质量召回，“成对解析”要求每一对真值由两个不同候选分别命中。

| 注入核 | 总峰值 | `r` | 源候选 / 质量召回 | 成对候选 / 质量解析率 |
| --- | ---: | ---: | ---: | ---: |
| Gaussian | `256` | `0.50` | `1.000 / 0.8125` | `1.000 / 0.250` |
| Gaussian | `256` | `0.25` | `1.000 / 0.500` | `1.000 / 0.000` |
| Gaussian | `256` | `0.125` | `0.750 / 0.500` | `0.500 / 0.000` |
| Gaussian | `512` | `0.50` | `1.000 / 1.000` | `1.000 / 1.000` |
| Gaussian | `512` | `0.25` | `1.000 / 1.000` | `1.000 / 1.000` |
| Gaussian | `512` | `0.125` | `1.000 / 0.625` | `1.000 / 0.250` |
| Gaussian | `1024` | `0.50/0.25/0.125` | `1.000 / 1.000` | `1.000 / 1.000` |

这组控制把“强弱比”和“总亮度”分开了：在固定 `r=0.125` 时，总峰值由 `256` 提高到 `512` 再到 `1024`，成对质量解析率由 `0` 到 `0.25` 再到 `1.0`；因此截图中第二框的消失不能只归因于 NMS 或 5.4 px 的几何距离，弱副源的有效显著性和质量层证据同样是瓶颈。反过来，`r=0.25` 在 256 ADU 时宽筛仍为 `1.0`、质量成对解析率却为 `0`，正是“两个局部峰不等于两个独立质量源”的直接反例。

再以首帧筛出的 `20` 个干净质量源构造经验 PSF（中位 FWHM `2.4966 px`、归一化核和 `3.6465`），在总峰值 `512 ADU` 下补做 `r=0.25/0.125` 对照。经验核结果分别为：

| 注入核 | `r` | 源候选 / 质量召回 | 成对候选 / 质量解析率 |
| --- | ---: | ---: | ---: |
| empirical | `0.25` | `1.000 / 0.625` | `1.000 / 0.250` |
| empirical | `0.125` | `0.875 / 0.500` | `0.750 / 0.000` |

该经验核对照不是“empirical 已经优于 Gaussian”的排名实验：当前检测器仍使用 `psf_fwhm=2 px` 的 GUI 口径，而注入核的实测中位 FWHM 约 `2.497 px`，所以它同时包含了形状/尺度失配和模板代表性不确定性。它能支持的较窄结论是：**弱副源的质量层损失对 PSF 形状和归一化并不免疫**；最终默认 PSF 仍需用匹配检测尺度、分区留出模板和更多 trial 公平比较。Gaussian 多级实验产物为 `tmp/pair-flux-ratio-multilevel-gui-default/pair_flux_ratio_audit.csv/json/png`，经验核对照为 `tmp/pair-flux-ratio-512-empirical-gui-default/pair_flux_ratio_audit.csv/json/png`。

随后把 detector FWHM 调到经验核中位宽度附近 `2.5 px` 做了单独的匹配尺度探针：经验核 `r=0.25/0.125` 的源候选/质量召回为 `1.000/0.625`、`0.500/0.500`，成对候选/质量解析率为 `1.000/0.250`、`0/0`。同尺度 Gaussian 探针为 `1.000/1.000`、`0.875/0.750`，成对为 `1.000/1.000`、`0.750/0.500`。这两次运行的基线候选会随 detector FWHM 改变，注入位置抽样也因此不保证逐点相同，不能当作严格配对排名；它只说明“把一个全局 FWHM 调到中位值”并不能自动恢复 1:8 弱副源，模板形状、积分通量归一化、子像素位置和局部背景仍需拆开控制。匹配尺度产物为 `tmp/pair-flux-ratio-512-empirical-matched25-gui-default/` 与 `tmp/pair-flux-ratio-512-gaussian25-gui-default/`。

因此本节新增一个可用于答辩的判别原则：对于近邻多峰，至少同时报告“总亮度—强弱比—PSF 模型”三维条件下的单源召回、成对候选解析率和成对质量解析率；只报告“找到了两个框”会把宽筛结构误写成物理去混叠结果。以上仍是 `1 trial × 4 对/条件` 的机制控制，不是实际双星比例、全图完备率或截图副响应的真值确认。

### 8.33 2026-09-03 固定离散积分信号的 PSF 公平对照

8.32 还存在一个容易忽视的混杂：当前 Gaussian 与经验核都按峰值归一化，但 FWHM `2 px` 的离散 Gaussian 核和约为 `4.5323`，经验核和为 `3.6465`。所以同样的峰值 ADU 并不代表同样的积分信号。对离散核 `K`，若峰值幅度为 `A`，注入小窗的积分超额近似为

```text
F_disc = A · ΣK
```

本轮给 `rst19-injection --pair-flux-ratio-audit` 增加 `--pair-signal-normalization integrated_excess`：先生成单位峰值核，再把每个源按 `F_disc` 归一化；因此亚像素位置允许有轻微峰值变化，但不同 PSF 在同一条件下的离散积分信号一致。使用首帧同一真实背景、同一布局、`5.4 px` 间距、detector FWHM `2 px`、`2 trials × 8 对`，固定总离散积分超额 `1867 ADU`，结果为：

| 注入核 | `r=A_s/A_p` | 源候选 / 质量召回 | 成对候选 / 质量解析率 |
| --- | ---: | ---: | ---: |
| Gaussian | `0.25` | `1.000 / 0.906` | `1.000 / 0.812` |
| empirical | `0.25` | `0.969 / 0.812` | `0.938 / 0.625` |
| Gaussian | `0.125` | `0.844 / 0.594` | `0.688 / 0.188` |

### 8.37 2026-09-03 截图三个位置的固定位置多源 PSF 审计

#### 目的与模型

前面的单/双 Gaussian 比较只回答“指定的两个中心是否需要第二个分量”。为进一步解释截图中为什么会出现两个框，本轮把三个候选位置一起放进同一个局部模型：

```text
P_K(x,y) = b0 + bx*x + by*y + Σ_j=1..K a_j G(x-x_j, y-y_j; FWHM=2 px)
```

其中 `K=1/2/3` 分别表示一个、两个、三个固定中心的局部 PSF；背景平面在模型间相同，源幅度 `a_j≥0` 用 NNLS 求解。模型选择量为

```text
BIC_K = n ln(RSS_K / n) + p_K ln(n)
ΔBIC = BIC_1 - BIC_K
```

`ΔBIC` 越大表示在当前这块像素和当前模型假设下，复杂模型的残差改善足以抵消参数惩罚；它不是源级概率，也不是物理身份确认。本文沿用工程确认线 `ΔBIC≥10`，并要求每个新增分量的局部幅度 SNR `≥5`，避免仅靠增加参数换取残差下降。BIC 的模型比较含义见 [Kass & Raftery 1995](https://doi.org/10.1080/01621459.1995.10476572)；固定中心的做法仍比自由位置联合拟合更弱，PSF 去混叠的背景见 [DAOPHOT](https://articles.adsabs.harvard.edu/pdf/1987PASP...99..191S)、[StarFinder](https://arxiv.org/abs/astro-ph/0004101) 和 [Hedges et al. 2021](https://arxiv.org/abs/2106.08411)。


程序对 15 帧逐帧运行 `raw`、`range_masked`、`sentinel_masked` 三种值域口径，并保存每一帧 `K=1/2/3` 的 RSS、BIC、`ΔBIC`、非负分量幅度、分量 SNR、模板相关和设计矩阵条件数。输出为 `local_multipsf_audit.csv`、`local_multipsf_audit.json` 和 `local_multipsf_bic.png`；这项审计是研究工具，不改变 GUI 默认计数。

#### 对“为什么会识别到两颗”的结论

检测器的第一层任务是寻找局部响应。截图两处响应相距 `5.39 px`，而当前 `min_distance=4 px`，所以 NMS 不会强制把它们合并；Gaussian/DoG 宽筛可以把一个异常、重叠或真实双源结构拆成两个候选。这个过程只产生两个候选 ID，并没有完成多源去混叠。第二层的固定位置模型显示：原始 15 帧没有一帧同时给出足够强的新增 PSF 分量，第三位置更没有独立分量证据；因此当前最稳妥的论文表述是：

> 该局部确实存在两个可重复提案的局部响应，但目前只能确认“候选层分解出两个响应”，不能确认是两颗独立恒星；副响应也不应被武断称为普通白噪声，因为它位于异常值域、固定 `-1` 邻域和 PSF 重叠环境中。

这解释了“程序为什么框出两处”，也解释了“为什么论文不能直接把它计成两颗”。本轮的新增发现是：F07 的 `template_correlation≈0.04`、设计条件数约 `1.04`，因此问题不像简单的两个模板完全退化；不确定性主要来自饱和/掩膜/值域和较弱新增分量，而不是仅由 `5.39 px` 的几何距离决定。该结论仍需空间变 PSF、自由位置多源联合拟合、设备级坏像素/满阱定义和官方星表验证。

#### 检测器修正及边界

新增的 `CODE_PATTERN` 规则不删除候选，只在以下三个条件同时成立时拒绝质量层：

1. 全幅同一有符号整型高位码达到工程频次线（当前首帧识别到 `3990--3993`，最小频次线为 `128`，不是设备满阱标定）；
2. 该候选的有效测光孔径同时含远离局部背景的负值（当前工程线为 `min(-1000, background-50×RMS)`）；
3. **候选峰本身的像素值就是上述重复高位码之一**（仅“孔径内含重复码”不算，否则真实亮星的饱和/溢出出血列会误触发）。

首帧同参复算为 `84,594` 个候选、`29,263` 个质量源；门控前可比结果为 `29,295`。门控接入初版曾因第 3 条缺失把 `159` 个源标为 `CODE_PATTERN`（质量数 `29,153`），其中 `147` 个峰值并非重复码、属于真实亮星被误拒；修正后 `CODE_PATTERN` 只剩 `12` 个（峰值都恰为 `3990–3993` 且紧邻更强源），质量数回到 `29,263`。截图这两个提案均保留在候选表并带 `CODE_PATTERN`，质量视图不再把它们显示成可信星点，悬浮信息可查看重复码值和异常像素数。该门控的科学含义是“数据有效性不足，暂不纳入干净点源样本”，不是“已经证明是噪点/坏点”；仍需主办方确认 signedness、`BLANK`、ADC 满阱、增益和坏像素表。

本实验的结论是：**这次识别到两颗，是 NMS 对两个相距 `4.12 px` 的局部峰都保留、而旧质量规则又被高通量和 PSF 支持指标说服；继续做原始值域和多源 PSF 复核后，当前只能保留为两个候选响应，不能报告为两颗独立恒星。**

### 8.40 2026-09-03 修正 CODE_PATTERN 对真实亮星的误拒

8.38 的 `CODE_PATTERN` 规则把“候选测光孔径内含全幅异常重复高位码 + 孔径含异常负值”作为充分条件。真实首帧复核发现该规则误伤了真实亮星：亮星的饱和/溢出出血列会同时把 `3991/3992` 等重复码和 `-20628` 这类负值带进孔径，峰值却仍是正常高亮度值（例如 `ID 24651`：峰值 `20893`、`flux_snr≈775.9`、`FWHM≈2.84`、椭圆率 `0.044`、支持像素 `4/9`），因此被错误标为数据编码伪迹并移出质量层。

修正后的触发条件改为：**候选峰本身的像素值落在全幅异常重复高位码上**、且孔径含异常负值，才判定 `CODE_PATTERN`；仅“孔径内含重复码”不再构成拒绝理由。真实首帧 `hybrid + FWHM=2` 同参复算：候选数仍为 `84,594`，`CODE_PATTERN` 由 `159` 降到 `12`（这 `12` 个峰值都恰为 `3990–3993` 且紧邻更强源），质量源由 `29,153` 升到 `29,263`；`ID 24651` 现在通过质量层。该修正只影响数据有效性门，不改变宽筛候选、孔径通量、仪器星等、PSF/形态或线状/掩膜规则；`repeated_code_count`、`range_anomaly_pixel_count`、`repeated_code_values` 仍作为可审计字段保留。8.39 的 15 帧持久性表仍是初版口径，需按本节修正后的检测器重跑。

回归测试见 `tests/test_detection.py` 的 `test_code_pattern_rejects_a_local_high_code_and_negative_pair`、`test_code_pattern_does_not_reject_bright_peak_with_bleed_codes` 与 `test_code_pattern_does_not_count_masked_negative_pixels`。

### 8.41 2026-09-03 亮星邻域“肉眼可见亮点”的跨帧噪声审计

用户在“增亮噪声 · 看弱点”显示层下，看到亮星邻域有很多肉眼可见、但检测器没有标记的亮点，怀疑存在漏检。该显示层故意把 `median-2σ` 到 `median+7σ` 的灰度区间拉伸到全屏，因此会把约 `3σ` 量级的单帧噪声颗粒也显示成可见亮点；它只用于判断“弱点是否只是颗粒噪声”，不能作为漏检证据。需要用 15 帧原始数据做配准坐标下的持久性审计，才能区分真实暗星和单帧噪声。

方法：对首帧 `ID 24651`（亮星，`1717,1342`）与 `ID 20794`（截图悬停的质量源，`1848,1142`）各自 `R=60 px` 邻域，列出原始图像 `3×3` 局部极大值中处于 `3σ–8σ` 的“肉眼可见”峰；再在 15 帧同坐标 `±2 px` 小窗内取局部峰，以局部环稳健中位数/MAD 计算逐帧显著性，持久门槛取 `≥12/15` 帧 `≥3σ`。15 帧间的全局平移已用互相关复核为 `(0,0)`（亚像素级），亮星峰位在 `±1–2 px` 内抖动，`±2 px` 搜索足以覆盖。

结果：

| 邻域 | `3σ–8σ` 可见峰 | 跨帧持久 `≥12/15` | 单帧瞬态 |
| --- | ---: | ---: | ---: |
| `ID 20794` 邻域（R=60） | 96 | 1 | 95 |
| `ID 24651` 亮星邻域（R=60） | 87 | 3 | 84 |

持久样本逐一回查检测表后发现：它们都不是被漏掉的孤立暗星——要么落在已通过质量层的亮星 PSF 翼部（如 `(1769,1324)→id 24253`、`(1756,1310)→id 24077`），要么已经被检测为候选、只是因单帧 `flux_snr<5` 或 `INSUFFICIENT_PSF_SUPPORT` 而未进入质量层（如 `(1895,1138)→id 20748`，`flux_snr≈3.4`、14/15 帧 `≥4σ`）。

**但本节原结论“肉眼可见亮点主要是单帧噪声、不是漏检的真星”是错的。** 事后用 15 帧注册中值叠加直接检测才发现：叠加把噪声从约 `7.4` 降到 `4.45 ADU`，同参数（`hybrid`、`FWHM=2`、`4σ`、`flux_snr≥5`）在亮星 `R=80` 邻域恢复了约 `51` 个峰值 `33–121 ADU`、`flux_snr 5–9` 的质量源，其中多数在单帧被 `LOW_FLUX_SNR` 拒绝。错误根源是本节用“单帧局部环显著性”做跨帧持久性判别，而亮星的 PSF 翼部抬高了局部背景/噪声，把真实暗星的逐帧显著性系统性压低，于是把真暗星误判成瞬态。单帧 `4σ→2.5σ` 时整幅质量源只 `+42`、亮星邻域质量源保持 `20`，这一“无差别调低单帧阈值没用”的结论仍然成立，但正确解释是：暗星恢复必须走**降噪叠加 + 逐帧强制测光**的路径，而不是说那些亮点是噪声。8.42 已落地该恢复层。

### 8.42 2026-09-03 叠加暗星恢复层（stack_faint）

8.41 的更正把方向指到“降噪叠加 + 逐帧强制测光”。落地实现为 `sequence.py` 的 `_stack_faint_tracks`：

1. 对 15 帧注册后的时间中值（或稳健均值）参考图，用参考图自身降噪后的噪声底，以 `4σ`、`flux_snr≥5`、`FWHM=2` 重新检测（float32 快速路径），得到“叠加候选”；
2. 与已有质量/共识轨迹按 `link_radius_px=4` 做一对一去重；
3. 对每个剩余候选回到 15 帧原始图，在预测点做 `±1 px` 局部峰强制测光、`3×3` 支持、FWHM/椭圆率形状和边缘/掩膜审计，要求出现帧数达到 `persistent` 门槛（本数据 `8/15`）且逐帧放宽 `flux_snr≥3`；
4. 通过的轨迹标为 `evidence_level="stack_faint"`、`classification="persistent"`，单独计为 `stack_faint_count`，不混入 `persistent_source_count`/`stable_source_count`/单帧 `quality_count`。

真实 15 帧同参复测（`hybrid`、`FWHM=2`、`4σ`、`flux_snr≥5`、PSF 支持 `≥3/9`、工作集 `6000`、4 worker）：

| 口径 | 数值 |
| --- | ---: |
| 单帧每帧质量源（工作集） | `5,034–5,084` |
| 严格静态 | `4,328` |
| 持续候选（不含 stack_faint） | `25,911` |
| 候选共识补检 | `25,768` |
| 叠加参考图质量源（stack candidates） | `48,920` |
| **叠加暗星 stack_faint** | **`9,814`** |
| 亮星 `ID 24651` 邻域（R=80）stack_faint | `16` |

亮星邻域的 `16` 条里包含此前单帧 `LOW_FLUX_SNR` 拒绝、但 15 帧持续存在的暗星（例如 `(1711,1350)`：单帧 `flux_snr≈2.4`，恢复后 `10/15` 帧、逐帧 `flux_snr 3.1–5.4`）。直接对中值图做检测而不做逐帧门控时，该邻域能提出约 `51` 个质量源；`_stack_faint_tracks` 在逐帧支持/形状/出现帧数门控后保留 `16`，说明这个低置信层比“中值图直接计数”更保守，仍不是官方逐星真值。

性能口径（本机、4 worker）：叠加参考图重建约 `15 s`，参考图重新检测约 `60 s`，逐帧强制测光（向量化 + 按帧并行）约 `22 s`，其余为 15 帧单帧检测与关联。全 15 帧运行由此前标量逐候选逐帧测光的约 `450 s` 降到约 `310 s`；单帧质量数、严格静态/持续候选口径不变，`stack_faint` 由 `9,857` 变为 `9,814`（`−0.4%`，来自向量化局部环估计与逐像素标量版的近边缘差异）。`--no-stack-faint` 可关闭该层；`--stack-frame-min-flux-snr`/`--stack-min-presence` 可调严。进一步加速可考虑参考图只跑 Gaussian 提案（去掉 DoG/Starlet 副通道）或按参考图 `flux_snr` 截断候选。

- [Alard & Lupton 1998, optimal image subtraction](https://arxiv.org/abs/astro-ph/9712287)：PSF/背景变化下的差分图像和变化源提案。
- [Hedges et al. 2021, Linearized Field Deblending](https://arxiv.org/abs/2106.08411)：拥挤场中的快速 PSF 去混叠。
- [Aoyeww/StarImage_SimuIden](https://github.com/Aoyeww/StarImage_SimuIden)：主办方参考路线中亮星 PSF 估计、暗目标增强和序列跟踪的公开实现入口；不把其模拟/识别输出当作本数据真值。
- [Lo et al. 2019, Hough transform for asteroid detection](https://arxiv.org/abs/1910.07146)：直线运动候选的轨迹关联参考。
