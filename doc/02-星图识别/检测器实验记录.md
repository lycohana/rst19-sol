状态：**已在本地 15 帧 FITS 上完成第一轮可复现实验；不是比赛真值**
实验日期：2026-08-28

本记录的目的不是寻找一个接近外部示例的数字，而是回答三个可检验问题：

1. 当前 8 万级结果来自随机噪声，还是来自真实信号/固定图样/伪迹？
2. 在没有官方逐星真值标注时，什么条件可以把候选峰称为“可信点源”？
3. 15 帧中哪些源是稳定星场，哪些源具有足够证据成为运动目标？

## 1. 结果定义

代码中故意保留两层数量：

| 名称 | 代码字段 | 定义 | 能否直接作为物理恒星真值 |
| --- | --- | --- | --- |
| 候选峰 | `candidate_count` | Gaussian PSF 匹配滤波后，超过阈值且经非极大值抑制的峰 | 不能；包含伪迹和低质量源 |
| 审计返回 | `returned_count` | 实际计算了局部测光属性的候选源数 | 不能；仅受显式 `max_sources` 影响 |
| 可信点源 | `quality_count` / `star_count` | 通量 SNR、形状、有效像素、边缘、掩膜和饱和检查均通过的源 | 仍需真值/星表/注入实验确认 |
| 最暗可信源 | `faintest_detected` | 在可信点源中，净通量为正且 `flux_snr` 达标的最大 `m_inst` 源 | 是图像内相对答案，不是未经标定的物理星等 |

因此，任何比赛材料都不能只写“程序检测到 N 颗星”，必须同时写检测定义、参数和质量规则。

## 2. 当前检测器

### 2.1 数据掩膜

每帧先屏蔽格式说明中的首行前 104 个像素位置、非有限值和整型传感器接近饱和上限的值。对于当前 `BITPIX=16` 数据，自动饱和上限为 `32767 - 32 = 32735`；这是防止把整型边界值当亮星，不是相机真实物理满阱值的替代品。

当前数据背景约为 21 ADU，并存在大量精确 0 值。对于整型图像且背景不为 0 的情况，代码把精确 0 作为无效像素候选进行掩膜；如果未来拿到的相机数据证明 0 是合法信号，可用 `mask_zero_pixels=False` 关闭这一规则。零像素出现在背景环中时不会单独否定整颗星；只有孔径内受污染或背景环有效像素不足才会增加质量标志。

### 2.2 局部背景和噪声

全图 sigma-clipping 的中位数/MAD 用于建立可比较的全局基线；检测实际使用 128×128 网格上的局部背景 `B(x,y)` 和 RMS `R(x,y)`，再线性插值到像素位置。局部噪声不是把每个像素的波动简单当作独立白噪声，而是保留为当前数据的经验 RMS。

外部源提取工具也采用背景图与背景 RMS 图，而不是只用一个全图标量；例如 [SExtractor 背景建模文档](https://sextractor.readthedocs.io/en/stable/Background.html)明确区分 background map 与 RMS map，并指出网格大小会影响估计。当前实现是轻量离线版本，仍需用空白区/注入实验验证 128 像素网格是否最优。

### 2.3 PSF 匹配滤波

对 `D(x,y)=I(x,y)-B(x,y)` 使用 FWHM 为 3 像素的圆 Gaussian 核，`sigma = FWHM / 2.35482`。匹配响应采用掩膜归一化卷积，避免无效像素的 0 值人为压低附近响应；再在响应图上做局部极大值和最小间距抑制。

这一步与旧程序直接把原始像素局部极大值交给 DAOStarFinder 的思路不同，但仍属于点源检测基线，不代表已经完成经验 PSF 拟合。若亮星的实测 PSF 呈椭圆、拖尾或随视场变化，应把实测 PSF/空间变 PSF 纳入后续实验。

### 2.4 局部孔径测光和 SNR

对每个候选峰，在原始图像上用半径 `r=4` 像素的圆孔径测量净通量：

```text
F = sum_aperture(I - B_local)
```

背景环取 `r+2` 到 `r+4` 像素，并对环内值做 sigma-clipping。没有相机增益资料时，通量误差至少包含孔径内背景噪声和背景均值估计误差：

```text
σ_F² = N_ap × σ_b² + (N_ap² / N_bg) × σ_b²
```

如果提供增益，还会加入 `max(F,0)/gain` 的源光子 Poisson 方差；如果提供读出噪声，则加入孔径像素数乘以读出噪声方差。代码同时输出：

- `snr`：峰值 `(peak-B_local)/σ_b`；
- `flux_snr`：净通量 `F/σ_F`；
- `filter_snr`：匹配滤波响应的检测 SNR。

最暗星筛选使用 `flux_snr`，不再把峰值 SNR 当作孔径通量 SNR。没有增益、暗电流、读出噪声、滤光片响应和标准星资料时，代码不会伪造绝对星等。

### 2.5 点源质量规则

默认参数如下，全部会写入 JSON 的 `detection.parameters`：

| 参数 | 默认值 | 作用 |
| --- | ---: | --- |
| `threshold_sigma` | 4.0 | 匹配滤波候选阈值，偏向保留候选 |
| `min_distance` | 3 px | 候选峰最小间距 |
| `psf_fwhm` | 3.0 px | 检测 Gaussian 核 FWHM |
| `background_box_size` | 128 px | 局部背景/RMS 网格 |
| `min_flux_snr` | 5.0 | 可信点源的孔径通量 SNR 下限 |
| `0.8 ≤ fwhm ≤ 12` px | — | 排除极窄尖峰和异常宽源 |
| `ellipticity ≤ 0.65` | — | 排除明显拉长源；椭圆率为 `|FWHM_x-FWHM_y|/max(FWHM_x,FWHM_y)` |
| `0.005 ≤ sharpness ≤ 0.85` | — | 排除过于弥散或单像素尖峰 |
| `footprint_pixels ≥ 2` | — | 孔径内至少有两个像素超过 1 个局部 RMS |

边缘、孔径内掩膜、饱和、背景环有效像素不足、非正通量和低通量 SNR 都会成为拒绝标志。拒绝源不会从审计返回列表消失，而是保留 `flags` 和 `quality_passed=False`，便于解释数量差异。

## 3. 首帧实测结果

运行环境：Python 3.11.9、NumPy 1.26.4、SciPy 1.17.1、Pillow 12.2.0。命令入口为：

```powershell
python -m rst19.cli doc/00-项目资料/原始数据/20260330163205413_9901.fits `
  --threshold-sigma 4 --min-distance 3 --aperture-radius 4 `
  --psf-fwhm 3 --background-box-size 128 --min-flux-snr 5 `
  --json-out tmp/frame-01.json
```

### 3.1 阈值敏感性

| 候选阈值 | 候选峰 | 质量通过 | 被拒绝 |
| ---: | ---: | ---: | ---: |
| 4σ | 58,411 | 30,266 | 28,145 |
| 5σ | 50,893 | 30,162 | 20,731 |
| 6σ | 45,387 | 29,977 | 15,410 |
| 8σ | 37,656 | 29,205 | 8,451 |
| 10σ | 32,383 | 27,757 | 4,626 |
| 12σ | 28,520 | 25,814 | 2,706 |
| 15σ | 24,324 | 22,674 | 1,650 |
| 20σ | 19,671 | 18,356 | 1,315 |

质量通过数量在 4–8σ 间相对稳定，10–20σ 后才明显下降；原因是许多低响应候选本来就会在通量 SNR 或形状阶段被拒绝。这说明“把阈值从 4 调到 8”主要减少候选尾部，并没有证明 30,000 就是真实恒星数。20σ 得到 18,356 也不能被倒过来当成比赛答案，因为它对应的是另一套检出极限，会牺牲暗源召回率；最终计数仍需注入回收率和星表交叉验证。

### 3.2 负峰对照

| 阈值 | 正峰（NMS 后） | 负峰（NMS 后） |
| ---: | ---: | ---: |
| 4σ | 58,411 | 515 |
| 5σ | 50,893 | 93 |
| 6σ | 45,387 | 59 |

| 10σ | 32,383 | 58 |

阴性对照不支持“全部 8 万都是对称高斯随机噪声”的解释。剩余正峰中仍可能包含恒星、正向固定图样、热像素邻域或其他仪器结构；因此负峰对照只能排除一个假设，不能直接给出恒星真值。

### 3.3 拒绝原因

4σ 默认运行的主要拒绝标志为：

```text
LOW_FLUX_SNR     26,764
SPIKE             1,137
EDGE                468
NON_POSITIVE_FLUX   458
SMALL_FOOTPRINT      24
ELONGATED             8
NARROW                7
```

这里的标志可能重叠，不能把它们简单相加后当作互斥类别。精确 0 无效像素如果位于背景环而没有进入孔径，不会再造成整颗星被拒绝；这一点是实验中修正的关键实现细节。

## 4. 为什么不能把外部 18,000 当答案

旧项目对同一首帧使用 DAOStarFinder、FWHM=3、排除边缘和 shape 过滤，在阈值约 50×MAD 时得到 8,511 个源；旧代码的“星等”还是峰值 SNR 代理量。当前直接原始局部峰值基线在 4σ 下可达到 83,233，主要因为检测对象、阈值尺度、坏像素处理和后续形状/光度筛选完全不同。

新检测器在当前默认质量定义下得到 30,266 个质量通过源，但这不是向 18,000 靠拢后的数字，也不是已经证明的物理恒星数。若将某个外部示例数字写入参数，就会把验证目标和结果混为一谈。正确做法是：

1. 以本记录的定义输出候选峰和质量通过数；
2. 用合成注入实验测召回率、误检率和质心误差；
3. 用可靠 WCS/星表给通过源做身份核验，并保留未匹配原因；
4. 用人工抽检或主办方标注确认固定图样/热像素是否被误计；
5. 只有在上述验证完成后，才把某个数量写进正式比赛结论。

## 5. 15 帧关联的证据链

序列代码 `src/rst19/sequence.py` 按以下顺序工作：

```text
单帧质量源
  → 高 SNR 源最近邻估计相邻帧全局平移
  → 扣除累积平移得到配准坐标
  → 逐帧唯一关联
  → 轨迹出现帧数、总位移、线性拟合 RMS
  → static / moving / transient
```

默认 15 帧要求轨迹至少出现 `ceil(0.8×15)=12` 帧；只有总位移不少于 2 px 且直线拟合 RMS 不超过 0.75 px 才判为 `moving`。这个阈值是当前图像像素坐标中的工程基线，不能在没有像元角尺度和时间间隔时直接写成角速度或真实轨道速度。

## 6. 下一轮必须完成的验证

- 从实测亮星估计空间变化 PSF，并比较 FWHM=2、3、4 像素；不以计数接近某数字为选择依据。
- 在真实背景上注入不同通量、FWHM、椭圆率、位置和运动速度的 Gaussian/实测 PSF，测完备率和误检率。
- 对 4–8σ 质量源做分区抽检：图像边缘、精确 0 邻域、极值邻域、密集源和疑似条纹。
- 获取任务方星表或完成有先验/盲 WCS，分开记录 `detected`、`matched`、`unmatched` 和目录预期数。
- 检查序列关联是否需要仿射/旋转模型；当前平移模型只适合相邻帧姿态变化很小的情况。
- 确认相机 gain、read noise、暗电流、非线性和真实饱和阈值后，重新计算物理通量误差和标准系统星等。
